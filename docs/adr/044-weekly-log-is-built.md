# ADR-044: 주간 보육일지를 만든다 — 근거는 일일 보육일지 또는 일과 기록에서 고른다

- 날짜: 2026-10-28
- 상태: 채택 (U-2 를 닫는다)

## 맥락

`weeklyLog` 는 api-spec §11 의 일지 4종에 계약으로 들어 있었는데, **만들기로 정한 적이
없었다.** PRD 는 「보육일지」라고만 적어 일일인지 주간인지 구분하지 않았고,
미확정사항은 U-2 「주간 보육일지를 만들 것인가」로 열어 두고 있었다.

그 사이에 구현이 먼저 들어왔다. 서버는 `weeklyLog` 생성 · `source_kind` 선택 ·
한글 파일 내보내기까지 돌고, 화면도 보관함의 「새로 만들기」에서 주간을 고를 수 있다.
**문서만 「미정 · 미진행」으로 남아 있었다.**

## 결정

**주간 보육일지를 만든다.** U-2 를 닫는다.

근거를 두 가지 중에서 고른다 — `source_kind` 한 칸이다.

```
"dailyLog"   생략했을 때 기본    확정된 일일 보육일지를 묶는다
"routine"                       일과 기록에서 바로 만든다 — 일일 보육일지를 쓰지 않는 원
```

`weeklyLog` 가 아닌 `kind` 에 `source_kind` 를 보내면 `VALIDATION_FAILED` 422 다.

## 근거

**[실측 #124] 원마다 하나를 고른다.** A원은 주간으로만, B원은 일일로만 쓴다.
원이 2곳뿐이라 비율은 모른다.

**법이 둘 다 요구하지 않는다.** 중앙육아종합지원센터 「보육일지 공식양식」(2020-03-04)이
개정 누리과정 놀이실행자료를 인용한다 — 「월간, 주간, 일일계획을 모두 수립하여야 하는
것은 아니며 **하나만 선택**하여 작성할 수 있음」. 공식 양식 예시도 주간 3 · 일일 2 로
둘 다 든다.

그래서 **둘 중 하나만 만들면 원의 절반이 못 쓴다.** 둘 다 만들고, 일일을 쓰지 않는 원이
일과 기록에서 바로 주간을 만들 수 있게 `source_kind` 를 둔다.

## 종이 한 장

주간 보육일지는 **반 단위 · 한 주**다. `child_id` 를 받지 않는다.
실물 양식은 날짜 행마다 「우리반 놀이」가 있고, 해석과 지원이 「놀이 이해 및 분석」 ·
「앞으로의 지원방향」 두 칸으로 나뉜다(api-spec §11 「종이 한 장」).

## 남은 것

**[미확정] 주간만 쓰는 원이 일과 기록을 매일 적는가.** 주간 양식은 날짜 행이 월~금 다
있어서 날짜별 근거가 있어야 채워진다. 일과를 주 1회만 적으면 행이 빈다.
현직자 인터뷰에서 확인한다.

영유아 평가(`assessment`)의 한글 파일 칸 나누기는 여전히 안 정했다 — U-3.
실물을 한 장도 못 봤다.
