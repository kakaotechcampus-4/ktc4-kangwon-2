# ADR-077: 놀이 연간은 4구간을 동시에 만들고 실패 구간만 한 번 · 겹친 후보만 한 번 다시 만든다

- 2026-11-09
- 상태 — 채택 (하민 결정 2026-11-09: ⑦을 서비스에 넣는다, 계획 권장안 1~13 승인). 병합 조건이던 ⑦ 사람 판정은 2026-11-09 마쳤다(⑦ 1.35 · ① 1.30, 실험 README).
- 관련 — [ADR-043](043-yearly-format-selection-storage-api-call-unit.md) §5 를 **대체** · ADR-076(닿지 못한 요청만 한 번 더) · ADR-060(요청 사항) · ADR-036(사용량 기록) · ADR-023(Golden) · api-spec §4

## 맥락

ADR-043 §5 는 놀이 프로젝트형 연간을 구간마다 한 번, 차례로 불렀다. 앞 구간 놀이명을 「피할 목록」으로 넘겨 겹침을 막았다.
그래서 [실측] Sol 로 평균 150초가 걸리고(①, 10회), 한 구간이라도 실패하면 앞 구간까지 모두 버렸다.

11-08 ~ 11-09 에 네 구간을 동시에 부르는 방식을 조건 ⑤ · ⑥ · ⑦ 로 10회씩 쟀다(`docs/evaluation/runs/2026-11-09-play-annual/`).
동시에 부르면 앞 구간의 놀이명을 넘길 수 없으므로, 대신 Rule 이 후보마다 다른 출발점을 정해 준다.

| | ① 순차 | ⑦ 동시 + 힌트 |
|---|---|---|
| 시간 평균 (초) | 149.7 | 38.3 |
| 한 계획 안 구간끼리 겹침 | 0 | 0 |
| 다시 만들었을 때 같은 구간에 또 나온 이름 (40개당) | 1.91 | 0.15 |

⑦은 jev B2(이름만 읽어도 알겠는가) · B6(억지 조합)에서 ①보다 못했다. 사람 판정(2026-11-09, ⑦ · ① 20개씩, 조건 가림)에서는 평균 1.35 · 1.30으로 ①보다 못하지 않았다(`docs/evaluation/runs/2026-11-09-play-annual/human7.json`).

## 결정

1. **네 구간을 동시에 한 번씩 부른다.** 첫 호출에는 `avoid_play_names` 가 없다. 프롬프트 판은 `play-project-planner-v7`.
2. **후보마다 Rule 이 힌트 둘을 정한다(`play_seeds`).** 모델은 고르지 않는다(CLAUDE.md §5).
   - 중심 누리과정 내용 하나 — 승인된 카탈로그에서 한 해 40개가 모두 다르게 뽑는다. 1.2 건강하게 생활하기 · 1.3 안전하게 생활하기 8개는 뽑지 않는다(59 → 51). 배움 칸은 59개 전부에서 그대로 고른다.
   - 중심 자료 하나 — 해설서의 자료 종류 6가지를 구간 안에서 1~2번씩 고르게 섞는다.
     [출처] 2019 개정 누리과정 해설서 p.48-49 「풍부한 놀이자료 제공」(자료 종류 이름만 쓴다, 문장 인용 없음. PDF · 인쇄 쪽 구분 미확인).
   - Validation `SEED_CONTENT_MISSING`: n 번째 후보의 배움 칸 근거에 n 번째 힌트의 내용 ID 가 없으면 그 구간은 계약 위반이다.
   - 힌트는 저장하지 않는다(§13 — 근거는 배움 칸의 `CURRICULUM` evidence 로 이미 남는다).
3. **실패한 구간만 한 번 더 부른다.** 호출이 깨짐 · 시간 초과 · 계약 위반(파싱 · Validation · `LlmFailed` · 공급자 오류)인 구간만 같은 입력으로 다시 부른다.
   한도(401 · 403 · 429) · 키 없음 · 설정 오류 · Reference 미승인 · 메모 가명 실패는 다시 불러도 같으므로 바로 그 오류를 낸다.
   다시 불러도 실패하면 500 이고 **아무것도 저장하지 않는다.** 전송 계층의 재시도(ADR-076)와는 별개로, 이것은 구간 단위다.
4. **겹친 후보만 한 번 다시 만든다.** 다른 구간끼리 놀이명, 또는 놀이명 + 지원매체가 비슷하면(공백 · 문장부호를 뺀 글자 두 개 묶음 Jaccard ≥ 0.6, 또는 같음) 나중 구간 쪽 후보를 그 힌트로 다시 만든다.
   - 그때는 나머지 39개 놀이명을 `avoid_play_names` 로 넘기고 요청 사항은 넣지 않는다. 요청을 반영한 후보(ADR-060)는 바꾸지 않는다 — 짝의 다른 쪽을 바꾸고, 둘 다 반영했으면 둘 다 둔다.
   - 결과는 같은 자리 · 같은 `row_key` 로 들어간다. 다시 만들기는 한 번뿐이다.
   - 그 뒤에도 비슷한 겹침이 남으면 원래 후보를 둔다(품질 문제). **이름이 똑같은 후보가 남으면 500** 이다 — 순차일 때도 저장된 적 없는 상태다.
   - [실측] 0.6 선은 같은 놀이 짝 24개 중 6개만 잡는다(`dup-pairs.json`, 라벨은 하민 확인 2026-11-09). 선을 낮추면 다른 놀이를 잘못 잡는다. 글자 유사도의 한계이고 이 ADR 은 선을 바꾸지 않는다.
5. **「생성 멈추기」의 뜻이 바뀐다.** 서버는 동시 호출 전 · 다시 부르기 전 · 저장 전에 끊김을 본다(요청 스레드에서만). 끊겼으면 저장하지 않는다.
   네 구간은 이미 동시에 불렀으므로 **멈춰도 그 비용은 남는다**(순차일 때는 남은 구간을 아꼈다). 화면 문구는 그대로다.
6. **시간 기록.** 작업 스레드의 LLM 호출도 같은 run id · kind 로 `llm_call` 줄을 남긴다. 구간(phase)은 요청 스레드만 나누고(기다리는 동안 `llm`), 호출 수는 끝날 때 더한다.
   서버 로그에는 숫자만 남긴다: `recalled` · `replaced` · `overlaps_left`(§21).

## 하지 않는 것

- 구간별 저장 · 이어서 하기. 저장은 여전히 네 구간이 모두 통과한 뒤 한 번이다.
- 겹침 선(0.6) 조정 · 뜻으로 묻는 겹침 판정(jev). 근거는 위 4 의 [실측].
- 전체 다시 만들기 · 두 번 이상의 다시 만들기.

## 결과

- 호출 수: 보통 4번. 최악은 4 + 실패 구간 + 겹친 구간 = 12번이고 `llm_usage` 도 그만큼이다(ADR-036).
- 최악의 대기는 세 단계 × 120초 = 6분 — nginx 510초 · 스트림 마감 120초는 그대로다.
- **`rule_version` 이 `play-project-planner-v6+teacher-venues-v2` → `play-project-planner-v7+teacher-venues-v2` 로 바뀐다.** 프롬프트 · 입력(`play_seeds`) · Validation 이 바뀐 계약 변경이라 판을 올렸다(ADR-023: 결과가 달라졌다는 이유가 아니다). 이 판을 고정한 테스트 한 줄만 고쳤다.
- 화면의 기다림 표시는 180초 → 45초다(⑦ 실측 평균 38초).
