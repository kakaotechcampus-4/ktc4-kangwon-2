# ADR-043: 연간 형식 선택 — 형식은 body 에 두고, 생성 요청에 형식을 받고, 놀이 프로젝트형은 한 요청에서 네 구간을 차례로 만든다

- 날짜: 2026-10-25 (결정 성진 2026-10-25 · 검토 하민)
- 상태 — **제안 (검토 전)**. ADR-042 도 제안이라 이 ADR 은 그 위에 선다. 둘이 같이 채택돼야 한다.
- 관련 — ADR-042 · ADR-036 · ADR-041 · ADR-030 PM-04 · api-spec §4~§7-1 · §9 · §9-1

## 맥락

ADR-042 「아직 정하지 않은 것」 중 **저장의 형식 구분 위치 · API 경로와 오류 코드 · 전체 연간 LLM 호출 단위**, 세 가지만 정한다.
놀이 프로젝트형 생성을 이어 붙이고 화면에서 보여 주며 구간마다 고르게 하는 데(저장 없이) 필요한 만큼이다.
범위 밖: 후보 선택 이력 이벤트 모양 · 다개월 자료 검색 · 월간 연결(거절하는 것까지만).

## 결정

### 1. 저장 — 형식은 `plans.body.format` 에 둔다

- migration · 새 열 없음. `body` 에 `format` 이 없는 행은 `MONTHLY_THEME` 이다(ADR-042 읽기 호환).

### 2. 요청 — 생성에 `format` 을 받는다

- `POST /api/plans/annual` 본문은 `{ "class_id": 1, "format": "MONTHLY_THEME", "form_id": null }`.
- `format` 은 **필수**, `MONTHLY_THEME` · `PLAY_PROJECT` 중 하나. 없거나 모르는 값은 422 `VALIDATION_FAILED` `["format"]`.
- `PLAY_PROJECT` 와 `form_id` 가 함께 오면 422 `["form_id"]` — 기관 양식은 놀이 프로젝트형이 쓰지 않는다.
- 결정 당시 화면은 `format` 을 보내지 않았다. 서버와 화면 변경이 틈 없이 들어가야 한다(머지 순서는 코드 PR 에서 맞춘다).

### 3. 응답 — 모든 연간 응답이 `format` 을 싣는다

- 생성 201 · 단건 · 목록 항목 모두. 월별 주제형은 기존 모양에 `"format": "MONTHLY_THEME"` 한 칸만 더한다.
- 놀이 프로젝트형은 `format_version`(= Core `layout_version`) · `periods[]`(4구간 × 후보 10) 를 싣는다. 모양은 api-spec §4.
- 칸마다 `{ value, evidence, generation }`. 놀이명 · 지원매체 · 지원 방향의 `evidence` 는 `[]` 다(쓴 기관 자료가 없다, ADR-042 §3).

### 4. 지원하지 않는 작업은 409 `GATE_BLOCKED`

- 놀이 프로젝트형에 대한 칸 수정 · 확정 · 변경 이력 · 내보내기, 그리고 그 반의 월간 생성.
- 월간 생성은 부모 행을 찾은 직후, 월별 주제형으로 읽기 전에, LLM 호출 전에, 부모 상태와 관계없이 막는다(ADR-042 §2 하위 gate).
- `GATE_BLOCKED` 는 보통 「앞 단계가 안 끝났다」이고 여기서는 「이 형식에는 월간이 없다」다. 차이는 `message` 가 나른다.

### 5. 호출 단위 — 한 요청, 구간 순차 4호출, 전부 통과해야 저장

- 서버가 Core 를 구간마다 한 번, `m03_m05` → `m06_m08` → `m09_m11` → `m12_m02` 순으로 부른다. 앞 구간 놀이명을 `avoid_play_names` 로 넘긴다.
- 네 구간을 합쳐 한 번 저장한다. 하나라도 실패하면 아무것도 저장하지 않는다.
- 구간당 마감 120초 — 구간 하나의 호출 전체에 거는 벽시계 한도이고, 스트림의 읽기 한 번 상한이 아니다. 놀이 프로젝트형 호출에만 적용한다. **전체 마감은 두지 않는다**(성진의 선택). nginx `proxy_read_timeout` 은 `POST /api/plans/annual` 만 510초(= 4 × 120 + 30), 나머지 경로는 120초 그대로.
- 최악의 대기는 약 8.5분이다. 진행 표시가 필수다.
- 오류: 누리과정 Reference 없음 · 승인 전 → 503 `DEPENDENCY_UNAVAILABLE` · 한도 · 키(401 · 403 · 429) → 503 `LLM_BUDGET_EXCEEDED` · 호출 깨짐 · 계약 위반 · 시간 초과 · `stop` 아닌 종료 → 500 `GENERATION_FAILED` · 같은 반 두 번째 생성 → 409 `ALREADY_EXISTS`(형식 무관).
- 호출 기록: 모든 호출이 `shared/llm` 을 지나 성공한 호출마다 `llm_usage` 한 줄(ADR-036). 계획안 하나에 4줄.

### 6. 화면 — S7 에서 형식 카드를 고르고, S8 에서 구간마다 5개를 골라 미리보기에 반영한다 (성진 2026-10-25)

- **S7** 형식 선택은 버튼이 아니라 **카드** 둘이다 — 「월별 주제형」 · 「놀이 프로젝트형」. 카드마다 결과 문서를 실제로 캡처한 그림과 이름을 보여 준다(어떤 문서가 나오는지 그림으로 보여 주려는 것이다). 그림은 성진이 준 캡처이고 실제 아동 · 기관 이름이 없다. 하나를 골라야 만들 수 있고(필수), 놀이 프로젝트형이면 기관 양식 선택을 비활성으로 두며 월간 · 주간 안내를 띄운다.
- **S8** 놀이 프로젝트형 결과 화면에서 교사는 **구간마다 후보 10개 중 정확히 5개를 고른다.** 고른 것은 **오른쪽 문서 미리보기에 바로 반영된다** — 문서 모양의 표이고 열은 시기 · 놀이명 · 지원매체 · 내용 및 지원 방향 예상하기 · 놀이를 통한 배움 다섯, 구간 순서대로다.
- **고른 놀이는 저장하지 않는다.** 화면에만 있고 새로고침하거나 페이지를 떠나면 사라진다. 화면이 그 사실을 알려야 한다(예: 「고른 놀이는 아직 저장되지 않아요. 새로고침하면 처음부터 다시 골라야 해요.」). **`localStorage` · `sessionStorage` 에도 두지 않는다** — 화면 상태일 뿐이다.
- 확정 · 내려받기 · 수정 버튼은 아직 없다. 서버 API 는 그대로다 — 고르기 엔드포인트가 없고 서버는 구간마다 후보 10개를 모두 준다.
- 고른 것을 저장하는 일(ADR-042 가 말한 선택 이력 포함)은 하민의 Core 선택 후속 뒤에 온다. 그때 더해지는 것은 저장 호출 하나다.
- 6번째를 고르면 어떻게 되는지 · 좁은 화면 배치 등 그 밖의 UX 는 화면 PR 에서 정한다.

## 근거

- [실측] `PlayProjectYearlyPlan` 은 `format` 필드(기본 `"PLAY_PROJECT"`)를 이미 갖고, 서버 codec 은 dataclass 필드를 그대로 직렬화한다(`backend/app/features/plans/codec.py:37-38`). `YearlyPlan` 에는 `format` 이 없어 기존 행은 다시 쓰지 않고도 월별 주제형으로 읽힌다.
- [판단] 열은 SQL 로 형식을 걸러 볼 때만 이득인데 지금 그런 조회가 없다.
- [판단] `format` 을 필수로 둔 것은 명시성을 고른 것이다. 기본값을 두면 화면이 빠뜨린 채로도 월별 주제형이 만들어져 놀이 프로젝트형 반이 조용히 틀어진다.
- [판단] `form_id` 를 받아 저장하면 계획안이 그 양식을 따른 것처럼 보인다. 놀이 프로젝트형은 기관 양식을 쓰지 않으므로 거절한다.
- [실측] 월간 화면은 서버 `message` 를 그대로 보여 준다(`frontend/components/workspace/MonthlyPlanPage.tsx:40`). 새 코드 없이 문구로 차이를 전한다.
- [실측] #222 커밋 메시지: 한 구간 19.3초 · 출력 1,713토큰, 22.0초 · 2,092토큰. 12~2월 구간은 회피 목록을 넣고 5,514토큰을 썼다. **네 구간 합계는 재 본 적이 없다** — 누리과정 승인과 서버가 필요하고 로컬 real 모드는 금지다.
- [판단] 구간당 120초 = 출력 상한 10,000토큰 ÷ 실측 약 90토큰/초 ≈ 111초에 여유를 얹었다. 전체 마감을 안 둔 것은 잘라 내는 것보다 끝까지 만드는 쪽을 성진이 택해서다.
- [판단] 구간 단위로 부르면 구간 사이에 회피 목록을 넘길 수 있고, 한 구간이 깨져도 이미 쓴 토큰의 범위가 한 구간이다.

## 대안

- 새 열 `annual_format`: migration · 모델 · repository · `alembic check` 로 약 60줄. 형식으로 SQL 을 거를 일이 생기면 그때 다시 본다.
- `format` 선택 입력(기본 월별 주제형): 명시성이 없어 탈락.
- 새 오류 코드 `FORMAT_NOT_SUPPORTED`: 화면이 코드를 하나 더 알아야 한다. `message` 로 충분하다.
- 비동기(202 + polling) 지금: 「생성 중」 상태, 배포 때 죽는 백그라운드 작업(배포마다 backend 컨테이너가 새로 뜬다), 멈춘 행 정리, polling 화면, PR 1~2개가 더 들고 ADR-036 §2 를 바꾼다.
- 구간마다 화면이 한 요청씩: 첫 구간이 나머지보다 먼저 저장돼 부분 계획안이 생긴다. 부분 저장 금지와 부딪치고, 구간 추가 API 와 잠금이 필요하다.
- 전체 마감 300초: 끝까지 만드는 쪽을 택해 탈락.

## 결과

- 요청 모양이 바뀐다. 서버와 화면이 같이 들어가야 한다.
- 누리과정 내용 Reference 는 `PENDING_HUMAN_REVIEW` 다. **하민이 승인하기 전에는 놀이 프로젝트형 생성이 mock 모드를 포함해 모두 503 이다.**
- 고른 놀이는 저장하지 않는다 — 새로고침하면 처음부터 다시 고른다. 저장은 Core 선택 후속 뒤다(§6).
- nginx 에 경로별 timeout 한 줄이 는다.
- 계획안 하나에 `llm_usage` 가 4줄 남는다. **알려진 틈:** `stop` 으로 끝나지 않은 스트림은 토큰을 쓰고도 사용량 줄이 남지 않는다.
- **ADR-036 §2 의 다시 볼 조건(호출이 20초를 자주 넘음)에 걸릴 가능성이 높다** — 실측 19.3초 · 22.0초, 표본이 2건이다. 네 구간 합계를 서버에서 잰 뒤 판단한다. 비동기는 미룬다.
- `shared/llm` 의 호출 타임아웃(지금 30초)과 월간 설정 30초는 그대로 두고, 놀이 프로젝트형 호출만 구간 하나의 전체 시간을 120초로 끊는다 — 스트림의 읽기 한 번 상한이 아니다.
- **ADR-042 보충.** ADR-042 「결과」는 기존 연간 API 응답이 바뀌지 않는다고 했다. 이 ADR 은 응답에 `format` 한 칸을 더한다(추가만 · 기존 클라이언트는 영향 없음). 하민의 검토에서 확인한다.
