# ADR-076: LLM 일시 오류는 다시 부르고, 생성 요청 하나의 호출 수에 상한을 둔다

- 날짜: 2026-11-09
- 상태: 제안 — 설계 중(draft PR). 설계 확정 · 구현 뒤 채운다

## 맥락

[실측] `backend/app/shared/llm/client.py` 는 호출이 한 번 실패하면 그대로 끝난다. 다시 부르지 않는다.

- `:41` 제한 시간 30초
- `:244-248` 401 · 403 · 429 는 `LlmBudgetExceeded`(계약 `LLM_BUDGET_EXCEEDED` 503, 화면은 「운영 문의」), 그 밖 HTTP 오류는 `LlmFailed`
- `:249-250` 연결 실패 · 시간 초과 · 깨진 JSON 도 `LlmFailed`(계약 `GENERATION_FAILED` 500)

그래서 엘리스 쪽이 몇 초 흔들리면 교사는 생성 실패를 보고 처음부터 다시 누른다.

[실측] `post_json` 은 연간 · 문서 초안 · 월간 Core 어댑터 · jev 판정(`decide`)이 같이 지나는 문이다(`:224-226` · `:128`).
재시도를 여기 두면 네 길이 모두 바뀐다.

[실측] 생성 요청 하나가 LLM 을 몇 번 부르는지는 `ssuksak.timing` 의 run 이 이미 센다(`:196-198` `run.llm_calls`). 상한은 없다.

월 예산 카운터(70% 경고 · 90% 차단)는 2026-09-21 무효가 됐다(CLAUDE.md 「LLM 예산」). 여기서 말하는 상한은 그것과 다르다 —
**요청 하나 안에서** 호출이 늘어나는 것을 막는 장치다. 재시도를 넣으면 호출 수가 늘 수 있어서 같이 둔다.

## 결정

설계 설명 · 확인 뒤 채운다. 정할 것:

1. **어떤 실패를 다시 부르나** — 모델에 닿기 전 실패(연결 실패 · 502 · 503 · 504)만인가. 429 는 지금 계약상 예산 오류다.
   시간 초과는 엘리스가 이미 처리했을 수 있어 두 번 과금될 수 있다
2. **어디서 부르나** — `complete_json` 만인가 `post_json` 전체인가, jev 판정도 넣나. `post_stream` 은 일부를 읽은 뒤 다시 부를 수 없다
3. **몇 번 · 최악 대기** — 30초 × 횟수가 nginx · 화면의 기다림 시간 안에 들어와야 한다
4. **상한 값** — 생성 요청 하나의 호출 수

LLM 이 끝내 실패했을 때 규칙만으로 초안을 만드는 폴백은 이 ADR 밖이다. `GENERATION_FAILED` 계약과 ADR-032 를 바꾸는 일이라 따로 정한다.
