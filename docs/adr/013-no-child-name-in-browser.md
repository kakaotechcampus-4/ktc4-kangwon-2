# ADR-013: 아동 실명을 브라우저에 저장하지 않는다

- 2026-09-19
- 상태 — 채택

## 맥락

FE 목업이 관찰일지(`/records`)를 브라우저 저장소에 쌓고 있다.
화면이 스스로 *"기록은 이 브라우저에 저장됩니다"* 라고 안내한다.

ADR-004 가 아동 실명의 저장 위치를 정했지만 **DB · 프롬프트 · 로그만 다뤘다.**
브라우저는 우리 문서 어디에도 없다.

## 결정

**아동 실명을 `localStorage` · `sessionStorage` · IndexedDB 에 저장하지 않는다.**

- **목업 단계의 가명 데이터는 예외다.** 실제 연동 시점에 서버로 옮긴다.
- 저장해도 되는 것 — 화면 설정, 접은 상태, 임시 입력값. **사람을 식별하지 않는 것만.**

## 근거

**우리가 못 지운다** `[판단]`

우리 서버에 없으면 삭제 요청이 와도 지울 방법이 없다.
ADR-004 가 정한 대로 원이 개인정보처리자고 우리는 수탁자다(개인정보보호법 §26).
수탁자에게도 파기 의무가 따라오는데, 브라우저에 있는 건 파기 대상을 특정할 수도 없다.

**공용 기기** `[판단]`

어린이집 교무실 PC 는 교사 여럿이 쓴다. 개발자도구를 열면 저장소가 그대로 보인다.
로그인이 8주차(P1)라 지금은 계정 구분도 없다.

**★ 치환 장치를 우회한다** `[판단]`

ADR-004 가 「LLM 호출 직전에 아동 코드로 치환한다」를 정했고
그 장치를 `shared/childCode` 한 곳에만 두기로 했다. 이유는 법이 아니라 로그였다.

```
LLM 요청 로그 → 서버 로그 파일 → 모니터링 → 에러 리포터 → 공급자 로그
```

브라우저에 쌓인 데이터는 그 경로를 지나지 않는다.
P1 관찰일지가 브라우저 저장을 유지하면 **안전장치를 통째로 건너뛰는 길**이 생긴다.
코드를 6명이 만지는데 그 길이 문서 어디에도 없으면 아무도 막지 않는다.

## 대안

**암호화해서 저장한다** — 키를 어디 둘지가 다시 문제다.
브라우저에 두면 데이터와 같이 털리고, 서버에 두면 서버를 부를 거니까 데이터도 서버에 두면 된다.

**저장 기간을 제한한다** — 기간 안에는 여전히 남는다. 삭제 요청에 못 응한다.
그리고 「7일」 같은 숫자에 근거가 없다.

**브라우저에 코드만 저장한다** — `shared/childCode` 가 서버에 있어서
FE 가 치환하려면 서버를 불러야 한다. 서버를 부를 거면 데이터도 서버에 두면 된다.

## 결과

- **P1 관찰일지는 입력 즉시 서버로 보낸다.** 오프라인 임시 저장이 필요해지면
  치환한 뒤 저장하는 설계를 별도 ADR 로 남긴다.
- **FE 목업의 가명 데이터는 연동 PR 에서 제거한다.** 지금은 그대로 둔다 —
  가명이고 P1 화면이라 6주차 계약 대상이 아니다.
- `frontend/CLAUDE.md` 「브라우저 저장」 절이 이 결정을 세 줄로 요약한다.
- `CLAUDE.md` 개인정보 절에 브라우저를 추가한다 — 지금은 DB · 프롬프트 · 로그만 있다.
