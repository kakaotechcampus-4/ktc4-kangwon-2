# ADR-051: 주간 대·소집단 활동 · 특별활동을 요일 칸으로 나눈다

- 날짜: 2026-10-31
- 상태: 제안 — 결정 WD-1~WD-4 는 하민 확정(2026-10-31). Template v0.2.0 파일은 2026-10-31 하민 승인(`reviewer_ai_lead_001`). WD-4 출력 양식 · WD-5 공개 필드는 2026-11-01 서버 담당과 합의(구현 전).
  → 2026-11-11 현재 채택 · 구현됨(develop). 서버 응답의 `repeat_by`(`backend/app/features/plans/weekly_schemas.py:68`) · HWPX 의 `DAY` 분기(`export.py:398`)가 있다.
- 보충 · 일부 대체: ADR-030 WQ-02 와 ADR-027 「`DAY` 는 후속」을 **`group_activity` · `special_program` 두 Section 에 한해** 대체한다. 다른 Section 은 WQ-02 그대로 주 단위 값이다.

## 맥락

[실측] 주간 샘플의 대·소집단 활동과 특별활동은 요일마다 값이 다른 행이다. WQ-02 는 이를 주 단위 칸 하나 안 목록으로 쓰게 했지만,
교사가 요일별로 고치고 출력하려면 요일마다 칸 주소가 필요하다.

## 결정

1. **WD-1 요일 칸.** `RepeatBy.DAY` 를 둔다. `DAY` Section 은 주간계획안의 `operating_days` 마다 한 칸이다(월~금 5칸, 토요일 운영이면 6칸).
   요일 수는 생성 때 저장한 `operating_days` 를 따른다. 칸 주소는 `item_id`, 의미 주소는 `(section_key, day)` 다.
   `WeeklyCell.day` 는 `DAY` Section 칸에만 있고 다른 칸은 `None` 이다.
2. **대상.** `group_activity`(생성)와 `special_program`(교사 입력, 처음엔 비어 있고 처음 쓰면 `MANUAL`)만 `DAY` 다.
   `indoor_play` 는 주 전체 목록 그대로이고, 나머지 Section 은 `NONE` 이다.
3. **WD-2 새 Template.** `weekly-template-a-v0.2.0` 을 발행했고 2026-10-31 하민이 승인했다. v0.1.0 의 승인을 물려받은 것이 아니다(ADR-027 §3).
   원별 선택 없이 승인 뒤 새 주간 전체에 쓴다. **단, 실제 생성이 v0.2.0 을 쓰도록 바꾸는 것은 요일 칸 생성 · 검증이 들어간 뒤다.**
   Template 승인과 생성 전환은 별개다.
4. **WD-3 근거 없는 요일 = 빈칸.** 그 요일에 쓸 근거가 없으면 비워 두고, 다른 요일 값으로 채우지 않는다.
5. **월간은 `DAY` 를 쓰지 않는다.** `MonthlySection` 과 월간 Template 해석이 `NONE` · `WEEK` 외의 값을 거절한다.
6. **기존 계획.** v0.1.0 으로 만든 주간계획안은 그대로 읽는다. 저장본에 `day` 가 없으면 `None` 으로 읽는다. 기존 계획을 변환하지 않는다.
7. **WD-5 공개 API (2026-11-01 서버 담당과 합의).** 응답에 `sections[].repeat_by: "NONE" | "DAY"`(null 없음),
   `cells[].day: "MON"…"SAT" | null`, 변경 이력 `day` 를 더한다. 편집 · 재생성 경로와 오류 매핑은 그대로다.
   검사 결과(`findings`)에는 `day` 를 넣지 않는다 — Core 검사 위치에 요일이 없다. 필요해지면 Core 에 먼저 넣는다.
   계약은 api-spec §9-6.
8. **WD-4 출력 (2026-11-01 합의).** v0.2.0 계획의 HWPX 는 고정 양식 두 개(월 ~ 금 · 월 ~ 토)를 쓴다. 각 요일 칸
   묶음 위에 「요일 | 월 … 금(토)」 머리줄을 두고, 칸 이름을 양식에 박는다. 이것은 api-spec §9-6 「칸 이름은 `label`,
   양식에 박아두지 않는다」의 **v0.2.0 한정 예외**다. 내용은 `(section_key, day)` 로 명시적으로 채운다.
   v0.1.0 출력은 그대로다. 완성 양식은 하민 승인과 실제 내용을 넣은 5일 · 6일 한글 렌더 확인을 거친다.

## 아직 정하지 않은 것

- **WD-6 화면:** 요일 칸 편집 화면은 화면 담당(하민)이 정한다.

## 결과

- Core 구조(요일 칸 불변식 · `cell(key, day)` · `replace_cell` 의 요일 보존)와 Template v0.2.0 승인이 들어갔다.
- 생성 · 검증 · 요일 칸 재생성이 들어갔다(#316). 서버 필드 · 화면 · HWPX · 생성 전환은 후속 단계다.
