# ADR-014: 규칙 엔진은 고르지 않고 검사한다 (ADR-005 대체)

- 2026-09-19
- 상태 — 채택
- 대체 — ADR-005

## 맥락

ADR-005 는 계획안 생성을 세 층으로 나눴다.

```
1  배치 층   어느 칸에 무엇이 들어가나        규칙 엔진
2  선별 층   후보 중 무엇을 고르나            규칙 엔진
3  문장화     "개미 관찰" → "꼭꼭 숨은 개미 찾기!"   LLM
```

**앞 둘에 LLM 이 들어가지 않는 설계였다.** 할루시네이션 표면을 문장 한 줄로 좁히는 게 목적이었다.

그런데 이 설계가 두 가지를 전제한다.

- `activities` 테이블에 활동 후보가 **충분히 쌓여 있다.**
- 「무엇을 고를까」의 순위(연령 → 누리과정 → 안전성 → 원 특성 → 놀이성 → 트렌드)를
  **규칙으로 다 적을 수 있다.**

6주차가 끝나는 시점에 활동풀은 **0행이다.** 그리고 「놀이성」·「원 특성」 같은 순위는
규칙으로 적어본 적이 없다 — 어떤 데이터로 판정할지가 정해지지 않았다.

## 결정

**순서를 뒤집는다. LLM/RAG 가 만들고, 규칙 엔진이 검사한다.**

```
1  생성    12개월치 계획안을 만든다              LLM + RAG
2  검사    어긋난 곳을 찾는다                    규칙 엔진
3  처리    위반이 있으면 재생성하거나 교사에게 표시  호출한 쪽
```

**규칙 엔진의 출력은 계획안이 아니라 「위반 목록」이다.**

```python
def verify(plan, *, age_min, age_max, flags) -> list[Violation]
```

```python
@dataclass(frozen=True)
class Violation:
    month: int      # 3~2월 중 어느 달
    rule: str       # "legal_hours" · "age" · "safety" · "domain_balance"
    detail: str     # 교사에게 그대로 보여도 되는 한 줄
```

**검사 규칙 4개를 이 순서로 만든다.**

```
1  legal_hours      법정 안전교육의 주기와 연간 시수
2  age              활동 대상 연령이 반 연령을 벗어나나
3  safety           위험 도구가 최소 연령 미달 반에 들어갔나
4  domain_balance   5영역이 한쪽으로 쏠렸나
```

## 근거

**지금 시작할 수 있다** `[실측]`

`legal_hours` 는 `resources/rules/legal_safety_education.yaml` 만 있으면 돈다.
활동풀도, DB 행도 필요 없다. 순수 산수다.

선별 방향은 `activities` 200행이 커밋돼야 첫 줄을 쓸 수 있다. 6주차에 0행이었다.

**검사는 규칙으로 적을 수 있고, 선별은 아니었다** `[판단]`

```
선별   "놀이성이 높은 활동을 고른다"      → 무엇으로 판정하나.  정해진 적 없다
검사   "교통안전이 2개월에 1회 있나"      → 세면 된다
```

**어긋난 것을 찾는 건 빠짐없이 적을 수 있다. 좋은 것을 고르는 건 그렇지 않다.**
ADR-005 가 지키려던 것(법정 시수가 틀리지 않는다)은 검사만으로도 지켜진다.

**틀린 것을 못 만들게 하는 게 아니라, 틀린 채로 나가지 못하게 한다** `[판단]`

ADR-005 의 목표는 「모델이 법정 시수를 틀리지 않게」였다.
생성 단계에서 막든 검사 단계에서 막든 **교사에게 틀린 문서가 가지 않는다**는 결과는 같다.
검사 쪽이 구현이 작고, 규칙을 하나씩 늘려도 앞 규칙이 안 깨진다.

**비용 우려는 그대로 남는다** `[판단]`

ADR-005 가 계산한 대로 칸 단위 호출은 시스템 프롬프트가 43번 반복돼 15배가 나간다.
**생성은 여전히 월 단위 배치로 한다.** 검사는 LLM 을 안 쓰므로 비용이 0 이다.
재생성이 몇 번까지 허용되는지는 예산과 함께 따로 정한다 — 이 ADR 이 다루지 않는다.

## 대안

**ADR-005 를 그대로 간다** — 활동풀 200행을 기다린다.
활동풀은 수집·정제·태깅이 다 필요해서 최소 한 주다. 그동안 규칙 엔진 담당이 놀게 된다.

**검사 없이 LLM 에 전부 맡긴다** — ADR-005 가 이미 기각했다.
법정 시수가 틀리고 검증할 방법이 없다. 이 ADR 은 검사 층을 붙여서 그 기각을 뒤집는다.

**생성과 검사를 둘 다 LLM 으로** — 검사를 모델에 맡기면 검사 결과도 못 믿는다.
법정 시수는 산수라 모델이 할 일이 아니다.

**선별과 검사를 둘 다 만든다** — 같은 규칙을 두 군데 적게 된다.
연령 조건이 선별에도 있고 검사에도 있으면 한쪽만 고치는 날이 온다.

## 결과

- **`activities` 활동풀은 급하지 않다.** `legal_hours` 는 안 쓴다. `age` · `safety` ·
  `domain_balance` 가 쓰는데, 그건 2순위 이후다.
- **검사에 필요한 기준값은 `backend/resources/` 에 파일로 둔다.** 코드에 숫자를 박지 않는다.
  법이 바뀌면 파일 한 줄만 고친다.
  ```
  resources/rules/legal_safety_education.yaml   아동복지법 시행령 별표 6
  resources/rules/safety_flags.yaml             위험 도구.  법이 아니라 팀 판단
  ```
- **`verify()` 는 무엇을 할지 정하지 않는다.** 위반 목록만 준다.
  재생성할지 교사에게 보여줄지는 호출하는 쪽이 정한다. 규칙이 늘어도 이 경계는 안 바뀐다.
- **`safety` 규칙은 당분간 막지 않고 표시만 한다.** `min_age` 에 법적 근거가 없다.
  현직 교사 확인 전까지 교사를 막으면 없는 기준으로 막는 것이다.
- ADR-005 는 **대체됨**으로 바꾼다. 세 층 구조는 더 이상 유효하지 않다.
- `docs/api-spec.md` §4 의 `generation.method` 는 `RULE_LLM` 이 기본이 된다.
  검사만 통과한 것이라 `RULE_ONLY` 는 당분간 나오지 않는다.
