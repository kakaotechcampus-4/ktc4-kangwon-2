# ADR-079: 생성 요청 하나가 LLM 을 부르는 횟수를 8번으로 막는다

- 날짜: 2026-11-09
- 상태: 제안

## 맥락

[실측] 생성 요청 하나가 LLM 을 몇 번 부르는지는 `ssuksak.timing` 의 run 이 센다(`backend/app/shared/llm/client.py` `_llm_call` 의 `run.llm_calls`).
세기만 하고 막지는 않았다.

[실측] 2026-11-09 ADR-076 「모델에 닿지 못한 LLM 요청만 한 번 더 보낸다」가 들어오면서
시도마다 `_llm_call` 을 따로 지나 `run.llm_calls` 가 시도마다 오른다. 수리 1회와 재시도 1회가 겹치는 경로가 생겼고,
반복문이 새면 요청 하나가 끝없이 부를 수 있는데 그걸 막는 장치가 없다.

월 예산 카운터(70% 경고 · 90% 차단)는 2026-09-21 무효가 됐다(CLAUDE.md 「LLM 예산」) — 파일럿 중 교사 앞에서 서비스가 멈추면 안 되고,
사용량은 담당자가 본다.

## 결정

1. **생성 요청 하나(timing run) 안에서 LLM 호출은 8번까지다.** 9번째는 부르지 않고 `LlmFailed` — 계약상 `GENERATION_FAILED`(500, 「다시 시도」)다.
2. **재시도도 센다.** 막힌 시도는 세지 않고 `llm_call` 줄도 남기지 않는다. 상한 오류는 재시도 대상(`_NotDelivered`)이 아니라 다시 부르지 않는다.
3. `post_json` · `post_stream` 둘 다 걸린다. run 이 없는 호출(문서 초안 · 칸 재생성 · 연간 가져오기 추출 · jev 판정)은 걸지 않는다.

## 근거

- **8은 지금 설계상 최대다.** [실측] 경로별로 요청 하나가 부르는 횟수(2026-11-09 코드 확인, 재시도 1회 포함):
  ```
  run kind         호출                                  재시도까지 최대
  annual_play      스트림 4(구간 4개, 수리 없음)            8
  annual_theme     post_json 2(12개월 주제 + 소주제)        4
  monthly_theme    스트림 2(첫 호출 + 수리 최대 1)          4
  monthly_play     스트림 2(첫 호출 + 수리 최대 1)          4
  weekly           2(첫 호출 + 수리 최대 1)                 4
  ```
  근거 줄: `plans/router.py:455` · `generate_play_project_plan.py:50 · :136` · `planner/service.py:73 · :103` ·
  `generate_play_monthly_plan.py:326 · :347` · `planner/weekly.py:979 · :1011`.
- **월 예산 차단과 다르다.** [판단] 이 상한은 요청 하나 안에서 호출이 불어나는 것만 막는다. 월 합계는 세지 않고, 정상 요청은 막지 않는다.
  09-21 결정이 피하려던 「파일럿 중 서비스가 멈추는 일」은 생기지 않는다.
- **넘으면 버그다.** 설계상 최대와 같은 값이라, 9번째가 나가려 하면 어딘가 반복문이 샌 것이다.

## 대안

- **6** — 재시도 1회를 더해 놀이형 연간(최대 8)이 정상인데도 막힌다.
- **경로마다 다른 상한** — 경로가 바뀔 때마다 표를 같이 고쳐야 한다. 한 값으로 충분하다.
- **토큰 · 금액 상한** — 응답이 오기 전에는 출력 토큰을 모른다. 출력 상한은 `max_completion_tokens` 가 따로 있다.

## 결과

- 새 기능이 생성 요청 하나에서 LLM 을 더 부르게 되면 이 값과 위 표를 같이 고친다. 안 고치면 그 기능이 `GENERATION_FAILED` 로 끝난다.
- 상한에 걸린 요청은 `plan_timing` 줄의 `llm_calls=8` 로 보인다.
