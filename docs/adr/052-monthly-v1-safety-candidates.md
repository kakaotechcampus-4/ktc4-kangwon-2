# ADR-052: v1 월간은 안전교육 후보 8개를 만들고 교사가 주마다 고른다

- 날짜: 2026-10-31
- 상태: 채택 — 하민 제안 · 성진 구현, 하민 리뷰로 확인
- 대체: 새 계획안에 한해 ADR-033 §4 의 한 줄 「Backend 월간 생성은 v2 를 `supplemental=False` 로 넘긴다(2026-10-22 · 10-23 결정)」만 대체한다. ADR-033 의 나머지는 그대로 유효하다. 이미 만든 계획안은 저장된 그대로다.

## 맥락

[실측] 배치 정책 v2 는 법정 주에만 Rule 이 안전교육을 놓는다. 교사는 어느 주에 무엇을 둘지 고를 수 없었고, 고칠 수 있는 것은
이미 놓인 문장뿐이었다. 놀이 월간(ADR-046)은 처음부터 후보를 만들고 교사가 배치하는 구조다.
Core(#310)는 후보 모드(법정 6 + 생활안전 2)를 이미 갖췄고, mock 월간 LLM 도 후보 문장을 쓴다.

## 결정

1. **새 v1 월간은 후보 모드로 만든다.** `POST /api/plans/monthly` 가 안전교육 후보 8개(법정 6 + 생활안전 2)를 만들고
   교사가 주마다 0~1개를 둔다. 주별 안전교육 칸은 비워 두고, 표시값(`display_value`)은 응답마다 계산한다(저장하지 않는다).
2. **미배치 · 빈 문장은 안내(`notices`)이고 확정을 막지 않는다.**
3. **이미 만든 계획안은 저장된 그대로다.** 저장된 값 · 코드 경로를 바꾸지 않는다 — 세 목록이 비면 응답 · 편집 · 내보내기가 예전대로 동작한다.
4. 배치 API · 주별 칸 편집 막기 · 이력 `arrangement_change`, 응답 세 목록, HWPX 안전 줄(주마다 `display_value`)이 이 결정의 서버 쪽이다.
5. 후보를 못 만드는 자료 오류는 「다시 시도」(500)가 아니라 503 `DEPENDENCY_UNAVAILABLE` 로 낸다 — 다시 해도 같은 실패다.
   양식에 안전교육 칸이 없는 경우는 422 로 매핑하지만 방어용이다(안전교육은 필수 Section).
6. 두 판 상수(분류 · 품질)는 서버에 사본을 두지 않고 Core 조립부 값을 가져온다(ADR-046 Q4).

## 근거

- [실측] 생활안전 근거가 1~12월 모두 후보 8개를 만든다(2026-10-31 로컬 실측).
- [실측] 후보 모드에서도 `constraints` 의 `STATUTORY_SAFETY_EDUCATION` 은 `NOT_VERIFIED_SOURCE_REQUIRED` 그대로이고,
  `verification.findings` 에서 `SAFETY_ANNUAL_HOURS_NOT_VERIFIED` 만 사라진다(`backend/tests/test_monthly_plans_api.py`).
- [판단] 놀이 월간과 같은 구조라 화면 · 이력 · 내보내기를 한 모양으로 둘 수 있다.
- 하민 서버 협의 메시지 3절(2026-10-31) · 사용자 결정(2026-10-31).

## 대안

- 자동 배치 유지 — 교사가 주를 고를 수 없다는 문제가 그대로 남는다.
- 후보 수 축소(법정 6개만) — 생활안전 근거가 12개월 모두 2개를 만들어 줄일 이유가 없고, 놀이 월간과도 어긋난다.

## 결과

- 화면에 후보 패널이 있어야 교사가 배치한다 → 이 스위치는 화면 패널과 같이 머지한다.
- 후보 문장은 LLM 이 쓴다. `LLM_MODE=mock` 도 후보 문장을 써야 하며 이는 별도 Core 어댑터 변경으로 갖춰졌다.
- ADR-041(안전교육 배치는 교사가 직접 입력)과 같은 방향이다. 2026-10-22 · 10-23 결정(자동 배치 · 보충 주 없음)은 새 계획안에는 적용하지 않는다.
- 훈련(drill) 줄의 HWPX 출력은 이 결정 범위 밖이다.
