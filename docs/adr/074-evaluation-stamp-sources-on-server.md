# ADR-074: 평가 서류 도장의 근거를 서버에 남긴다 — 직접확인 · 폴더 결과는 교사 단위, 원장 서류는 원 단위

- 2026-11-09
- 상태 — 제안 (ADR-045 결정 5 · 6 일부 대체)
- 관련 — ADR-045 · ADR-022(결정 6) · ADR-019 · ADR-013 · ADR-073

## 맥락

평가 점검 화면은 서류 6종마다 도장 칸을 하나 둔다(평가 서류 도장판, 2026-11-08). 도장 안에는 「왜 찍혔는지」를
낱말로 적는다 — **쌤플확정 · 내컴퓨터 · 직접확인**(사용자 결정 2026-11-08). 근거가 둘이면 두 줄로 쌓는다.

ADR-045 는 이 근거들을 브라우저에 두었다.

- **결정 5** — 폴더 검사 결과는 화면 메모리에만 있다. [실측] 새로 고치면 도장 「내컴퓨터」가 사라지고, 근거 줄도 「폴더를 고르면」으로 돌아간다.
- **결정 6** — 못 찾은 서류 · 원장 서류 체크는 localStorage 에 항목 id 만 남긴다. [실측] 기기 · 브라우저마다 다르다.
  원장 서류(운영계획 · 연간 보육계획안 등)는 원에 한 벌인데 교사마다 따로 체크한다.
- [실측] 옛 화면은 폴더에서 찾은 서류를 체크 목록에 써 넣었다(`withFound`). 그 뒤로는 「폴더가 찍었나, 선생님이 찍었나」를 가를 수 없고,
  폴더를 다시 골라 못 찾아도 도장이 남았다. 2026-11-08 화면은 저장 키를 v2 로 바꿔 둘을 떼어 냈다.

사용자 요청(2026-11-08)은 「체크도 서버에 저장하고, 폴더 결과도 저장하자. 어떤 단위로 저장할지 정확히 조사하자」였다.

## 결정

1. **도장은 근거가 하나라도 있으면 찍힌다.** 근거는 셋이다.
   ```
   쌤플확정   쌤플에서 확정한 문서가 그 서류의 기준을 채웠다     쌤플이 만드는 서류(보육일지 · 계획안 · 영유아 평가)
   내컴퓨터   폴더에서 파일 이름으로 찾았다(「일부 빠짐」은 아니다)  6종 모두
   직접확인   선생님이 도장 칸을 눌렀다                         쌤플이 만들지 않는 서류(부모면담 · 이수증 · 개별화교육계획)
   ```
   **근거끼리 숫자를 더하지 않는다.** 화면은 근거마다 줄을 나눠 적는다. ADR-045 결과의 「두 결과를 합치지 않는다」를
   이렇게 읽는다 — 숫자는 합치지 않고, 도장은 근거 가운데 하나로 찍힌다.
2. **쌤플확정은 서류마다 서버 기준으로 센다.** 4-1 판정의 두 조건을 따로 채운 반 수를 응답에 더한다.
   `journal_classes` = 검토 기간 평일마다 확정 보육일지가 있는 반, `plan_classes` = 확정 월간계획안이 1건 이상인 반(2026-11-09 ADR-080 — 기간에 걸친 달마다 1건씩).
   영유아 평가는 4-2 `children` 그대로다. **쌤플확정은 저장하지 않는다** — 확정 문서에서 그때그때 센다.
3. **직접확인은 쌤플이 만들지 않는 서류만 받는다.** 쌤플 서류는 확정 문서로만 찍힌다. 확정 0건인데 눌러 찍으면 도장이 확정 문서와 다른 말을 한다.
4. **저장 단위가 둘이다.**
   ```
   직접확인 · 폴더 결과   원 · 학년도 · 교사 · 서류    evaluation_doc_marks
   원장 서류 체크         원 · 학년도 · 항목           evaluation_director_checks
   ```
   원장 서류는 자체평가 체크(ADR-022 결정 6)와 같은 원 단위다 — 그 원의 교사 누구나 같은 체크를 본다.
   바꾸기는 원을 만든 교사만 한다(ADR-087 결정 6, 2026-11-10).
5. **폴더 결과는 서류마다 다섯 가지만 남긴다 — 상태 · 검사 시각 · 검사 기간 · 이름으로 센 파일 수 · 빈 날(평일 · 달) 수.**
   파일 이름 · 경로 · 어느 날이 비었는지는 남기지 않는다. ADR-045 결정 5 의 「검사 결과는 화면 메모리에만」을
   「**파일 이름은 화면 메모리에만, 결과 요약은 서버에**」로 바꾼다. 새 폴더 검사는 그 교사의 폴더 결과를 통째로 바꾼다 —
   새 폴더에 없는 서류의 옛 결과는 지운다.
6. **브라우저에 남은 옛 체크는 옮기지 않는다.** 새 화면은 localStorage 를 읽지도 쓰지도 않는다. ADR-045 결정 6 을 대체한다.

## 근거

- **[판단]** 서류 6종 · 폴더 결과가 교사 단위인 이유 — 폴더는 교사 컴퓨터마다 다르다. 원 단위로 두면 다른 반 선생님이 고른 폴더가
  내 도장을 덮는다. 서류도 담임이 자기 반 것을 챙긴다.
- **[판단]** 원장 서류가 원 단위인 이유 — 원에 한 벌이다. 교사마다 따로 체크하면 같은 원 화면이 서로 다른 말을 한다.
- **[판단]** 파일 이름을 남기지 않는 이유는 ADR-045 와 같다 — 이름에 아동 실명이 들어갈 수 있다(ADR-013).
  상태 · 날짜 · 숫자에는 실명이 없다.
- **[판단]** 숫자를 둘만 더한 이유 — 다시 열어도 근거 줄(「이름으로 찾음 · 2건」 · 「일부 빠짐 · 빈 평일 3일」)이 같게 하려고.
  빈 날 목록은 길고(보육일지는 40여 일까지) 「자세히」에서만 쓴다. 사용자 결정(2026-11-09) — 「건수까지」.
- **[판단]** 상태와 숫자가 서로 맞는지 스키마가 본다(못 찾음이면 센 파일 0, 일부 빠짐이면 빈 날 1 이상).
  화면 `checkDoc` 의 판정과 같은 관계다. 어긋나면 근거 줄이 서로 다른 말을 한다.
- **[실측]** 새 표 둘을 더하기만 한다. 옛 코드가 쓰는 칸을 지우거나 제약을 걸지 않아 ADR-073 의 `backend (rollback compat)` 를 지난다.

## 대안

**계속 브라우저에 둔다** — 기기마다 다르고, 원장 서류 체크가 교사마다 따로다. 새로 고치면 「내컴퓨터」가 사라진다.

**모두 원 단위 하나로 둔다** — 다른 교사의 폴더 검사가 내 결과를 덮는다.

**빈 날짜 목록까지 남긴다** — 다시 열어도 「자세히」의 빈 평일이 보인다. 칸이 하나 더 들고, 사용자가 건수까지로 정했다(2026-11-09).

**폴더 결과를 체크 목록에 써 넣는다(옛 `withFound`)** — 근거를 가를 수 없고, 다시 골라 못 찾아도 도장이 지워지지 않는다.

**쌤플 서류에도 직접확인을 받는다** — 확정 0건인데 도장이 찍혀, 쌤플 숫자와 도장이 다른 말을 한다.

**옛 localStorage 체크를 서버로 옮긴다** — 기기마다 값이 달라 어느 쪽이 맞는지 모른다. 원장 서류는 교사마다 달랐다.

## 결과

- 표 둘(`evaluation_doc_marks` · `evaluation_director_checks`)과 `PUT …/evaluation-checklist/documents` · `…/director` 가 생긴다.
  GET 응답에 `documents`(6줄) · `director`(5줄)와 4-1 의 `journal_classes` · `plan_classes` 가 더해진다(api-spec §12).
- 같은 원 다른 교사의 직접확인 · 폴더 결과는 보이지 않는다. 원장 서류 체크는 같이 본다.
- 브라우저에 남은 옛 체크는 버려진다 — 처음 열면 직접확인 · 원장 서류를 다시 체크해야 한다.
- **쌤플확정은 원 전체 기준이다.** AUTO 판정이 원의 반 전부를 센다 — 내 반은 다 썼어도 다른 반이 비면 빈 칸이다.
  교사 단위 도장과 단위가 다르다. 반을 고르게 하는 것은 이 ADR 이 하지 않는다.
- 「자세히」의 찾은 파일 이름 · 빈 날짜는 여전히 폴더를 고른 그 방문에만 보인다.

## 한계

- 검사 기간은 화면이 오늘로 정해 보낸다. 서버는 첫날이 마지막 날보다 늦지 않은지만 본다.
- 직접확인 시각은 처음 누른 때다. 풀었다가 다시 누르면 새 시각이다(자체평가 체크와 같다).
