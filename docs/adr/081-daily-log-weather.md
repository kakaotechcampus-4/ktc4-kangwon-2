# ADR-081: 일일 보육일지의 날씨를 기상청 · 에어코리아에서 받아 채우고, 교사가 고른 값이 이긴다

- 날짜: 2026-11-09
- 상태: 제안 (서버 · 종이까지. 화면은 PM 시안 확인 뒤)

## 맥락

[실측] 실물 일일 보육일지의 머리는 「날짜 · 요일 · 날씨 · 반」이다(`docs/journal-form-survey.md` B원 일일 양식).
우리 일일 보육일지 hwpx 에는 날씨 칸이 없어, 교사가 내려받은 뒤 손으로 적어야 했다.

[출처] ADR-008 이 「당일 나갈까 판정(F7, 날씨 · 미세먼지 API)」을 P1 일지 기능으로 옮겨 두었다.
그때 지운 것은 계획 시점의 기후 프로파일(F7a)이다. 이 ADR 은 F7 의 일부 — 그날 날씨를 일지에 적는 것 — 를 연다.
실외놀이를 할지 **판정하지 않는다.** 비 · 눈 · 미세먼지 나쁨이면 화면이 대체놀이 칩을 띄울 수 있게 까닭(`indoor_hint`)만 준다.

바깥 서비스를 새로 붙이는 결정이다. CLAUDE.md 「부가 기능이 죽어도 본 기능은 돌아간다」가 걸린다.

## 결정

1. **공공데이터포털 API 둘을 서버에서만 부른다.** 인증키 하나(`DATA_GO_KR_SERVICE_KEY`)로 같이 쓴다.
   - 하늘: 기상청 단기예보 조회서비스 `getVilageFcst`. 그날 02시 발표분의 낮(09~18시) SKY · PTY 를
     「맑음 / 구름많음 / 흐림 / 비 / 눈 / 비나 눈」 하나로 줄인다. 한 시간이라도 비 · 눈이면 그쪽, 아니면 가장 많은 하늘 상태(같으면 더 흐린 쪽).
   - 미세먼지: 에어코리아 대기오염정보 `getCtprvnRltmMesureDnsty`(시도별 실시간). 시군구와 같은 이름의 측정소가 있으면 그 값,
     없으면 시도 측정소 평균. PM10 · PM2.5 등급 중 나쁜 쪽(좋음 · 보통 · 나쁨 · 매우나쁨).
2. **시군구 → 격자(nx, ny) 표를 저장소에 둔다** — `backend/resources/weather/kma_grid.csv`.
   기상청이 공개한 격자 좌표 엑셀(2610판, 2026-11-09 받음)에서 `backend/scripts/build_weather_grid.py` 가 만든다.
   열쇠는 우리 원 지역 이름(어린이집 목록과 같은 230곳)이다. 원 지역 사본을 저장소에 두는 ADR-068 과 같은 방식이다.
3. **지역 · 날짜마다 한 번만 부른다.** 받은 값을 `region_weather` 에 남긴다. 둘 다 못 받았으면 남기지 않는다(다음 조회에 다시).
4. **교사가 고른 값이 이긴다.** `routine_weather`(반 × 날짜)에 따로 남긴다. 자동 값을 덮어쓰지 않는다 —
   지우면 자동 값으로 돌아간다. 미세먼지는 고르지 않는다(종이에 안 나간다).
5. **실패하면 값 없음이다.** 키가 없음 · 호출 실패 · 표에 없는 지역 · 예보가 없는 날짜 모두 `source: "none"` 으로 200 이다.
   오늘 · 어제만 부르고(단기예보가 하루 전 발표분까지 준다), 미세먼지는 오늘만 부른다.
6. **LLM_MODE 와 같은 문을 둔다** — `WEATHER_MODE=mock|real`. real 은 `IS_SERVER` 일 때만 부르고,
   mock 은 서버 밖에서만 가짜 응답을 쓴다. **서버에서 mock 이면 아무것도 부르지 않는다** — 가짜 날씨가 제출 종이에 찍히면 안 된다.
   테스트는 `weather.transport` 에 가짜 전송을 끼운다.
7. **종이에는 제목 아래 머리 줄로 싣는다** — `날짜 : 2026년 9월 22일 (화)      날씨 : 맑음`. 값이 없으면 「날씨 :」 뒤를 비운다.
   미세먼지는 싣지 않는다.
8. **화면 계약** — 일과 기록 하루치 조회(`GET /api/routines?class_id&from=D&to=D`)에 `weather` 를 붙이고,
   교사 선택은 `PUT /api/routines/weather` 다(docs/api-spec.md §10-1 「그날 날씨」).

## 근거

- [실측] 일일 양식 머리에 날씨가 있다 — `docs/journal-form-survey.md`. 주간 표준 양식에는 없어서 주간 종이는 그대로 둔다.
- [실측] 2026-11-09 공공데이터포털에서 받은 격자 엑셀은 광주 · 전남을 「전남광주통합특별시」 하나로 낸다.
  어린이집 목록 · 지역 고르개는 광주광역시 · 전라남도로 나눈다(`scripts/fetch_daycares.py` 도 같은 일을 한다).
  표는 우리 이름을 열쇠로 하고 기상청 이름을 `kma_name` 칸에 남겼다. 일반구가 있는 시 13곳은 엑셀에 시 줄이 없어
  행정구역코드가 가장 작은 구를 쓴다 — 격자가 5km 칸이라 같은 시 구끼리는 0~3칸 차이다(화성시가 가장 넓다).
- [판단] **하루 한 번 저장.** 같은 원 교사 여럿 · 같은 지역 원 여럿이 하루 몇 번씩 일과 화면을 연다. 그때마다 부르면
  일일 호출 한도(개발계정)와 화면 대기 시간이 같이 는다. 첫 조회 때 받은 예보가 그날 값이 된다.
- [판단] **교사 값을 따로 둔다.** 자동 값을 덮어쓰면 「교사가 고친 것인가」를 알 수 없다 — CLAUDE.md 「교사가 고쳐도 근거를 그대로 둔다」와 같은 생각이다.
- [판단] **표 밖 머리 줄.** 표에 줄을 더하면 일과 줄 주소가 하나씩 밀려 이미 있는 내보내기 계약(머리행 1 · 원형 · 꼬리 2)과
  그 시험이 바뀐다. 실물도 날짜 · 날씨는 표 위 머리에 있다.
- [판단] 시간 제한은 API 마다 3초다. 교사 화면이 기다리는 시간이라 짧게 둔다. 실패는 저장하지 않으니 다음 조회에 다시 시도한다.

## 대안

- **초단기실황(관측값)** — 지금 이 순간의 값이라 하루를 한 낱말로 줄일 수 없다.
- **종관기상관측(ASOS) 일자료** — 지난 날짜도 된다. 그러나 관측소 단위라 시군구 → 관측소 표가 또 필요하고 API 가 하나 더 는다.
  지난 날짜는 교사가 고르면 된다. 필요해지면 그때 더한다.
- **화면에서 직접 부른다** — 키가 번들에 박힌다(CLAUDE.md 보안).
- **확정할 때 날씨를 문서에 박는다** — 교사가 확정 뒤에 날씨를 고치면 종이에 안 나간다. 날씨는 3층 사실이 아니라
  `stale` · 재확정을 걸 이유도 없다. 내보낼 때 다시 읽는다.
- **시군구 위경도로 격자를 계산한다** — 기상청 변환식은 있지만 시군구 위경도 표가 또 필요하다. 기상청이 낸 격자 값을 그대로 쓰는 쪽이 출처가 하나다.

## 결과

- 서버 `.env` 에 `DATA_GO_KR_SERVICE_KEY` 와 `WEATHER_MODE=real` 을 넣어야 운영에서 값이 나온다. 없으면 「값 없음」으로 돈다.
- 새 표 둘(`region_weather` · `routine_weather`)과 마이그레이션 `463ecc68c630` 이 생긴다. 이미 있는 표는 건드리지 않아 ADR-073 롤백 한 칸이 된다.
- 행정구역이 바뀌면 격자 엑셀을 다시 받아 `scripts/build_weather_grid.py` 를 돌린다. 지역 고르개(`regions.ts`) · 어린이집 목록과 같이 맞춘다.
  표에 없는 지역은 오류가 아니라 값 없음이다.

## 한계

- **지난 날짜(그제 이전)는 자동 값이 없다.** 교사가 고른 값만 쓴다.
- **에어코리아 `sidoName` 이 광주 · 전남 통합을 따라 바뀌면** 그 두 곳의 미세먼지가 값 없음이 된다. 실제 키로 확인하지 않았다.
- **실제 키로 한 번도 부르지 않았다.** 응답 모양은 두 API 의 활용가이드와 가짜 전송으로만 맞췄다. 키를 받으면 서버에서 한 번 찍어 본다(CLAUDE.md 「서버 값은 실제 응답을 본다」).
- **한쪽만 받은 날은 다른 쪽을 그날 다시 부르지 않는다.** 하늘만 받고 미세먼지가 실패했으면 그날 미세먼지는 값 없음이다.
- **새 hwpx 머리 줄을 한글에서 열어 보지 않았다.** `.hwp` 변환은 된다. 내려받아 한글에서 한 번 연다.
