# ADR-001: PostgreSQL 을 쓴다

- 2026-09-06
- 상태 — 채택

## 맥락

기술 스택 초안에 MySQL 을 적어뒀다. 그런데 BE 팀원이 작성한 스키마에 `tags JSONB` 가 있었다.
`JSONB` 는 PostgreSQL 타입이고 MySQL 에는 없다.

## 결정

PostgreSQL 15 를 쓴다. `docker-compose.yml` 에 `postgres:15` 로 버전을 고정한다.

## 근거

**1. 태그 검색이 가장 잦은 쿼리다** `[판단]`

활동마다 5영역 태그·주제 태그가 붙고, 생성할 때마다 "자연탐구 태그 달린 활동 뽑아와"를 돈다.

| | PostgreSQL | MySQL 8 |
|---|---|---|
| 저장 | `jsonb` | `JSON` |
| 인덱스 | `GIN` 을 바로 건다 | generated column 을 파생시켜 거기 인덱스 |
| 쿼리 | `tags @> '["자연탐구"]'` | `JSON_CONTAINS(...)` + 우회 |

MySQL 은 태그 종류가 늘 때마다 우회 컬럼과 마이그레이션이 붙는다.

**2. 향후 활동 추천에 임베딩이 필요하다** `[판단]`

PostgreSQL 은 `pgvector` 확장이라 같은 DB 안에서 된다.
MySQL 은 벡터 DB 프로세스를 따로 띄우고 동기화 코드를 써야 해서 배포 대상이 2개가 된다.

**3. 결정적 이유 — 이미 그렇게 짜여 있었다**

PostgreSQL 이면 기존 스키마를 고칠 게 0이고, MySQL 이면 남이 쓴 스키마를 되돌려야 한다.
5주차에 이미 시간이 없는데 굳이 되돌릴 이유가 없다.

## 대안

**MySQL** — RDS 요금 차이는 무의미하고 팀원 익숙함이 유일한 근거였다.
`tags JSONB` 를 쓴 사람이 PostgreSQL 을 기본값으로 생각했다는 게 그 근거도 무너뜨렸다.

**DynamoDB** — 관계형이 필요하고 조인을 쓴다. 기각.

## 결과

- `postgres:latest` 를 쓰지 않는다. 메이저 버전이 올라가며 깨진다.
- 로컬·CI·서버가 모두 15 여야 한다. 버전이 갈리면 재현 안 되는 버그가 나온다.
- `psql` 클라이언트 버전은 더 높아도 된다(하위 호환).
