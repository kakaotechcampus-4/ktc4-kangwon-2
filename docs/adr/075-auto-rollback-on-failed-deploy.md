# ADR-075: 교체 뒤 서버 안에서 서비스가 안 살아나면 같은 배포 run 이 직전 성공 버전으로 되돌린다

- 날짜: 2026-11-09
- 상태: 제안 — 구현 중(draft PR). 구현 · 운영 연습 뒤 채택으로 바꾼다

## 맥락

[실측] 배포 뒤 확인(`.github/workflows/deploy.yml` 「Health check」, `/health/ready` 30번)이 실패하면 run 이 실패하고
Discord 알림만 간다. 직전 버전으로 돌아가지 않는다 — 사람이 알림을 보고 손 롤백(`ref` 에 SHA)을 해야 한다.

[실측] 그 확인은 GitHub 러너가 인터넷을 건너 도메인으로 묻는다. 2026-10-11 배포는 서버가 멀쩡했는데 secret 에 남은 옛 IP 때문에
확인만 실패했다(`docs/evaluation/09-deployment.md` 「배포 사고 하나를 끝까지 추적했다」). 밖에서 본 실패로 되감으면
멀쩡한 새 버전을 옛 코드로 내린다 — 옛 코드는 새 코드가 쓴 JSONB 키를 저장할 때 버린다(같은 문서 「운영에서 롤백을 한 번 해 봤다」).

## 결정

구현 플랜을 따라 채운다. 방향:

1. **판정은 서버 안에서.** `scripts/deploy.sh` 가 교체 뒤 서버 자신의 nginx 로 `/health/ready`(backend · DB)와 `/`(화면)를 묻고,
   안 살아나면 전용 종료 코드 3 으로 끝난다
2. **3 일 때만 같은 run 안에서 되돌린다.** 대상은 develop 의 마지막 성공 배포가 올린 커밋. push 배포는 늘, 손 배포는 `auto_rollback` 을 켰을 때만
3. **밖에서 확인은 알림만.** DNS · 인증서 · secret 문제는 코드를 되감아도 안 고쳐진다

## 근거 · 대안 · 결과

구현 · 연습 뒤 채운다.
