# ADR-004: 아동 실명은 저장하고 LLM 직전에 치환한다

- 2026-09-05 결정 / 2026-09-08 보강
- 상태 — 채택

## 맥락

처음에는 아동 실명을 서버에 저장하지 않고 기기 로컬에서만 치환하는 설계를 세웠다.
그런데 관찰일지·발달평가는 아동 실명이 본체라 기능이 성립하지 않았다.

법적 근거를 확인하지 않고 "아동 정보는 위험하다"는 감각으로 판단한 것이었다.

## 결정

- 아동 실명을 **DB에 저장한다.**
- **동의서를 우리가 받지 않는다.** 원이 보호자에게 받는다. 우리는 아동 명단 화면에
  **처리 범위와 책임 소재를 적은 확인 문구**를 띄우고, 원이 확인해야 입력칸이 열린다.
- **LLM 호출 직전에 아동 코드로 치환한다.** 프롬프트·응답·로그에 실명을 남기지 않는다.
- 치환은 `shared/childCode` 한 곳에서만. 실패 시 호출하지 않고 에러를 낸다.
- 적용 시점은 **P1부터.** 계획안(P0)은 반 단위 문서라 아동 이름이 없다. `[실측]`

## 근거

**저장은 법적으로 가능하다** `[출처]`

개인정보보호법 §22의2 — 법정대리인 동의로 만 14세 미만 정보를 처리할 수 있다.
키즈노트 등 상업 서비스도 이 방식이다.

**동의를 받을 의무는 원에 있고 우리에게 없다** `[판단]`

| | 역할 | 의무 |
|---|---|---|
| 어린이집 | 개인정보처리자 | 보호자 동의를 받는다 |
| 쓱싹요정 | 수탁자 (§26 처리위탁) | 위탁 범위 안에서 처리만 한다 |

동의서 파일을 우리가 업로드받으면 **우리가 처리자가 되고 보관 의무가 따라온다.**
받을 이유가 없다. 화면에는 확인 문구만 띄운다 — 무엇을 처리하는지, 동의 확보 책임이
원에 있다는 것, LLM 으로는 실명이 나가지 않는다는 것.

**저장 동의와 전송 동의는 별개다** `[출처]`

| | 근거 | 동의서 문구 |
|---|---|---|
| DB 저장 | §22의2 법정대리인 동의 | "아동 정보를 수집·저장" |
| LLM 전송 | §26 처리위탁 + **§28의8 국외 이전** | "국외 소재 AI 처리업체로 전송" |

**치환하는 진짜 이유는 법이 아니라 로그다** `[판단]`

```
LLM 요청 로그 → 서버 로그 파일 → 모니터링 → 에러 리포터 → 공급자 로그
```

코드를 6명이 만진다. `logger.info(prompt)` 한 줄이면 유출이다.
치환하면 이 경로 전체가 개인정보가 아니게 된다. 비용은 딕셔너리 하나.

**P0 에 아동 이름이 없다** `[실측]`

월간계획안 실물 5장에 나오는 이름은 반 이름(씨앗반·새싹반·풀잎반)과
담임 이름(조혜란·김희숙·박지니)뿐이다. 계획안은 연간·월간·주간 모두 반 단위 문서다.
→ 5주차에 `shared/childCode` 를 만들지 않는다.

## 대안

**실명 미저장 + 기기 로컬 치환** — 원안. 관찰일지가 성립하지 않는다. V2 로 이연.

**실명을 그대로 LLM 에 전송** — 동의서에 국외 이전을 넣으면 합법이다.
그래도 로그 유출 경로가 남아서 치환을 택했다.

## 결과

- 아동에게서 **이름만 받는다.** 생년월일·성별·건강정보를 받지 않는다.
  발달평가를 스펙아웃했으므로 생년월일을 쓰는 기능이 없다(ADR-007).
  이름만이면 「이름+생년월일+원명」 특정 조합이 애초에 생기지 않는다.
- 아동 명단 입력칸은 **동의 확인 체크박스 뒤에서만** 활성화한다.
- 치환 토큰은 `CHILD_01` 이 아니라 **받침 있는 더미 한글 이름**을 쓴다.
  한국어 조사가 이름 받침에 붙어서, 영문 토큰이면 복원 후 조사가 틀어진다.
- **개발 DB에 실제 아동 실명을 넣지 않는다.** 테스트는 가명으로.
