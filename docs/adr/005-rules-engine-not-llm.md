# ADR-005: 배치·선별은 규칙 엔진, LLM 은 문장화만

- 2026-09-07
- 상태 — 채택

## 맥락

계획안 생성을 LLM 에 통째로 맡기면 「이 칸에 뭘 넣을까」부터 「어떻게 쓸까」까지
전부 모델이 판단한다. 그러면 할루시네이션 표면이 문서 전체가 된다.

그리고 법정 안전교육 시수처럼 **틀리면 안 되는 계산**이 섞인다.

## 결정

세 단계로 나눈다. 앞 둘에 LLM 이 들어가지 않는다.

```
1  배치 층   어느 칸에 무엇이 들어가나        규칙 엔진
     법정 → 행사·달력 → 연간 주제 파생 → 5영역 균형 → 트렌드

2  선별 층   후보 중 무엇을 고르나            규칙 엔진
     연령 → 누리과정 → 안전성 → 원 특성 → 놀이성 → 트렌드

3  문장화     "개미 관찰" → "꼭꼭 숨은 개미 찾기!"   LLM
```

## 근거

**할루시네이션 표면이 문장 한 줄로 좁아진다** `[판단]`

배치와 선별은 검증 가능한 규칙이다. 문장만 모델이 쓰면
틀려도 문장 하나가 이상할 뿐이고, 법정 시수나 영역 균형은 안 틀린다.

**법정 계산을 모델에 맡길 수 없다** `[출처]`

아동복지법 시행령 별표6 — 안전교육 5영역의 주기가 다르다.
교통안전 2개월 1회, 실종·유괴 3개월 1회, 성폭력·아동학대 6개월 1회.
합계 연 44시간. 이건 산수이고 모델이 할 일이 아니다.

**두 층은 독립적으로 같은 결론에 도달했다**

배치 층은 우리가 만들고 선별 층은 AI 담당이 제안했는데,
**양쪽 모두 트렌드가 최하위**로 나왔다.

**비용도 여기서 갈린다** `[판단]`

배치·선별이 끝나면 소재 목록이 확정되므로 **한 반 한 달을 호출 1~2회**로 처리한다.

```
입력   시스템 프롬프트 1,500 + 소재 43개 × 20  ≈ 2,400 토큰
출력   43개 문장 × 30                          ≈ 1,300 토큰
```

칸 단위로 호출하면 시스템 프롬프트가 43번 반복돼 15배 이상 나간다.
엘리스 팀 예산이 ₩120,000/월이고 초과하면 키가 삭제된다.

## 대안

**LLM 에 전부 맡김** — 프롬프트 하나로 계획안을 뽑는다.
법정 시수가 틀리고, 검증할 방법이 없고, 비용이 15배다.

**배치는 규칙, 선별도 LLM** — 선별은 「연령 적합성」처럼 데이터로 판단되는 것이라
모델이 필요 없다.

## 결과

- 선별 층 1순위(연령)와 3순위(안전성)가 `activities` 테이블에 컬럼을 요구한다.
  `age_min` · `age_max` · `safety_flags`. **첫 마이그레이션에 넣는다.**
  활동 200개를 다 넣은 뒤에 추가하면 200개를 다시 훑어야 한다.
- 안전성 플래그 목록을 `resources/rules/safety_flags.yaml` 로 만든다.
  가위·글루건·뜨거운 물·삼킴 위험. 트렌드봇 승인 로직은 "성인 가요냐"를
  걸러내지만 도구 위험은 걸러내지 않는다.
- 프롬프트를 **월 단위 배치**로 설계한다.
