# ADR-063: 카카오 로그인을 더하고, 같은 이메일 계정에 잇는다

- 2026-11-06
- 상태 — 채택
- 관련 — ADR-017(인증) · ADR-013(브라우저 저장) · `docs/api-spec.md` §0-1

## 맥락

교사는 이메일 · 비밀번호로만 들어온다. 비밀번호를 하나 더 만들고 외우는 것이 첫 화면의 문턱이다.
교사 대부분이 카카오톡을 쓰고, 카카오 로그인은 처음 누르면 곧 가입이다.
팀장 요청으로 로그인 화면을 카카오 우선으로 바꾼다(2026-11-06 수민 · 사용자 선택).

화면의 계정 기록 · 반 설정은 **이메일을 열쇠로** 브라우저에 남는다(`lib/auth/account-store.ts`).

## 결정

1. **인가 코드 방식.** 화면이 카카오 동의 화면으로 보내고, 돌아온 `code` 를 서버가 카카오 토큰 ·
   계정 정보로 바꾼다. 카카오 토큰은 쓰고 버린다 — 저장하지 않는다.
2. **동의 화면 주소는 서버가 만든다**(`GET /api/auth/kakao/authorize`). REST API 키를 화면 번들에
   넣지 않는다(`NEXT_PUBLIC_` 금지).
3. **`state` 는 화면이 만들고 화면이 맞춰 본다.** `sessionStorage` 에 두고 돌아왔을 때 비교한다(CSRF).
4. **계정 찾기 순서** — 카카오 회원번호(`users.kakao_id`) → 검증된 같은 이메일 → 새 계정.
   이메일이 같으면 기존 계정에 회원번호를 잇는다. 이름은 교사가 적은 것을 두고 카카오 별명으로 덮지 않는다.
5. **이메일이 없으면 받지 않는다**(422). 열쇠가 이메일이라, 없으면 화면 기록이 어디에도 안 붙는다.
   카카오 콘솔에서 이메일 동의항목을 켜야 한다.
6. **검증된 이메일만 쓴다.** `is_email_valid` · `is_email_verified` 가 둘 다 참일 때만.
7. **카카오로만 만든 계정은 비밀번호가 없다.** 아무도 모르는 무작위 비밀번호의 해시를 넣는다.
8. **키가 없으면 카카오 경로만 503 이다.** 이메일 로그인은 그대로 돈다.

## 근거

- [판단] 같은 이메일을 잇지 않으면, 이메일로 가입했던 교사가 카카오를 누를 때 409 를 보고 막힌다.
  카카오가 검증한 이메일이면 같은 사람이라고 본다 — 업계 관례.
- [판단] 검증 안 된 이메일로 이으면, 남의 이메일을 카카오에 적어 둔 사람이 그 계정을 가져간다(6).
- [판단] 비밀번호 칸을 nullable 로 바꾸면 `login` · `change_password` 가 None 을 다 따로 봐야 한다.
  무작위 해시면 기존 검사가 그대로 막는다(7).
- [출처] 카카오 로그인 REST API 문서 — 인가 코드는 한 번만 쓰고, redirect_uri 가 콘솔 값과 다르면 KOE006 이다.

## 대안

- **카카오 JavaScript SDK** — 화면에 앱 키를 넣어야 하고 외부 스크립트가 하나 는다. 고르지 않았다.
- **이메일 대신 카카오 회원번호를 화면 열쇠로** — `account-store` · 반 설정 · 이전 데이터 이전을
  모두 바꿔야 한다. 이번 범위가 아니다.
- **같은 이메일이면 409 로 막기** — 안전하지만 기존 교사가 카카오를 못 쓴다.

## 결과

- `users.kakao_id`(BIGINT, UNIQUE, NULL) 가 생긴다.
- 서버 `.env` 에 `KAKAO_REST_API_KEY` · `KAKAO_REDIRECT_URI` (· 켰으면 `KAKAO_CLIENT_SECRET`) 를 넣고,
  콘솔에 같은 Redirect URI 를 등록해야 켜진다.
- 카카오 연결 끊기 · 탈퇴 콜백은 아직 없다. 카카오 쪽에서 연결을 끊어도 우리 계정은 남는다.
- 카카오로만 만든 계정은 「비밀번호 바꾸기」를 쓸 수 없다(지금 비밀번호를 모른다).
