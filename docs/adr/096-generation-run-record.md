# ADR-096: 생성 요청마다 실행 기록을 한 줄 남기고, 진행 표시는 서버 단계를 따른다

- 날짜: 2026-11-10
- 상태: 제안
- 관련: ADR-030 PM-12 · ADR-032(실행 기록) · ADR-072(트렌드) · ADR-073(롤백 한 칸) · ADR-077(놀이 연간 동시 호출) · ADR-081(호출 상한) · `docs/api-spec.md` §9-8 · 5c(실행 이력 조회)

## 맥락

[실측] `CLAUDE.md` 의 「생성」 절 · ADR-030 PM-12 · ADR-032 가 「실행 기록(Generation Run)」을 근거 자리로 가리키는데 그 표가 없다. LLM 을 썼는지(mock 여부)는 설정과 서버 로그로만 안다.

[실측] 5c 목표가 「실행 이력(run · 버전 · 프롬프트 버전) 조회 가능」을 요구한다.

[실측] 화면 링은 브라우저 `localStorage` 에 기억한 예상 시간으로 찬다. 서버가 어디까지 갔는지와 상관이 없다 — 서버가 수리 호출에 들어가도 링은 모른다.

## 결정

- **D1. `generation_runs` 표 — 요청마다 한 줄, 반 확인 직후 쓴다.** 숫자와 이름만 든다. 칸은 `id` · `kind` · `center_id` · `class_id` · `plan_id` · `status` · `stage` · `error_code` · `mode` · `model` · `prompt_versions` · `llm_calls` · `phase_ms` · `started_at` · `finished_at`.
  프롬프트 · 응답 본문 · 반 이름 · 아이 정보 · 요청 사항 원문 · 예외 문장은 저장하지 않는다.
- **D2. id 는 화면이 uuid 로 만들어 `X-Generation-Run-Id` 로 보낸다.** 없으면 서버가 만든다. uuid v4 가 아니면 422(입력 검사는 스키마에서). 같은 id 가 다시 오면 덮지 않고 그 요청의 기록을 끈다(생성은 한다).
- **D3. 생성 POST 의 응답 · 상태 · 오류 계약은 그대로 둔다.** 진행은 `GET /api/generation-runs/{id}` 를 약 2초마다 물어 본다. 실행 이력은 반별 목록 `GET /api/generation-runs?class_id=` 로 조회한다(5c).
- **D4. 단계는 종류별 큰 단계다.** 앞으로만 가고 `ssuksak.timing` 구간에서 나온다(`generation_runs.py` 의 `STAGES` · `OPENS`). 놀이 연간은 새 구간 `overlap`(겹침 찾기 · 겹친 후보 다시 만들기)이 가운데 단계를 연다. 연간 주제형은 소주제 구간을 `subthemes` 로 나눈다(예전엔 소주제 LLM 을 기다리는 내내 `save` 구간이었다).
- **D5. 계획안 FK 는 `ON DELETE SET NULL`.** 계획안을 지워도 기록은 남는다. 반 · 원에는 FK 를 두지 않는다 — 진짜 commit 하는 테스트가 반 · 원을 지운다.
- **D6. 기록이 실패해도 생성은 돈다.** 기록 전용 작은 연결 풀 · 연결 2초 · 풀 대기 1초 · 잠금 · 문장 2초. 한 번 실패하면 그 요청은 기록을 끈다. 한 요청에 쓰기는 최대 5번(첫 줄 1 + 단계 전진 최대 3 + 끝 1)이다.
- **D7. RUNNING 이 15분을 넘으면 읽을 때 `UNKNOWN` 으로 보인다.** 저장하지 않는다. 계획안 commit 뒤 프로세스가 죽었거나 끝 줄을 못 쓴 경우다.
- **D8. 이 표가 담는 것.**
  - mock 여부(`mode`, ADR-032 이행).
  - 프롬프트 판(`prompt_versions`). provider 를 지나는 요청의 `prompt_version` 과 연간 상수에서 모은다 — 실패 · 수리 · mock 포함. `PromptNoted` 가 `with_masked_memo` **안쪽**에서 적으므로 가명 치환을 통과해 실제로 부른 요청만 남는다.
- **D9. 트렌드 상태는 담지 않는다.** `CLAUDE.md` 대로 서버 로그 한 줄로 갈음한다.

## 이 표가 아닌 것

- 작업 큐 · 작업 테이블이 아니다. 워커가 없고, 생성은 요청 스레드가 처음부터 끝까지 한다.
- 이어 만들기에 쓰지 않는다. 구간별 결과를 저장하지 않으며, 계획안은 모든 단계가 통과한 뒤 한 번만 저장한다.
- 그래서 아래 세 문장은 그대로 참이다.
  - `docs/techspec/README.md` 「저장은 마지막에 한 번만 한다」
  - `docs/techspec/README.md` 「구간별 저장 · 작업 큐로 이어서 하기는 하지 않는다 | 생성 작업 테이블 + 워커」
  - `docs/techspec/agent.md` 「하지 않은 것: 구간별 저장 · 작업 큐로 이어서 하기」

## 근거

- [실측] `timing` 이 이미 요청 하나의 구간 · 호출 수를 센다. 관측 자리를 거기에 두면 p0-planning 안의 구간 전환(`select` · `prompt` · `validate` · `repair` · `assemble`)까지 보인다. backend 가 바깥에서 감싸면 볼 길이 없다.
- [실측] 프롬프트 판은 요청 객체의 `.prompt_version` 에 실려 backend 가 만든 provider 를 지난다. p0-planning 쪽은 `timing.py` 한 파일만 고친다. `shared/llm` 의 `_llm_call` 로는 못 잡는다 — 어댑터의 HTTP payload 에 판이 없다.
- [실측] nginx 생성 제한(`limit_req zone=gen`)은 생성 POST 정확 경로에만 걸린다. `/api/generation-runs…` 는 기본 `/api/` location 이라 생성 몫을 쓰지 않는다.
- [실측] 서버 쪽 최장 경로는 놀이 연간이다 — 동시 호출 → 실패한 구간 다시 → 겹친 후보 다시가 각각 스트림 마감 120초라 약 6분이다. nginx 최장 대기는 연간 510초다.
- [판단] 2초 간격 · 15분 · 최근 50개.

## 고르지 않은 대안

- **SSE 스트림** — 생성 응답이 스트림이 되면 오류 계약(상태 코드 · 봉투)을 모두 다시 써야 한다.
- **202 + 비동기 작업** — 작업 테이블 · 워커가 필요하다. techspec 이 이미 거절했다.
- **브라우저 시간 추측을 그대로 두기** — 서버가 수리 호출에 들어가도 화면은 모른다.
- **기록을 요청 세션에 같이 쓰기** — 실패한 생성의 rollback 이 기록까지 지우고, 성공 전에는 다른 연결이 못 본다.
- **프롬프트 판을 칸 `rule_version` 으로 대신하기** — 연간 주제 칸은 선택 규칙 판 `"v2"` 를 받는다(`generate_yearly_plan.py`, `rules/yearly_theme_selection.py`). 소주제는 판이 어디에도 없고, 실패한 실행은 계획안이 없다.

## 결과

- 생성 경로에 DB 쓰기가 요청당 최대 5번 늘고, 기록 전용 연결 풀(최대 5, uvicorn 하나)이 생긴다.
- 화면 링의 예상 시간 기억(`localStorage` `ssample.generation-seconds`)이 없어진다.
- **시간 줄(`plan_timing`)이 두 군데 바뀐다.**
  - 연간 주제형에 `subthemes_ms` 가 생긴다(행 읽기 몇 ms).
  - 놀이 연간은 겹침 찾기와 겹친 후보를 다시 만드는 시간이 **`llm_ms` 에서 빠져 `overlap_ms` 로 옮겨 간다.** 다시 만드는 호출의 `llm_call` 줄도 `phase=overlap` 으로 찍힌다 — 작업 스레드가 루트 구간 이름을 따라간다. 놀이 연간 시간을 예전 `llm_ms` 와 비교할 때는 `llm_ms + overlap_ms` 로 본다.
  - 놀이 연간의 `set_kind("annual_play")` 를 앞으로 옮겨, 이미 있는 연간의 409 · 메모 422 도 `plan_timing kind=annual_play` 로 찍힌다(전에는 `annual_theme`).
- `prompt_versions` 에 `+trend-v1` 같은 프롬프트 태그가 보일 수 있다. 칸 `rule_version` 과 같은 종류의 신호이고, 트렌드 상태 단어가 아니다.
- **놀이 연간 구간별 n/4 · 시도별 기록 · 실패 뒤 이어 만들기는 범위 밖이다.** 그 자리를 미리 두지 않는다. 특히 「이어 만들기」는 techspec 의 「하지 않은 것」을 뒤집는 결정이라, 그 PR 이 새 ADR · techspec 수정 · 하민 합의를 같이 가져와야 한다.
- 5c 의 「배포 코드 판(SHA)」은 담지 않는다. `DEPLOY_SHA` 가 컨테이너에 없어 배포 배선이 따로 필요하다.
- 마이그레이션은 `plans` 에 FK 를 걸어 잠금을 기다릴 수 있다. 연간 주제형 생성이 `plans` 행 잠금을 쥔 채 LLM 을 기다리는 동안 배포하면 `CREATE TABLE` 이 그 뒤에 줄 서고 계획안 쓰기가 같이 막힌다. 그래서 잠금 대기를 10초로 끊는다 — 넘기면 마이그레이션 트랜잭션이 취소되고, 배포는 컨테이너를 바꾸기 전에 멈춘다(`deploy.sh` 종료 1, 지금 컨테이너가 그대로 돈다). ADR-078 자동 롤백은 교체 뒤 실패에만 돌아서 이 경우에는 돌지 않는다. 다시 배포하면 된다.
- 마이그레이션은 표를 더하기만 한다. 자동 롤백(ADR-078) 때 직전 코드가 표를 모른 채 새 스키마에서 돈다(ADR-073).
