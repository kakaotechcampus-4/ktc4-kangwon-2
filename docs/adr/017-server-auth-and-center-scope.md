# ADR-017: 인증은 서버가 하고, 인가는 원 단위까지 한다

- 2026-09-26
- 상태 — 채택
- 관련 — ADR-004(아동 실명 저장) · ADR-013(브라우저에 실명 저장 안 함)

## 맥락

`GET /api/classes/{class_id}/children` 이 아무 확인 없이 열려 있었다. `class_id` 를 1, 2, 3
으로 바꿔가며 **전체 원의 아동 실명을 다 읽을 수 있었다.**

```
curl http://15.165.19.41/api/classes/1/children
→ {"items": [{"id": 7, "name": "이승석", "code": "승석"}, ...]}
```

멘토 리뷰(PR #52) — *"실제 아동명이 내려올 수도 있어서 인가까지는 아니더라도 전역적인
인증 처리가 있으면 좋을 거 같네요!"*

계약에 「인증 P1(8주차)부터」로 적혀 있었다. **그 단계 구분은 「순서대로 만든다」를
전제했고 지금은 기능별 병렬이라 미룰 근거가 아니다** — 계획안·온보딩·일지·배포가
동시에 움직인다. ADR-003 에 주석으로 남겼다.

브라우저에는 이미 로그인 화면과 게이트가 있었지만 **전부 `localStorage` 안에서만**
돌았다. 서버는 누가 부르는지 몰랐다. 그 코드의 주석도 그렇게 적고 있었다 —
*"화면 이동을 위한 데모 전용 가드. 실제 인증은 서버에서 별도로 검증해야 한다."*

## 결정

### 1. 비밀번호는 `hashlib.scrypt` + 계정별 salt 로 저장한다

표준 라이브러리만 쓴다. 새 의존성을 붙이지 않는다.

```
scrypt   일부러 느린 키 유도 함수. GPU 로 몰아쳐도 메모리 때문에 못 늘린다
salt     계정마다 다른 무작위 값. 같은 비밀번호가 같은 값으로 저장되지 않는다
```

검증은 `hmac.compare_digest` 로 한다 — `==` 는 앞에서 몇 글자가 맞았는지에 따라 걸리는
시간이 달라져 한 글자씩 맞춰 나갈 수 있다.

### 2. 토큰은 HMAC-SHA256 서명 문자열이다. 저장하지 않는다

```
<본문>.<서명>
본문   {"sub": 7, "exp": 1790000000}   base64.  교사 id 와 만료 시각만
서명   HMAC-SHA256(SECRET_KEY, 본문)
```

**비밀번호와 다른 것을 쓰는 이유** — 비밀번호 확인은 로그인 때 한 번이라 느려도 되고,
서명 확인은 매 요청마다라 빨라야 한다.

만료는 12시간이다. 교사가 하루를 일한다 — 더 길면 잃어버린 토큰이 오래 살고, 짧으면
작업 중에 끊긴다.

**토큰을 DB 에 저장하지 않으므로 강제 무효화가 안 된다.** 로그아웃은 브라우저가 토큰을
버리는 것이고 서버는 만료까지 그 토큰을 받는다. 필요해지면 그때 저장소를 둔다.

### 3. 인증은 라우터 단위로 한 번에 건다

```python
_authenticated = [Depends(current_user)]
app.include_router(centers_router,  prefix="/api", dependencies=_authenticated)
app.include_router(children_router, prefix="/api", dependencies=_authenticated)
```

**엔드포인트마다 붙이지 않는다.** 지금 7개인데 8주차에 일지·문서가 붙으면 20개가 넘는다.
하나씩 붙이면 반드시 빠뜨리고, 빠뜨린 그 하나가 구멍이 된다.

```
auth     회원가입·로그인. 토큰을 받으러 오는 곳이라 열어 둔다
forms    업로드한 파일을 그대로 돌려줄 뿐 저장된 개인정보가 없다
나머지    아동 실명이 내려온다. 막는다
```

### 4. 왜 401 인지는 응답에 싣지 않는다

「만료됐다」와 「서명이 틀렸다」를 나눠 주면 토큰을 맞춰 보는 쪽에 힌트가 된다.
로그인도 마찬가지로 **없는 이메일과 틀린 비밀번호가 같은 응답**이다 — 나누면 어느
이메일이 가입돼 있는지 확인하는 수단이 된다.

### 5. 인가는 「자기 원」까지다. 「자기 반」은 하지 않는다

**로그인만 확인하면 반쪽이다.** 토큰이 있는 사람이 여전히 `class_id` 를 바꿔가며 남의 원
아동 명단을 읽는다. `users.center_id` 로 자기 원까지만 본다.

**「자기 반만」은 규칙을 먼저 정해야 한다** — 원장도 봐야 하고 담임이 바뀌기도 한다.
원 단위까지가 개인정보 보호의 실질이다.

`POST /api/centers` 가 그 원을 부른 교사의 것으로 등록한다. 같은 트랜잭션에서 붙인다 —
나눠 커밋하면 원은 생겼는데 주인이 없는 행이 남는다.

**한 계정은 원 하나다**(두 번째는 409). 바꾸려면 기존 원의 반·아동·계획안을 어떻게 할지
정해야 하는데 그 규칙이 아직 없다.

### 6. 남의 것은 403 이 아니라 404 다

403 은 「그건 있는데 너는 못 본다」라서 **그 id 가 존재한다는 사실을 알려준다.**
없는 id 와 남의 id 를 같은 응답으로 돌려준다.

### 7. 비밀번호를 브라우저에서 미리 해싱하지 않는다

그 해시가 곧 비밀번호가 된다 — 그대로 재전송하면 통과하므로 이득이 없다.

**예전에는 `crypto.subtle` 로 브라우저에서 해싱해 `localStorage` 에 넣고 로그인 판정에
썼다.** 그 함수는 https 나 localhost 에서만 존재해서, `http` 로 배포된 서버에서만
회원가입이 죽었다(PR #52 멘토 리뷰). 서버가 비밀번호를 들게 되면서 그 코드가 필요
없어져 통째로 지웠다.

## 근거

**아동 실명이 무방비였다** `[실측]`

`GET /api/classes/{id}/children` 에 확인이 없었다. 멘토가 PR #52 리뷰에서 짚었다.

**표준 라이브러리로 충분하다** `[실측]`

`hashlib.scrypt` 와 `hmac` 이 파이썬에 들어 있다. 비밀번호 해싱과 서명에 새 패키지를
깔 필요가 없었다.

**`crypto.subtle` 은 보안 컨텍스트에서만 존재한다** `[실측]`

`http://15.165.19.41` 에서 회원가입이
`Cannot read properties of undefined (reading 'importKey')` 로 죽었다. 로컬은
`localhost` 라 예외로 통과해서 드러나지 않았다.

**늦을수록 비싸진다** `[판단]`

지금 엔드포인트가 7개다. 8주차에 일지·문서·계획안이 붙으면 20개가 넘는다. 인증을
나중에 붙이면 그만큼 고칠 곳이 는다.

## 대안

**JWT 라이브러리(python-jose 등)를 쓴다** — 표준이고 도구가 많다. 그러나 우리가 쓸
기능은 서명뿐이고, `hmac` 으로 40줄이면 된다. 의존성이 하나 늘면 그만큼 따라다닌다.

**세션 + 쿠키** — 서버가 상태를 들고 강제 로그아웃이 된다. 그러나 서버가 세션 저장소를
들어야 하고 CSRF 처리가 따라온다. 지금 서버가 한 대라 되긴 하지만 얻는 것보다 붙는 게 많다.

**토큰을 DB 에 저장한다** — 강제 무효화가 된다. 그러나 매 요청마다 조회가 는다.
강제 로그아웃이 필요해진 적이 아직 없다.

**인증만 하고 인가는 8주차로** — 멘토가 「인가까지는 아니더라도」라고 선을 그었다.
그러나 로그인만 확인하면 토큰 가진 사람이 남의 원 아동을 그대로 읽는다. **인가가 없으면
인증이 막는 것이 거의 없다.**

## 결과

- **`.env` 에 `SECRET_KEY` 가 필수다.** 없으면 기동 시점에 죽는다. 기본값을 두지 않았다 —
  기본값이 있으면 서버에 안 넣은 채로 배포되고, 그 값은 저장소에 적혀 있으므로 누구나
  토큰을 만들 수 있다. **배포 전에 서버에서 한 번 넣어야 한다.**
- **`SECRET_KEY` 를 바꾸면 발급된 토큰이 전부 무효가 된다.** 교사가 다시 로그인한다.
- **HTTPS 가 아직 아니다.** 토큰이 평문으로 흐른다. 인증을 붙여도 같은 망에 있는 사람이
  읽을 수 있다. 다음 주에 EIP + 도메인 + 인증서를 붙인다. ADR-006 의 「Elastic IP 불가」도
  같이 고친다.
- 로그인 시도 횟수 제한이 없다. 비밀번호 최소 8자만 걸려 있다.
- 비밀번호 재설정이 없다. 잊으면 계정을 다시 만든다.
- 개발용 로그인(`test@test`)은 서버에서 토큰이 없어 401 이다. 목업 모드에서만 된다.
- 브라우저의 `Account` 기록에서 `salt`·`hash` 는 예전 기록에만 남는다. 읽을 때만 받아
  주고 새로 만들지 않는다.
