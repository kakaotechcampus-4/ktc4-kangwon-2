# ADR-025: 일일 보육일지의 근거는 「일과 기록」 테이블이다 — 행 수를 고정하지 않는다

- 2026-10-07
- 상태 — 채택
- 관련 — ADR-024(3층은 화면에서 나누고 종이에서 합친다) · api-spec §10-1 · §11 · #103 · #109

## 맥락

ADR-024 가 「일일 보육일지의 근거는 관찰 기록이 아니라 일과 기록이다」 라고 정하고, 테이블은 #103 에
맡겼다. 일과 기록을 어디에 어떤 모양으로 둘지 정해야 했다.

## 결정

1. **`routine_records` 테이블을 새로 둔다.** 반 · 날짜 · 표시 순서 · 시간 · 일과 이름 · 활동계획 ·
   활동실행. 행 하나가 종이의 일과 한 줄이다.
2. **행 수와 일과 이름을 고정하지 않는다.** 교사가 행을 더하고 이름을 적는다.
3. **일지는 이 행을 근거(`document_sources`, `source_kind = 'routine'`)로 인용한다.**
   관찰 기록 → 관찰일지와 같은 길이다. 근거 사본 · 확정 · `stale` · `refresh` 를 그대로 쓴다.
4. **사본 문자열은 `[일과 이름 시간] 활동실행` 한 줄이다.** `stale` 판정이 이 한 줄을 비교하므로
   일과 이름 · 시간 · 활동실행 중 무엇이 바뀌어도 걸린다. 활동계획 · 순서는 사실이 아니라 보지 않는다.
5. **활동실행이 빈 행은 근거가 될 수 없다.** 사실이 없는 행이다.
6. **일일 보육일지는 `child_id` 를 받지 않는다.** 반 단위다.

## 근거

- **[실측]** 실물 일지에서 같은 반도 특별활동이 있는 날 행이 하나 더 있다 (ADR-024, 원 2곳 11건).
  공식 양식 5건도 일과 이름이 비슷하지만 같지 않다 — 고정 목록을 DB 에 박으면 맞지 않는 원이 생긴다.
- **[판단]** 근거 구조를 관찰 기록과 같게 두면 확정 · 주간 근거 · `stale` · `refresh` 코드를 새로 쓰지
  않는다. 근거 종류 하나(`routine`)가 늘 뿐이다.

## 대안

- **문서 안에 고정 11칸(`document_slots`)을 둔다.** 처음 구현했다가 버렸다. 칸이 원마다 · 날마다
  달라 맞지 않고, ADR-024 의 「근거는 일과 기록」과 다르다.
- **일과를 문서 `sections` 에 직접 넣는다.** `사실 · 해석 · 지원` 제약을 풀어야 한다. ADR-024 가 막았다.
- **하루치를 JSONB 한 덩어리로 둔다.** 행 단위 수정 · 근거 인용 · `stale` 판정을 할 수 없다.

## 결과

- `routine_records` 테이블과 `document_sources.source_kind` 의 `'routine'` 이 늘었다(마이그레이션 하나).
- **관찰 기록으로 일일 보육일지를 만들던 길이 막힌다.** 프론트 문서 화면이 아직 그렇게 만든다 —
  화면을 일과 기록 입력으로 바꿔야 한다.
- 주간 보육일지(요일 × 일과)는 지금처럼 확정된 일일 보육일지를 근거로 쓴다. 종이 배치는 미정이다.
- **미정:** 같은 반 같은 날의 일일 보육일지를 하나로 막을지, 일과 기록 행을 하루 단위로 한꺼번에
  저장하는 API 가 필요한지(화면이 행마다 저장하면 요청이 많다).
