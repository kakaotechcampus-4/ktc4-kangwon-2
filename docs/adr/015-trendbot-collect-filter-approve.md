# ADR-015: 트렌드봇은 미리 모아 거르고, 쓸 때 꺼낸다

- 2026-09-23
- 상태 — 채택
- 관련 — ADR-003(P0b 정의 일부 수정) · ADR-014(생성은 RAG, 규칙은 검사)

## 맥락

ADR-003 이 트렌드봇을 P0b(7주차)로 정했지만 **어떻게 만드는지는 아무 데도 없었다.**
저장소에 남은 기록이 두 줄이다.

```
docs/structure.md:80   | `trends` | 트렌드 소재 · 승인 큐 |
docs/adr/003:26        P0b 트렌드봇 연결 — P0a 출력을 기준선으로 두고 가점만 얹는다
```

그 사이 화면(`TrendsPage`)과 프론트 경로가 먼저 생겼다. 지금 도는 방식은 이렇다.

```
교사가 새로고침 → Next 라우트 → OpenAI web_search → title·summary·idea·url 5개
```

**URL 을 LLM 이 만든다.** 프롬프트에 「확인되지 않은 URL 을 만들지 않는다」고 적혀 있지만
검사하는 코드가 없다. 교사가 누른 링크가 404 면 그걸로 끝이다.
우리 원칙이 「사실기록형은 AI 가 쓰면 위조」인데 외부 자료 링크가 정확히 그거다.

## 결정

### 1. 사실은 API 가, 문장은 AI 가

```
사실   제목 · 채널 · 날짜 · 링크 · 대출수 · 검색량      API 값 그대로.  AI 가 못 만진다
해석   "자연·생태 쪽 신간이 늘었다"                    세면 나온다
지원   "표지를 보고 고른 장면으로 역할놀이"             AI 가 쓴다
```

**AI 에게 링크를 넘기지 않는다.** 넘기지 않으면 지어낼 수도 없다.

### 2. 낱말이 아니라 「놀이」를 뽑는다

계획안 활동 칸에 들어가는 것은 명사가 아니다. 「공룡」만 있으면 교사가 놀이를 직접
짜야 하고, 그러면 트렌드봇이 일을 안 한 것이다.

```
이름       경찰과 도둑
어떻게     술래(경찰)가 도망자를 잡는다. 잡히면 감옥, 친구가 터치하면 풀려난다
필요한 것   없음. 공간만
인원·공간   6명 이상 · 바깥
```

**다섯 종류를 모은다.**

| 종류 | 주력 | 보조 |
|---|---|---|
| 놀이 | 유튜브 | 뉴스 |
| 노래·율동 | 유튜브(동요·율동 채널만) | — |
| 이야기·책 | 도서관 정보나루 | 네이버 책 |
| 만들기 | 유튜브 | 데이터랩 쇼핑인사이트 |
| 소재 | 유튜브 · 뉴스 | 데이터랩 검색어트렌드 |

**뉴스는 놀이 소스가 아니다.** 기사는 「공룡이 유행이다」까지만 알려주고 노는 법은
안 알려준다. 소재 발굴과 유행 확인에만 쓴다.

### 3. 수집은 검색이 아니라 「승인 채널 긁기」

```
search.list       1회 100 units    하루 100회가 끝
playlistItems     1회 1 units      하루 1만 회
```

어차피 승인된 채널 것만 쓴다. 검색해서 아무거나 긁어와도 검열 1단에서 다 떨어진다.
**승인 채널 20~30개의 최근 업로드를 긁는다.** 검색은 「새 채널 발굴」용으로 한 달에 한 번.

### 4. 검열 4단 — 결정론을 먼저, AI 는 떨어뜨리기만

```
1단  누가 올렸나        유튜브 madeForKids 아니면 탈락. 채널·언론사 화이트리스트
2단  금칙 대조          문자열 대조. 모델 안 씀
3단  LLM Judge         "만 3~5세에 맞나". 떨어뜨리기만 한다. 통과를 보증하지 않는다
4단  승인 소스인가      우리 팀이 승인한 곳에서 왔나
```

**1·2단이 모델 없이 먼저 돌아 대부분을 털어낸다.** 비용도 준다.

**3단이 보는 것은 제목이 아니라 놀이 서술 전체다.** 위험한 유행 놀이는 제목에 위험한
낱말이 없다. 다치는 동작(밀기·목·숨 참기·높은 곳), 따돌리는 구조, 만 3~5세가 규칙을
이해할 수 있는지를 본다.

### 5. 승인은 저장소 파일이다 — 화면을 만들지 않는다

```
월요일 새벽   Actions 가 수집 · 검열 · 놀이 서술 정리
             backend/resources/trends/2026-W39.json 을 만들고 PR 을 연다
월요일        팀원 한 명이 diff 를 본다. 이상한 줄을 지우고 merge
일요일        develop → main → 배포에 실려 나간다
```

**PR diff 가 승인 화면이다.** 새 화면 0개, 기록은 git 에 영구히 남고, 되돌리기는
revert 다. 우리는 이미 매일 PR 을 본다.

**개별 항목을 사람이 매번 보지 않는다.** 소스(채널·언론사) 단위로만 승인한다.
그래야 수백 개를 사람이 안 봐도 된다.

서비스 반영까지 최대 6일 늦는다. 유아 놀이 유행은 몇 주 단위라 감수한다.
빠듯하면 수집을 목요일로 당긴다 — `schedule` 한 줄이다.

### 6. 주 1회. 초기에만 손으로 여러 번

```
주기    월요일 새벽 (교사가 주간계획을 월·화에 쓴다)
초기    수동 실행으로 2~3번 돌려 100~200개를 시드로 쌓는다
```

**매일 돌리지 않는다.** 계획안이 월·주 단위 문서라 일 단위 수집은 주기가 안 맞고,
7일 지나도 살아있는 것이 진짜 유행이라 하루짜리 밈이 자동으로 걸러진다.
매일 AI 검열이면 토큰도 매일 나간다.

**초기 시드 200개가 검열 규칙의 실측 자료다.** 손으로 훑으면서 금칙 목록을 채운다.

### 7. 트렌드 놀이는 활동 후보 풀에 섞인다 — ADR-003 수정

```
A (채택)  트렌드 놀이가 기존 활동 풀과 나란히 후보가 된다
B (기각)  계획안은 그대로 두고 옆에 "요즘 이런 놀이가 유행이에요"만 붙인다
```

**B 는 교사가 직접 옮겨 적어야 해서 일을 안 덜어준다.**

ADR-003 의 「P0a 출력을 기준선으로 두고 가점만 얹는다」를 **이 범위에서 수정한다.**
트렌드가 계획안 내용을 바꾼다. 다만 **트렌드 항목이 하나도 없어도 기존 활동 풀만으로
계획안이 나온다** — 「부가 기능이 죽어도 본 기능은 돌아간다」는 그대로다.

**계획안에 트렌드 사용 여부를 값으로 저장한다.** 없으면 교사가 뺀 뒤에 다른 칸을
재생성했을 때 트렌드가 또 들어온다.

**[트렌드 빼기]는 생성 후에 둔다.** 교사는 만들어보고 마음에 안 들면 뺀다. 만들기
전에 묻는 것은 뭘 묻는지 모른다. 칸마다 근거(evidence)에 출처가 박혀 있어 트렌드에서
온 칸만 골라 다시 만들 수 있다. 하민의 `RegenerateYearlyPlanItem` 이 칸 단위로 돈다.

### 8. 캐릭터 이름은 그대로 쓴다

「뽀로로 놀이」면 그대로 적는다. 일반 명사로 바꾸지 않는다.
근거란에 출처가 남아 어디서 온 것인지는 추적된다.

**노래는 동요·율동 채널로 한정한다.** 성인 가요 따라부르기는 현장에서 실제로 일어나지만
계획안에 적는 것은 다른 문제다 — 가사를 API 가 주지 않아 확인할 수 없고, 저작권이 더
빡빡하고, 「왜 이 곡인가」를 교사가 원장에게 설명해야 한다. 채널 화이트리스트에서 자동으로
걸러진다. 나중에 필요하면 채널 목록에 한 줄 더하면 된다.

### 9. PDF 는 파싱하지 않는다. 사람이 분기에 한 번 넣는다

KOCCA 애니메이션 순위, i-누리 놀이 사례, 육아정책연구소 실태조사처럼 **API 가 없는
공신력 자료는 근거 보강용으로 사람이 손으로 넣는다.**

```
backend/resources/trends/reference/kocca-2026-Q3.json
```

유행을 찾는 용도가 아니다. 같은 사실이라도 근거란에 적혔을 때 무게가 다르다.

```
근거: 유튜브 조회수 500만                    원장: "그래서?"
근거: KOCCA 2026 3분기 애니메이션 인기 순위    원장: 납득
```

## 근거

**LLM 이 만든 URL 을 검사하는 코드가 없다** `[실측]`

`frontend/app/api/assistant/route.ts:66` 의 trends 프롬프트가 「확인되지 않은 URL 이나
인기 순위를 만들지 않는다」고 지시하지만, 응답을 검사하는 것은 JSON 스키마 형태뿐이다.
`url` 필드가 문자열이기만 하면 통과한다.

**한글 공공기관 PDF 는 텍스트 추출이 실패한 적이 있다** `[실측]`

`p0-planning/data/rules/safety_education_legal_v1.json` 의 `unreadable_sources` —
아동복지법 제31조 PDF 를 poppler 로 못 읽었다. Adobe-Korea1 CMap 이 없어서다.
글꼴을 파일에 넣지 않고 이름만 적어두는 문서가 많다.

**유튜브 검색은 채널 긁기보다 100배 비싸다** `[실측]`

YouTube Data API v3 의 `search.list` 는 호출당 100 units, `playlistItems.list` 는
1 unit 이다. 기본 일일 쿼터가 10,000 units 다.

**유튜브만 아동용 여부를 플랫폼이 직접 표시한다** `[실측]`

미국 COPPA 때문에 업로더가 아동용 여부를 표시해야 하고 그 값이 `status.madeForKids` 로
API 에 나온다. 다른 소스에는 이에 대응하는 값이 없다.

**도서관 대출 기록은 마케팅이 못 건드린다** `[판단]`

정보나루는 전국 도서관의 실제 대출 기록이다. 출판사가 광고로 순위를 바꿀 수 없다.
대신 신간 유행이 3~6개월 늦게 반영된다 — 유행 탐지용이 아니라 안정적인 기본 소재용이다.

**검열 근거가 아직 없다** `[판단]`

2단 금칙 목록은 지금 근거가 없다. 초기 시드 200개를 훑으면서 채우고, 어린이안전넷·
한국소비자원 자료로 뒷받침한다. 「왜 걸렀나」를 설명할 수 없으면 검열이 아니라 취향이다.

## 대안

**교사가 버튼을 누를 때 수집한다** — 기각

```
느리다        유튜브 + 뉴스 + AI 검열 = 30초 넘는다
한도가 있다    교사 100명이 각자 누르면 오전에 쿼터가 끝난다
검열이 안 된다  실시간이면 위험한 놀이가 검열을 못 거치고 교사에게 간다
```

**관리자 승인 화면을 만든다** — 기각

화면·인증·권한이 따라온다. PR diff 가 같은 일을 하고 기록까지 남긴다.

**네이버 블로그·카페도 긁는다** — 기각

협찬 글을 구분할 방법이 없다. 뉴스만 쓴다.

**소스를 더 늘린다** — 기각

지금 넷으로 다섯 종류가 다 찬다. 더 붙이면 검열할 쓰레기만 는다.

## 결과

- `backend/app/features/trends/` 를 채운다. 지금 빈 `__init__.py` 뿐이다.
- 프론트의 OpenAI `web_search` 트렌드 경로를 지운다. `GET /api/trends` 로 바꾼다.
- `TrendsPage` 의 하드코딩 자료 3개를 지운다.
- **승인 채널·언론사 목록을 사람이 먼저 짜야 한다.** 목록이 비면 수집해도 전부 1단에서
  떨어진다. 코드보다 이것이 먼저다. AI 에게 시키지 않는다 — 없는 채널을 지어낸다.
- API 계정 3개가 필요하다 — 구글 클라우드(YouTube), 네이버 개발자센터(검색+데이터랩),
  공공데이터포털(정보나루). 셋 다 무료다.
- ADR-003 의 「가점만 얹는다」에 이 ADR 을 가리키는 주석을 단다.
- `docs/structure.md` 의 「트렌드 소재 · 승인 큐」에서 승인 큐를 지운다. 큐가 아니라
  저장소 파일이다.

## PR 계획

| | 내용 | 줄 수 |
|---|---|---|
| ① | 수집 + 저장. 소스 어댑터, 채널 ID 해석 스크립트 | ~450 |
| ② | 검열 1·2단 (화이트리스트 + 금칙 YAML) | ~350 |
| ③ | 검열 3단 + 주간 Actions + 자동 PR + `GET /api/trends` | ~450 |
| ④ | 화면 연결. 하드코딩 제거. [트렌드 빼기] | ~300 |

③에서 LLM Judge 와 승인 절차가 같이 들어간다. 판정만 먼저 넣으면 AI 가 최종
결정자가 되는 기간이 생긴다.
