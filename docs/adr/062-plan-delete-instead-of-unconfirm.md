# ADR-062: 화면의 계획안 확정 취소를 없애고, 확정본은 문서 보관함에서 지운 뒤 다시 만든다

- 날짜: 2026-11-05
- 상태: 채택 (Human Decision 2026-11-05 하민)
- 대체: ADR-055 §6 「삭제 규칙(확정본 · 딸린 하위가 있으면 막음)은 바꾸지 않는다」 중 **확정본 금지**를 대체한다. ADR-055 의 `unconfirm` API 와 그 동작(§1~§5)은 그대로다 — 화면에서만 뺀다.

## 맥락

[실측] 연간(월별 주제형 · 놀이 중심형) · 월간(주제형 · 놀이 중심) · 주간 확정 화면에 「확정 취소」 버튼이 있었다(ADR-055). 확정본은 `DELETE` 가 409 `GATE_BLOCKED` 로 막았다.
하민 결정(2026-11-05): 계획안 화면의 「확정 취소」 버튼을 없앤다. 확정한 계획안을 고치고 싶으면 문서 보관함에서 지우고 다시 만든다.

## 결정

1. **화면** — 연간 · 월간 · 주간 계획안 화면 전부에서 「확정 취소」 버튼과 그 안내(투어 포함)를 없앤다. 확정 확인 문구는 「고치려면 문서 보관함에서 지우고 다시 만들어요」로 바꾼다. 보육일지 · 관찰일지 문서의 확정 취소는 계획안이 아니라 그대로다.
2. **문서 보관함** — 계획안 미리보기에 「삭제」를 둔다(상태 무관, 확정본도). 지우기 전에 페이지 안 확인 상자 「이 계획안을 지울까요? 되돌릴 수 없어요.」를 거친다. 승인받아 보기만 하는 남의 반 미리보기에는 없다(ADR-059). 놀이 중심 월간도 보관함 월간 목록에 나온다 — 안 나오면 놀이 연간을 지울 길이 없다.
3. **서버 `DELETE`** — 연간 · 주제형 월간 · 놀이 월간 · 주간 모두 상태를 보지 않는다(확정본도 `204`).
   - 하위가 있으면 막는다(409 `IN_USE`, 한국어 문구). 연간 → 그 반 · 학년도 월간(기존). **월간 → 그 월간을 부모(`parent_lineage.parent_plan_id`)로 든 주간(새로 넣음)** — 전에는 확정 월간만 주간을 가질 수 있어 확정본 금지가 이걸 대신 막았다.
   - 경쟁: 부모 `DELETE` 는 부모 행을 `FOR UPDATE` 로 잠그고 하위를 본다. 하위 생성(월간 · 놀이 월간 · 주간)은 LLM 뒤 저장 단계 첫머리에 부모 행을 `FOR SHARE` 로 다시 보고, 없거나 CONFIRMED 가 아니면 409 `GATE_BLOCKED` 다. 그래서 둘이 겹쳐도 부모 없는 하위가 저장되지 않는다.
   - 이력 · 근거는 `plans.body` 안에 있고 `plans` 를 가리키는 FK 가 없어 행과 함께 사라진다 — 고아가 남지 않는다.
4. **`unconfirm` API 는 남긴다** (`POST .../{id}/unconfirm`). 화면은 부르지 않는다. 지울지는 다음 결정 때 본다.

## 근거

- 하민 결정(2026-11-05): 「확정 취소」 버튼을 없애고, 확정본은 문서 보관함에서 지우고 다시 만든다.
- 하위 조회는 부모의 스냅샷을 읽지만 부모 id 로 상세 링크를 만든다(`parent.monthly_plan_id`). 부모만 지우면 하위가 주인 없이 남으므로 하위부터 지우게 한다.

## 결과

- 「확정 = 최종」 의미가 ADR-055 보다 다시 단단해진다 — 확정본은 고칠 수 없고, 지우고 새로 만드는 것만 된다. 지운 계획안의 이력은 남지 않는다.
- 하위를 가진 계획안은 아래부터 지워야 한다(주간 → 월간 → 연간). 보관함은 409 `IN_USE` 에 「이 계획안으로 만든 월간(주간)계획안이 있어요. 먼저 지워주세요.」를 띄운다.
- `test-reset`(시험용)은 그대로다.
