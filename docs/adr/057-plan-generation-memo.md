# ADR-057: 계획안을 만들기 전에 교사가 「요청 사항」을 적는다

- 날짜: 2026-11-03
- 상태: 사용자 방향 확정 (2026-11-03 하민). 1차(글 요청 · 반영 못한 요청) 로컬 구현, 2차(안전교육 개수 · 주차) 미구현
- 보완: api-spec §9 「받지 않는 것: 자유 메모」를 이 ADR 의 `memo` 로 바꾼다. CLAUDE.md §5(Rule/LLM 경계)는 그대로다.

## 맥락

[실측] 연간 · 월간 · 주간 생성 요청은 반 · 달 · 주만 받는다. 교사가 「이번 달엔 숲 놀이를 넣어 달라」, 「재난 안전교육을 세 번 이상 넣어 달라」처럼
칸 내용에 바라는 점을 말할 길이 없다. 하민 요청(11-03): 「모든 칸에 사용자가 원하는 요구사항이 들어갈 수 있게」.

부딪히는 지점: CLAUDE.md §5 는 LLM 이 배치 · 개수 · 법정 기준을 정하지 못하게 한다. 메모를 LLM 에 그대로 맡기면 「안전교육 세 번」을 LLM 이 배치하게 된다.

## 결정

1. **생성 다섯 경로가 `memo` 를 받는다.** 연간(월별 주제형 · 놀이 프로젝트형) · 월간(v1 · 놀이 중심) · 주간.
   - 0~300자. 앞뒤 공백을 뗀다. 빈 값 = 메모 없음 — LLM 요청 · 결과 · Golden 이 메모 이전과 같다.
   - 메모는 생성 화면마다 따로 받는다. 연간 메모가 월간으로 내려가지 않는다.
   - 메모는 계획안 본문에 `teacher_memo` 로 남고, 상세 응답의 `memo` 로 돌아온다.
2. **두 층으로 나눈다.**
   - **1층 — 글 요청(이번 구현).** LLM 이 쓰는 칸에 메모를 데이터로 넘긴다(지시가 아니다 — FR-605).
     LLM 은 Rule 이 허용한 후보 · 근거 · 칸 안에서만 반영한다. 반영한 칸 주소를 `memo_applied` 로 답한다.
   - **2층 — 개수 · 주차 요청(다음 구현).** 「재난 안전교육 3회 이상」, 「2주차에 교통안전」 같은 요청은 LLM 이 정해진 모양
     (`safety_requests: [{slot, weeks, min_weeks}]`)으로 뽑기만 하고, **배치는 Rule 이 한다.** 대상은 월간 v1 · 놀이 중심 월간의 안전교육.
     요청 개수만큼 후보 문장을 더 만들고(주마다 다른 공식 내용 항목, 항목 수가 상한), 못 채운 개수는 아래 3 으로 알린다.
3. **반영하지 못한 요청은 숨기지 않는다.** LLM 이 `memo_skipped: [{summary ≤80자, reason}]` 로 답하고 응답 `memo_notices` 로 보인다. 생성을 막지 않는다.
   - `OUT_OF_RANGE` — 승인 후보 · 근거 밖을 요구했다.
   - `RULE_CONFLICT` — 안전교육 배치 · 법정 기준 · 칸 구조와 부딪힌다.
   - `FIXED_CELL` — Rule 이 복사하는 칸이다(연간 · 월간 v1 의 주제, 주간의 주제 · 안전교육).
4. **메모를 반영한 칸은 Evidence 하나를 더 갖는다.** `CLASSROOM_PROFILE` / `teacher_memo` / 「요청 사항」.
   새 Source Type 을 만들지 않는다. 칸별 근거 종류 검사는 이 표시 하나만 예외로 받는다. Generation Method 는 바꾸지 않는다.
5. **아이 이름은 가명으로 나간다**(api-spec 공통 규칙). 메모에 반 아이 이름이 있으면 메모 글만 `shared/childCode` 로 바꿔 보내고 답을 되돌린다.
   바꿀 수 없으면(두 아이가 같은 이름 등) 또는 보낼 요청에 그 이름이 남아 있으면 LLM 을 부르지 않고 422 `VALUE_INVALID` `["memo"]`.
6. 고정되는 칸
   - 연간 월별 주제형: 주제(theme_id)는 Rule 이 고른다. 메모는 소주제에만 닿고, 반영한 달의 주제 칸에 표시가 붙는다.
   - 주간 안전교육은 월간에서 복사한다. 주간 메모의 안전교육 요청은 `FIXED_CELL` 로 알린다.

## 근거

- 하민 결정(2026-11-03): 「두 층으로」, 2층 범위 「안전교육 개수 + 주차 지정」, 「주마다 다른 문장」, 「월간 복사 유지」.
- 메모 글만 가명으로 바꾸는 까닭: 요청 전체를 바꾸면 누리과정 문장 속 「하나씩」 같은 낱말까지 이름으로 보고 바꾼다.

## 대안

- 메모를 LLM 에 맡겨 배치까지 — CLAUDE.md §5 위반. 채택하지 않았다.
- 개수 요청을 정해진 입력 칸(드롭다운)으로 — 교사가 말로 적는 편이 쉽다는 하민 방향과 다르다. 2층이 같은 결과를 Rule 로 낸다.

## 결과

- 메모가 있는 생성은 prompt version 뒤에 `+teacher-memo-v1` 이 붙어 생성 방식(`rule_version`)에서 구분된다.
- LLM 이 반영했다고 답해도 내용 검사는 기존 검사 그대로다. 메모 때문에 검사가 느슨해지지 않는다.
