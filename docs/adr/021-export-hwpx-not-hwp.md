# ADR-021: 내보내기는 hwpx 로 한다 — hwp 를 만들지 않고 변환도 하지 않는다

- 2026-09-30
- 상태 — 채택
- 관련 — ADR-004(아동 실명) · ADR-013(브라우저 저장) · api-spec §9

## 맥락

교사가 만든 계획안을 원 밖으로 내보내야 한다. 제출용이고, 현장이 쓰는 형식은 `.hwp` 다 —
우리가 모은 실물 계획안이 전부 `.hwp` 였다.

`.hwp` 는 한글 5.0 바이너리다. 읽기는 `pyhwp`(hwp5html)로 되지만 **쓰기 도구가 없다.**
직접 만들려면 OLE2 복합파일 · 태그 레코드 · DocInfo 테이블을 다 조립해야 하고, 공개 명세가
약 200쪽이다. 틀리면 한글이 「손상된 파일입니다」 한 줄만 낸다 — 바이너리라 어디가 틀렸는지
볼 수 없다.

## 결정

1. **hwpx 로 내보낸다.** zip + XML(KS X 6101)이라 우리가 만들 수 있고, 한글 2010 이상에서
   열린다. 교사가 한글에서 「다른 이름으로 저장 → .hwp」 하면 hwp 가 된다 — 클릭 한 번이다.
2. **표를 새로 그리지 않는다.** 한글이 저장한 양식 파일을 두고 칸의 글자만 바꿔 다시
   압축한다. `header.xml`(글꼴 · 문단 모양 · 테두리)을 손으로 쓰면 한글이 안 여는 경로가
   수십 개 생긴다.
3. **변환 기능을 서버에 두지 않는다.** 시중 hwpx → hwp 변환은 파일을 남의 서버로 보낸다.
4. **확정본만 내보낸다.** 내보낸 파일은 제출 문서다.
5. **출처를 싣지 않는다.** `evidence` · `generation` 은 화면의 값이다.

## 근거

- **[실측]** 우리가 모은 어린이집 월간계획안이 전부 `.hwp` 다(충청북도 3건 확인).
  그래도 `.hwp` 쓰기는 선택지가 아니다 — 만들 도구가 없다.
- **[실측]** hwpx 압축을 풀면 `mimetype` · `version.xml` · `Contents/header.xml` ·
  `Contents/section0.xml` 이다. 표는 `section0.xml` 에 있고 칸마다 `hp:cellAddr` 로
  (행, 열) 주소가 적혀 있다 — 순서로 세면 병합된 칸에서 열이 밀린다.
- **변환을 안 하는 이유가 편의가 아니라 개인정보다.** 계획안에는 반 이름과 담임 이름이,
  일지에는 아동 실명이 들어간다. ADR-004 가 LLM 프롬프트 한 줄에도 실명을 못 싣게 해뒀는데
  문서를 통째로 외부 변환 서비스에 올리면 그 원칙이 그 자리에서 무너진다.
  **기능을 안 만드는 것이 더 안전한 경우다.**
- 교사가 치르는 값은 클릭 한 번이다. 우리가 치를 값은 며칠과 디버깅 불가다.

## 결과

- 교사가 hwpx 를 받아 한글에서 열고, 필요하면 `.hwp` 로 저장한다. 화면에 그 한 줄을 적는다.
- 파일럿에서 교사가 「hwp 아니면 불편하다」고 실제로 말하면 그때 다시 본다.
  말이 안 나오면 만들지 않는다.
- 원이 올린 양식(§8)으로 내보내는 경로는 `fill_table` 에 양식 파일을 넘기는 구조라
  양식만 바꾸면 된다. 원 양식이 hwpx 면 그 서식 그대로 나간다.

## 안 한 것

- **`.hwp` 쓰기** — 명세 200쪽, 디버깅 수단 없음.
- **서버 쪽 변환** — 개인정보. 위 결정 3.
- **PDF** — 대비책으로만 둔다. 수정이 안 되지만 제출은 된다. hwpx 가 막히면 두 시간이면 된다.
- **월간 내보내기** — 월간 API 와 양식이 같이 생길 때.
