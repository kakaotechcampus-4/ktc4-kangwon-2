# ADR-065: 놀이 월간의 활동은 AI 후보 8개 중 교사가 5개를 고르고, 기본생활습관은 주 사이에서 옮긴다

- 상태 — 채택 (Human Decision 2026-11-06(하민) — 「함께하는 활동, 예상 자유놀이도 8개씩으로 생성 해줘서 넣게 했으면 좋겠거든? … 놀이중심 연간 계획안의 AI후보 고르는 칸처럼」 → 고르는 개수 「정확히 5개」 · 놀이 주제 · 주제 선정 이유는 그대로 · 「기본 생활 습관도 이동 가능하게 안전교육도 끌어서 넣을 수 있게끔 … 11월 1주, 2주 이 칸도 선택 할 수 있게」 → 「어 해줘」)
- 관련 — ADR-042 · ADR-048(놀이 프로젝트형 연간 후보 고르기) · ADR-046 · ADR-047(놀이 월간) · ADR-060(요청 메모) · api-spec §9-7

## 맥락

놀이 중심 월간은 LLM 이 함께 하는 활동 · 유아 예상 자유놀이를 5개씩 써서 그대로 문서에 넣었다. 교사는 고를 수 없고
지우거나 직접 써야 했다. 놀이 프로젝트형 연간은 이미 AI 후보 중 교사가 고르는 방식이다.

## 결정

1. **새 양식 판 `play-monthly-layout-v0.3.0`.** LLM 은 두 목록에 후보를 **8개씩** 쓴다(한 번의 요청 · 수리 최대 1번은 그대로).
   그 밖의 칸 — 놀이 주제 · 주제 선정 이유 · 안전교육 · 훈련 후보 · 생활 문장 고르기 — 는 바뀌지 않는다.
2. **처음에는 문서에 활동이 없다.** 후보는 모두 `activity_pool` 에서 시작하고, 교사가 `POST .../activities/{item_id}/pick` 으로
   목록 끝에 넣는다. 한 목록은 **최대 5행**이고 **확정은 목록마다 정확히 5행**이다(교사가 직접 더한 행도 센다).
   초안은 0~5행으로 저장된다 — 연간 고르기처럼 중간에 멈췄다가 돌아올 수 있다. 화면은 연간 「놀이 고르기」 3패널 판
   (`PlayPickBoard`)을 그대로 쓰고, 5행이 안 된 목록이 있으면 그 판부터 연다(screen-spec S-PM1).
3. **AI 후보를 빼면 후보 목록으로 돌아간다**(생성 순서 자리로). 교사가 고친 글 · 연결 · 이력도 함께 돌아가 다시 넣으면 그대로다.
   교사가 직접 더한 행을 빼면 지금처럼 `removed_activities` 에 남는다. 후보 목록의 행은 고치지 않는다(연간과 같다).
   `GET ./audit` 은 후보 목록에 있는 행의 칸 이벤트도 싣는다(활성 칸 → 지운 행 → 후보 목록 순).
4. **넣기 · 빼기는 계획안 단위 `ARRANGEMENT_CHANGED`**(scope = 목록, 앞뒤 문서 행 id) — 행 더하기 · 빼기와 같은 이벤트다.
5. **기본생활습관은 주 사이에서 옮긴다.** `PUT .../habits/order` 가 습관 칸 전부를 새 주 순서로 받는다(화면은 두 주를 맞바꾼다).
   칸은 id · `semantic_key` · 근거 · 이력을 가진 채로 통째로 옮기고, `semantic_key`(`basic_habits.{처음 주}`)는 안정 주소로 남는다.
   `ARRANGEMENT_CHANGED`(scope = `habits`). 같은 순서면 무변경이다.
6. **안전교육 후보 끌어 넣기 · 주 고르기는 화면만 바뀐다** — 저장은 기존 `PUT .../safety-weeks/{week_id}` 다.
7. **옛 계획안(layout v0.2.0)은 그대로다.** `activity_pick` 은 null, 후보 목록은 비고, 확정 조건도 「목록마다 1행 이상」 그대로다.
   저장은 JSONB 라 마이그레이션이 없다(없는 필드는 기본값).

## 근거

- 무엇을 문서에 넣을지는 교사가 고르고, LLM 은 Rule 이 준 범위(개수 · 누리과정 id · 부모 놀이) 안에서 후보 문장만 쓴다(CLAUDE.md §5).
- 연간 고르기와 같은 감각 · 같은 「정확히 N개」 확정 규칙이라 새 규칙이 늘지 않는다.
- 후보가 10개에서 16개로 늘어 출력 토큰 · 생성 시간이 늘어난다. 측정해 로딩 화면 안내를 맞춘다.

## 공개 오류(제안)

- 목록이 이미 5행인데 넣기 · 행 더하기 → 422 `VALIDATION_FAILED` 「이미 다 골랐어요. 하나를 빼고 넣어 주세요.」 `["item_id"]`
- 후보 목록에 없는 id → 404 `NOT_FOUND` 「그 후보를 찾을 수 없습니다.」
- 습관 순서가 빠짐 · 중복 · 모르는 id → 422 `["item_ids"]`
