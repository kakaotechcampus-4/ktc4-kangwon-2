# ADR-003: P0 를 P0a · P0b 로 쪼갠다

- 2026-09-07
- 상태 — 채택

## 맥락

P0(계획안 계열)에 트렌드봇이 들어 있었다. AI 담당이 이렇게 제안했다.

> 날씨·기후·트렌드봇 같이 생성에 변동을 주는 기능은 나중에 두고,
> 기본적인 레퍼런스와 정부 지침으로 초안 생성을 먼저 하자.

정확한 지적이었다. 다만 트렌드봇을 P1 로 밀면 시험 2주(9~10주차)를 넘겨
파일럿에 못 들어간다. 김수민이 5주차에 소스를 검증하는데 그 결과가
8주차 이후에 쓰이면 3주를 방치한다.

## 결정

```
P0a   결정론적 초안 생성      5~6주차
      규칙 + 템플릿만.  같은 입력 → 같은 출력
P0b   트렌드봇 연결          7주차
      P0a 출력을 기준선으로 두고 가점만 얹는다
P1    날씨(F7) · 보육일지 · 관찰일지 · 로그인   8주차~
```

## 근거

**변동이 섞이면 품질을 측정할 수 없다** `[판단]`

6주차에 초안이 이상할 때 규칙 문제인지 트렌드 소재 문제인지 구분이 안 된다.
그리고 외부 API 3개가 붙으면 실패 모드가 3개 늘어난다.

**P0a 가 결정론적이라 golden set 이 성립한다**

입력과 기대 출력을 3세트 고정하고 (폴더는 6주차에 필요해진 사람이 만든다),
7주차에 트렌드봇을 붙인 뒤 다시 돌려 결과가 안 바뀌었는지 확인한다.
없으면 트렌드봇이 규칙 엔진을 망가뜨렸는지 알 수 없다.

## 대안

**트렌드봇을 P1 로** — AI 담당 원안. 파일럿에 못 들어간다.

**트렌드봇을 P0 안에 그대로** — 6주차에 변동 요소가 섞여 디버깅이 안 된다.

## 결과

- 이 분할이 「부가 기능이 죽어도 본 기능은 돌아간다」를 **코드 구조로 강제한다.**
  P0a 가 먼저 완성돼 배포된 상태라 트렌드봇을 필수 의존으로 넣을 수가 없다.
- golden set 을 6주차 말에 반드시 고정한다.
- 9/27 1차 배포(카테캠 스프린트 1 종료)에 P0a + P0b 가 다 들어간다.
