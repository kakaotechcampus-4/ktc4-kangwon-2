# ADR-020: 등록 양식은 파싱 결과만 원 단위로 저장한다

- 2026-09-29
- 상태 — 채택
- 관련 — ADR-009(표준 키) · ADR-017(인증 · 원 단위 인가)

## 맥락

`forms` 는 지금까지 저장하지 않았다. `POST /api/forms/parse` 가 hwp · hwpx 를 받아 표 구조와
라벨을 돌려주고 끝난다. `structure.md` 가 forms 를 「DB 미사용」으로 적었고, ADR-009 와
ADR-017 이 그 전제를 근거로 썼다 — 017 은 「저장된 개인정보가 없다」며 forms 라우터를 통째로 열었다.

계약 §8 은 원이 양식을 **한 번 등록하면 계속 쓰는** 구조를 정해 두었다. §4 의 연간 생성이
`form_id` 를 받는다. 이번 주에 등록 · 목록 · 삭제를 만든다. 무엇을 · 누구에게 붙여 저장할지가 남았다.

## 결정

1. **`forms` 테이블을 둔다. 원(`centers`)에 귀속된다.** 만료가 없다 — 원의 자산이다.
2. **파싱 결과만 저장한다** — `tables` · `labels` · `label_map`(JSONB), `filename`, `name`.
   **원본 파일은 남기지 않는다.** 표가 하나도 없는 양식은 등록하지 않는다(422) — 쓸 곳이 없다.
3. **`name` 은 지금 `filename` 으로 채운다.** 이름 입력은 받지 않는다. 컬럼은 처음부터 둔다.
4. **수정이 없다. 삭제 후 재등록이다.** 같은 파일을 다시 올려도 막지 않는다.
5. **삭제를 막지 않는다.** 이번 주 `plans.form_id` 에 FK 가 없다.
   지워진 `form_id` 를 계획안이 어떻게 다루는지는 plans 가 정한다.
6. **`/api/forms/parse` 만 토큰 없이 연다.** 등록 · 목록 · 삭제는 `main.py` 에서 라우터 단위로
   인증을 걸고, 원 단위 인가를 거친다. 남의 원 것은 404 다(ADR-017 결정 그대로).

## 근거

- **[실측]** 저장할 모양이 이미 있다 — `ParseResponse { filename, tables, labels, label_map }`
  (`backend/app/features/forms/schemas.py`). 새로 설계할 것이 원 귀속 · 이름 · 시각뿐이다.
- **[실측]** ADR-009 가 다운스트림에 넘기기로 한 것은 `label_map` 의 표준 키다 — 파싱 결과다.
  `backend/app` · `p0-planning/src` 에 원본 hwp 바이트를 다시 읽는 코드가 없다.
- **[판단]** 원본을 남기려면 둘 곳(DB bytes · 서버 디스크 · 객체 저장소)과 백업 · 삭제 방식을
  먼저 정해야 한다. 쓰는 곳이 생기기 전에 정하면 추측이다.
- **[판단]** 이름 입력은 FE 화면(`Template.name`)에 자리가 있지만 서버 연결이 아직이다.
  컬럼을 먼저 두면 입력을 열 때 마이그레이션이 필요 없다.
- **[판단]** 저장하는 순간 「개인정보가 없다」는 ADR-017 의 공개 근거가 사라진다. 양식에 원 이름 ·
  교사 이름이 적혀 있을 수 있고, 무엇보다 남의 원 자산을 읽고 지울 수 있게 된다.

## 대안

**원본 파일도 저장한다** — 「원이 올린 hwpx 양식을 그대로 채워 내보내기」(수린)에 원본이 필요하다.
그러나 그 기능이 이번 주에 붙는지 확인 전이고, 저장 위치가 정해지지 않았다.
**보류 — 수린 확인 대기.** 붙게 되면 저장 위치를 정한 뒤 더한다. 이미 저장한 파싱 결과와 API 응답은 그대로다.

**저장하지 않고 매번 parse 한다** — 테이블이 필요 없다. 그러나 §4 가 `form_id` 를 받을 곳이 없고,
교사가 계획안을 만들 때마다 양식을 다시 올린다. 계약 §8 과 어긋난다.

**반(`classes`) 단위로 귀속한다** — 양식은 원 전체가 같이 쓰는 것이 보통이다. 반마다 따로 올리게 된다.

**중복 업로드를 막는다** — 무엇이 「같은 양식」인지(파일명 · 내용 해시) 기준을 정해야 한다.
지우기가 있으니 막을 이유가 약하다.

## 결과

- `structure.md` 의 forms 행이 「DB 미사용」에서 바뀐다. ADR-009 의 결정(표준 키)은 그대로다.
- ADR-017 의 「forms 는 연다」가 「`/forms/parse` 만 연다」로 좁아진다. forms 라우터가 둘로 나뉜다.
- **원본이 없으므로 hwpx 그대로 채우기는 지금 등록된 양식으로 못 한다.** 그 기능이 붙으면
  그 뒤에 등록한 양식부터 된다 — 이전 양식은 원이 다시 올린다.
- 삭제된 양식을 가리키는 `plans.form_id` 가 생길 수 있다. FK 를 걸 때 `ON DELETE` 를 정한다.
- 파일 크기 상한이 parse 와 마찬가지로 없다. 따로 정한다.
