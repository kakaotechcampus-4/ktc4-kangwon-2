# ADR-038: 반 연령은 범위로 저장하고 Core 에는 그 범위의 연령 집합을 넘긴다 — 「만 N세」로 쓰고, 떨어진 조합은 아직 지원하지 않는다

- 2026-10-19
- 상태 — 채택 (PM-06 C, ADR-030)
- 보충 — ADR-010 (`classes.age_min` · `age_max`)

## 맥락

혼합반(두 연령 이상이 한 반)은 실측 39% 다. 연령을 표현하는 방식이 문서마다 달랐다(K-18).

| 방식 | 쓰는 곳 | 만 3세 + 만 5세 를 고르면 |
|---|---|---|
| 범위 | ADR-010 `classes.age_min` · `age_max`, FR-104, api-spec §2, screen-spec S2 | 3 ~ 5 로 저장된다 — 만 4세가 들어간다 |
| 집합 | 개인 P0 문서(OD-Y03 · OD-N02) | {3, 5} 그대로 |
| 배열 | FE 문서 일부(`selected_ages`) | [3, 5] |

명칭도 갈렸다. api-spec 「공통」은 「학년도 기준 연 나이, 만 나이 아님」, 화면 체크박스와 개인 문서는 「만 3세」였다.

## 결정

1. **DB 는 범위다.** `classes.age_min` · `age_max`, `CHECK (age_min <= age_max)`. 바꾸지 않는다.
2. **Core 에는 범위에서 만든 연령 집합을 넘긴다.** `{age_min, …, age_max}` — 예: 3 ~ 4 → {3, 4}, 4 ~ 5 → {4, 5}, 3 ~ 5 → {3, 4, 5}.
   Core 의 「Theme 후보는 반의 모든 연령을 지원해야 한다」 같은 검사는 이 집합으로 한다. 변환은 서버 한 곳에서만 한다.
3. **명칭은 「만 N세」로 통일한다.** 화면과 문서에 「만」을 붙인다 — 만 3세 · 만 4세 · 만 5세 · 만 3~4세 · 만 4~5세 · 만 3~5세.
   **값 `3 · 4 · 5` 는 반 연령(보육 현장의 「만 N세반」)이다.** 생년월일로 매일 계산하는 나이가 아니다. 이 결정은 명칭을 바꾸고,
   연령을 계산하는 규칙을 바꾸지 않는다.
4. **떨어진 조합(만 3세 + 만 5세, 만 4세 없음)은 P0 에서 지원하지 않는다.** 그 제한을 화면과 문서에 적는다.
   - 지금 화면에서 그 조합을 고르면 범위 3 ~ 5 로 저장되고 「만 3~5세반」으로 보인다. 만 4세가 포함된다는 사실을 교사가 알 수 있어야 한다.
   - 안내 방식(경고 문구 · 선택 막기 등)은 화면 담당이 정한다.
5. **다시 정하는 조건.** 수집 자료에서 떨어진 조합의 반이 확인되면 **집합 모델로 바꾸는 방향**으로 PM 과 다시 정한다. 그때는 DB ·
   API · migration 이 함께 바뀐다.
6. **반 연령과 활동 연령은 다른 개념이다.** 반은 범위, 활동(Activity Catalog `supported_ages`)은 점의 집합이다(강강술래 [3, 5] 등).
   두 값을 같은 규칙으로 읽지 않는다.

## 근거

- **[출처]** PM-06 = C, 명칭 「만」 통일, 떨어진 조합 우선 미지원 · 제한 명시, 「수집 자료에 있다면 집합으로」(2026-10-19, ADR-030).
- **[실측]** develop `backend/app/features/plans/router.py` — 연간 생성이 `frozenset(range(klass.age_min, klass.age_max + 1))` 를 Core 에
  넘긴다. 월간은 부모 연간의 연령 집합을 그대로 쓴다. 이 결정은 지금 코드와 같다.
- **[실측]** 떨어진 조합 자료 확인(2026-10-19):
  - 주간 Reference 126개 · 같은 기관 연간 12개의 반 표기 — **찾지 못했다.** 「만 3~5세」는 모두 연속 범위였다. 다만 반 구성 연령까지 적은
    자료가 없어, 그 반에 실제로 만 4세가 있는지는 확인할 수 없다.
  - 파일명 「만3세,만5세」 월간 7개 — 본문이 3세반 계획 + 4·5세 혼합반 계획(활동을 「(4세) / (5세)」로 나눔)이다. 한 반이 아니다.
  - 기존 실측(screen-spec S2): 계획안 369건 중 한 반이 떨어진 연령을 갖는 경우 0건.
  - **자료에 없다는 것이지 그런 반이 없다는 확인은 아니다.**

## 대안

- **(A) 범위를 공식으로 하고 떨어진 조합 미지원을 명시한다.** C 와 저장은 같다. C 는 Core 쪽 집합 변환 규칙까지 문서로 고정한다.
- **(B) 집합을 공식으로 한다.** DB · API · migration 이 바뀐다. 지금 근거(떨어진 조합 0건)로는 비용이 크다 — 위 「다시 정하는 조건」에서 다시 본다.

## 결과

- api-spec 「공통」의 「연 나이, 만 나이 아님」을 「만 N세(반 연령)」로 고친다. screen-spec S2 · 요구사항 용어 · `p0-planning/CLAUDE.md` ·
  `docs/schema.md` 불변 규칙 6 을 같은 뜻으로 맞춘다.
- `frontend/msw/README.md` 의 「반 연령은 `selected_ages` 배열로 보낸다」는 낡은 문장이다 — FE 는 이미 `age_min` · `age_max` 를 보낸다
  (`frontend/lib/api/age-adapter.ts`). 문장을 고친다.
- 떨어진 조합을 화면에서 안내하는 구현은 화면 작업(후속)이다. 이 ADR 은 코드를 바꾸지 않는다.
