# ADR-055: 확정한 계획안은 교사가 확정을 풀 수 있다

- 날짜: 2026-11-01
- 상태: 채택 (2026-11-01 하민, 서버 성진 · 화면 승석 동의)
- 대체: ADR-030 PM-03 「P0 계획안에는 확정 취소가 없다」를 대체한다. ADR-035 §2(확정 재호출 멱등)는 그대로이고, 확정을 풀었다가 다시 확정하면 새 확정 시각을 쓴다.

## 맥락

[실측] 확정한 계획안은 고칠 수도(409 `ALREADY_CONFIRMED`) 지울 수도 없다. 시험 중에는 `test-reset`(시험용, 운영에서 꺼짐)으로만 빠져나왔다.
화면 개편(2026-11-01 디자인 넘김)에서 확정 후 다시 고치는 길을 요청했다. 확정은 교사가 명시적으로 하는 행위이고, 같은 교사가 명시적으로 풀 수도 있어야 한다.

## 결정

1. **연간(월별 주제형 · 놀이 중심형) · 월간(v1/v2 · 놀이 중심) · 주간 모두 `POST .../{id}/unconfirm`으로 CONFIRMED → DRAFT.**
   - 본문은 그 종류의 confirm과 같다.
   - 응답은 그 종류의 상세다.
2. **값 · 근거 · 생성 방식 · 기존 이력은 그대로 둔다.**
   - 이력에 plan 단위 `UNCONFIRMED` 이벤트(누가 · 언제)를 더한다.
   - 상세의 `confirmed_at`은 null이 되고, 다시 확정하면 새 시각이다.
3. **이미 DRAFT면 200을 돌려주고 아무것도 바꾸지 않는다**(이벤트 없음, revision 그대로). revision이 있는 종류는 확정 취소 때 revision을 1 올린다.
4. **하위 계획이 있어도 풀 수 있다.**
   - 하위는 부모 값의 스냅샷(`parent_lineage`)을 그대로 가진다.
   - 하위 상세의 `parent_changed`는 부모가 지금 CONFIRMED가 아니거나 부모 확정 시각이 스냅샷과 다르면 true다. 화면은 안내 한 줄만 띄우고 막지 않는다.
5. **새 하위 생성 게이트는 그대로다.** 부모가 CONFIRMED여야 한다. 확정을 푼 연간으로는 다시 확정할 때까지 새 월간을 만들 수 없다.
6. 삭제 규칙(확정본 · 딸린 하위가 있으면 막음)과 `test-reset`(시험용)은 바꾸지 않는다.

## 근거

- 하위 조회는 부모 행이 아니라 스냅샷을 읽으므로, 부모 상태가 바뀌어도 깨지지 않는다(`monthly_router.py` · `weekly_router.py`의 `parent_lineage`).
- 하민 결정(2026-11-01): 「확정한 이후에 풀 수 있게 해주는 것이 맞다. 명시적으로 확정한다는 것이다. 기존 규칙을 바꾸는 것이 맞다(합의된 내용).」 하위가 있어도 풀 수 있게 한다.

## 대안

- 하위가 있으면 막기 — 상하위 불일치를 없애지만, 월간을 만든 뒤 연간을 고칠 수 없게 된다. 하민이 채택하지 않았다.
- 새 버전 만들기(확정본은 그대로 두고 사본 편집) — 버전 정책이 아직 없어 이번 범위가 아니다.

## 결과

- 「확정 = 최종 제출」 의미가 약해진다. 확정은 제출 · 발송을 하지 않는다는 기존 원칙은 그대로다.
- 이력에서 확정 · 확정 취소를 모두 볼 수 있어야 하므로 화면 이력 표시가 `UNCONFIRMED`를 받는다.
