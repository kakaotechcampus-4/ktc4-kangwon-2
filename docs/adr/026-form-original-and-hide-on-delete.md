# ADR-026: 등록 양식의 원본을 DB 에 남기고, 계획안이 걸린 양식은 숨긴다

- 2026-10-08
- 상태 — 채택
- 관련 — ADR-020(결정 2 · 5 대체) · ADR-021 · #89 · #108

## 맥락

파싱 결과만 남겨서는 수린의 원 서식 내보내기 · 승석의 양식 커스텀에 원본을 줄 수 없다.
계획안은 양식을 복사하지 않고 `form_id` 만 든다. #89 가 FK 를 붙였고, #108 은 삭제 거부를
임시로 `409 IN_USE` 로 돌렸다. #102 의 원본 저장 · 숨김 삭제를 구현하면서 보관 방식을 정한다.

## 결정

1. **원본은 `forms.content` 에 업로드한 바이트 그대로 남긴다.** nullable `LargeBinary`,
   `deferred=True` 다. 목록 · `find_own_form` 은 원본을 읽지 않고 어떤 응답에도 싣지 않는다.
   `FormResponse` 는 그대로다. 기본값 · 과거 행 채우기를 하지 않는다.
2. **앱 크기 제한을 더하지 않는다.** nginx `client_max_body_size 10m` 이 먼저 큰 요청을 거부한다.
3. **숨김은 nullable `forms.hidden_at` 이다.** `DateTime(timezone=True)`, NULL 이면 보인다.
4. **삭제 · commit 을 먼저 시도한다.** `fk_plans_form_id_forms` 의 `IntegrityError` 면 먼저
   rollback 하고 UTC-aware 현재 시각으로 `hidden_at` 을 채워 commit, `204` 를 돌린다.
   계획안이 없으면 행 · 원본이 실제로 지워지고 `204` 다. 다른 `IntegrityError` 는 rollback 후
   다시 올려 기존 `500` 을 유지한다. `409 IN_USE` 는 없앤다.
5. **목록과 `find_own_form` 모두 감춘 양식을 빼고 찾는다.** 다시 삭제하면 기존 문구의
   `404 NOT_FOUND`, 새 계획안의 `form_id` 로 써도 `404` 다. plans 코드는 바꾸지 않는다.
6. **감춘 양식 정리는 보류한다.** 계획안 삭제가 생기면 그 PR 이 감춘 양식 정리를 같이 붙인다.
   그때까지 감춘 양식 · 원본은 DB 에 남는다. 정리 코드를 미리 만들지 않는다.
7. **원본 조회 창구는 쓰는 쪽이 생길 때 만든다.** 수린 원 서식 내보내기 · 승석 양식 커스텀은
   감춘 양식도 찾아야 한다. 지금은 소비자가 없어 조회 함수를 두지 않는다.

## 근거

- **[실측]** 이 PR 전용 테스트 Postgres 15 에서 잰 값 — 압축되지 않는 16,761-byte `bytea` 5행에서
  본 테이블 8,192 bytes · TOAST 90,112 bytes, 다른 컬럼만 조회하면 280 bytes 를 읽었다.
  원본은 TOAST 로 빠져 본 테이블이 가볍고, deferred 가 목록에서 원본을 읽지 않게 한다.
- **[실측]** `scripts/backup.sh:28` 은 `pg_dump` 로 DB 를 백업한다. 원본도 함께 백업되어
  ADR-020 의 「백업 방식을 먼저 정해야」 우려가 해소된다.
- **[실측]** `nginx/nginx.conf:18` 에 `client_max_body_size 10m` 이 있다.
- **[실측]** `backend/app/features/plans/models.py:86-91` 은 `form_id` 만 들고,
  마이그레이션 `c1d4e7a92f31:39` 의 `fk_plans_form_id_forms` 가 참조된 양식 삭제를 막는다.
- **[실측]** plans 라우터에는 생성 · 목록/조회 · 수정 · 확정 · 감사만 있고 삭제가 없다.
  원 · 반을 지우는 API(centers 라우터)도 없고, `ON DELETE CASCADE` 도 없다.
- **[출처]** [#102](https://github.com/kakaotechcampus-4/ktc4-kangwon-2/issues/102):
  멘토 「하나당 양식이면 kb 수준」을 근거로 DB 저장을 정했고, PM 표는 계획안이 있으면 숨겨 `204` 다.
- **[판단]** `hidden_at` 은 `confirmed_at` · `consent_confirmed_at` 처럼 한 번 일어난 사건의
  시각이다. boolean 보다 「언제 감췄나」에도 답한다.
- **[판단]** 원장이 지운 양식이 오래 열린 화면에서 새 계획안에 붙지 않게 `find_own_form` 도 막는다.

## 대안

- **별도 `form_originals` 테이블** — TOAST · deferred 로 목록이 원본을 읽지 않으니 분리가 필요 없다.
- **서버 디스크 파일** — DB 행과 파일의 백업 · 삭제를 따로 맞춰야 한다.
- **실측 없는 앱 상한(예: 2MB)** — nginx 상한이 이미 있고 더 낮출 근거가 없다.
- **`is_hidden` boolean** — 같은 컬럼 하나로 숨긴 시각까지 알 수 없다.
- **목록에서만 숨김** — 오래 열린 화면이 숨긴 `form_id` 로 새 계획안을 만들 수 있다.
- **정리 함수부터 작성** — 계획안 삭제 API 가 없어 부를 곳이 없다. 그 PR 에 붙인다.
- **원본 조회 함수부터 작성** — 내보내기 · 커스텀이 필요한 조회 계약을 그때 정한다.

## 결과

- ADR-020 결정 2 · 5를 대체한다. 원 귀속 · 파싱 결과 · 인증/인가와 ADR-017 · ADR-009 는 그대로다.
- 컬럼 추가 전에 등록한 양식에는 원본이 없다. 원이 다시 올린다.
- `409 IN_USE` 가 계약에서 빠지고, 숨긴 양식은 목록 · 새 계획안에서 없는 것과 같다.
- 계획안 삭제 API 가 생기기까지 감춘 양식 · 원본이 DB 에 쌓인다.
- nginx 를 거치는 원본은 최대 10MB 다. 앱에 별도 상한은 없다.
