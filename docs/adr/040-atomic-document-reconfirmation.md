# ADR-040: 일과 근거 비교와 재확정을 한 트랜잭션으로 처리한다

- 날짜: 2026-10-19
- 번호: 처음에 030 으로 적었는데 하민님의 [ADR-030](030-pm-contract-decisions-2026-10-19.md)(PM 계약 결정 기록)과 겹쳐 2026-10-20 에 040 으로 옮겼다. 내용은 그대로다.
- 상태: 채택 (TASK 2 후속 수정)

## 맥락

[실측] 기존 API는 unconfirm → refresh → PUT → confirm이며 각각 커밋한다.
중간 실패로 확정본이 초안으로 남고, 비교 후 원본이 바뀌는 충돌도 막지 못한다.

## 결정

비교 API가 문서 전체와 원본 값에 바인딩한 HMAC 토큰을 발급한다.
새 reconfirm API는 원본 일과를 ID 순으로 잠근 뒤 문서를 잠그고 토큰·확인 3개·공유 게이트를
검사한다. 모두 통과하면 근거와 사실, 교사가 제출한 해석·지원을 반영하고 확정한다.
상위 문서 stale 전파와 완료 영수증 기록까지 한 트랜잭션으로 커밋한다.
`document_reconfirmations`는 문서·비교 토큰 유일 제약, 요청·원본 해시와 완료 버전을 보관한다.
기존 API는 유지한다. 새 API 범위는 일과 근거의 일일 보육일지다.

## 근거

[판단] 비교 토큰은 문서/원본을 다시 볼 필요가 있는 시점을 판별하고 영수증은 응답 유실의
재시도를 판별한다. 문서나 원본이 다시 바뀌면 기존 영수증으로 성공을 반환하지 않는다.
원본 → 문서 잠금 순서를 일과 PUT/DELETE와 통일해 잠금 순서 역전을 피한다.

## 대안

프런트에서 API를 연속 호출하면 부분 성공을 복구할 수 없다.
review_note에 토큰을 넣으면 교사 메모를 훼손한다. 메모와 별개인 영수증 테이블을 택한다.

## 보강 (2026-10-19) — 사라진 근거 처리

원본이 삭제되면 `refresh`도 `reconfirm`도 막혀 교사에게 「문서를 지우고 새로 만들기」밖에
남지 않았다. 문서 id 와 나머지 유효한 근거를 지킬 길이 없다.

그래서 reconfirm 요청에 선택 필드 `resolutions`를 더했다. 사라진 근거마다 **빼기(drop)** 또는
**같은 반·같은 날짜의 다른 일과로 바꾸기(replace)** 를 고르고, 서버가 같은 트랜잭션에서
사본을 지우거나 새 원본으로 다시 떠서 확정한다. 후보 목록은 비교 응답의 `candidates`로 함께
내려 화면이 반·날짜를 다시 알아내 또 조회하지 않게 했다.

[판단] 자동으로 빼지 않는다 — 교사가 고른 근거가 조용히 줄면 문서의 근거가 바뀐 것을 아무도
모른다. 근거가 하나도 남지 않는 선택은 거절한다. 무엇을 빼고 무엇으로 바꿨는지는
`document_reconfirmations.resolutions`에 원문 사본과 함께 남긴다 — 사본 행이 사라지므로
여기가 유일한 흔적이다. 기존 호출자는 필드를 보내지 않으므로 동작이 그대로다.

초안에도 같은 길을 열었다. 확정을 취소하면 `reconfirm` 을 쓸 수 없어(확정본 전용) 교사가 다시
막혔기 때문이다. `refresh` 가 같은 `resolutions` 를 **선택 본문**으로 받는다 — 본문 없는 예전
호출은 그대로 거절되고, 받은 경우에만 사본과 `사실`, 각 칸의 `source_ids` 를 다시 맞춘다.
해석·지원과 `DRAFT` 상태는 건드리지 않는다. 확정은 교사가 평소 경로로 한다.

[판단] (2026-10-20 갱신) 영수증에 적는 원본 해시를 **완료 후** 값으로 바꿨다. 전에는 변경
전 값을 적어서, 근거를 빼거나 바꾼 요청을 다시 보내면 재조회 값과 어긋나 409 `STALE_WRITE`
였다 — 첫 요청은 이미 반영된 뒤라 교사에게는 「실패했는데 바뀌어 있다」로 보였다. 지금은
재시도가 재는 것과 같은 길로 잰 값을 적으므로 같은 본문이면 200 이고 영수증은 한 줄이다.
본문이 다르거나 완료 뒤 문서·원본이 바뀌면 여전히 409 다.

[판단] 초안 쪽 처리 내역은 `document_source_resolutions` 라는 **별도 표**에 남긴다. 영수증
표에 섞지 않는다 — 저쪽은 비교 토큰마다 한 줄인 확정본 재확정의 완료 기록이고, 초안 처리는
확정이 아니라 토큰도 영수증도 없다. 한 줄에 `document_id, source_id, action, replacement_id,
before, actor_user_id, created_at` 을 적고, 문서 변경과 같은 트랜잭션이라 거절되면 아무것도
남지 않는다. 문서가 나중에 확정돼도 지우지 않는다. `before` 는 아동 관련 문구를 담을 수
있어 응답·로그·화면에 내보내지 않는다 (ADR-013).

[한계] 두 이력이 두 표로 나뉘어 있다. 「이 문서의 근거가 언제 어떻게 바뀌었나」를 한 번에
보려면 둘을 합쳐 읽어야 한다. 초안 쪽에는 `actor_user_id` 가 있고 영수증 쪽에는 없다 —
합칠지, 영수증에도 행위자를 넣을지는 정하지 않았다.

## 결과

배포 전에 Alembic 마이그레이션이 필요하다 (`f7a1c3d5e902` → `b6e2d4a71c38` →
develop 과의 합류점 `99de0f5d953a` → `c41ab7d6e508`). 교사 확인 없이
자동 재확정하지 않으며, 원본 누락·토큰 충돌·검증 실패는 기존 확정 상태와 내용을 그대로 보존한다.
