# ADR-091: 영유아 평가는 만들지 않고 올린 것만 4-2 로 센다

- 2026-11-10
- 상태 — 채택 (ADR-007 재확인 · ADR-022 결정 10 의 「PM 확인 대기」를 닫음)
- 관련 — ADR-007(발달평가 스펙아웃) · ADR-022(결정 10 · 12) · ADR-057(카드에서 증빙 등록) · api-spec §11 · §12 · 미확정사항 U-3 · #496

## 맥락

ADR-007(09-06)이 영유아 발달평가를 만들지 않기로 했다. 그 뒤 일지 API 를 넷으로 묶으면서
`POST /api/documents` 가 `kind: "assessment"` 도 받게 됐다. 관찰 기록을 고르면 AI 가 해석 · 지원을 써 주는
같은 길이었다. 화면에도 문서 종류 「영유아 평가」와 평가 점검 4-2 의 「영유아 평가 쓰기」 링크가 붙었다.

그런데 이 길은 끝까지 이어진 적이 없다.

- 만든 평가를 보관함에서 열 수 없었다(#496). 교사는 고치지도 확정하지도 못했다.
- AI 검토(jev)는 영유아 평가를 재지 않아 422 다(ADR-071). 한글 파일 칸 배치도 안 정했다(U-3).
- api-spec 안에서도 말이 갈렸다. §11 머리는 「여기서 만드는 문서」, 증빙 등록 절은 「만드는 기능이 아예 없다」였다.

ADR-022 결정 10 은 「ADR-007 발달평가와 같은 문서인가? 같다면 IMPORT 로만 센다」를 PM 확인 대기로 남겼다.

## 결정

1. **같은 문서다. 쌤플은 영유아 평가를 AI 로 만들지 않는다.**
   `POST /api/documents` 의 `kind` 는 `dailyLog` · `weeklyLog` · `observation` 셋이다.
   `assessment` 를 보내면 모델을 부르기 전에 422 `VALIDATION_FAILED` · `fields: ["kind"]` 다.
2. **원에서 쓴 영유아 평가는 「예전 평가 올리기」(`POST /api/documents/import`, ADR-057)로만 들어온다.**
   AI 를 쓰지 않는다. 확정(확인 셋)한 것을 4-2 가 아이마다 센다 — ADR-022 결정 10 · 12 그대로다.
3. **DB 는 그대로 둔다.** `documents.kind` 제약에 `assessment` 가 남는다 — 올린 평가와 이미 만들어진 행이 그대로 유효하다.
   마이그레이션은 없다.
4. **화면에서 「쓰기」를 뺀다.** 문서 만들기의 종류 고르기 · `/documents?kind=assessment` 미리 채우기 · 안내 문구를 지웠다.
   4-2 카드와 서류 카드의 단추는 「예전 평가 올리기」 하나다. 이름표 · 보관함 · 증빙 등록 칸은 올린 평가를 보여야 해서 남긴다.

## 근거

- **[판단]** 영유아 (발달) 평가는 아이의 발달을 영역마다 판단하는 문서다. 우리가 가진 것은 교사가 적은 관찰 · 일과 기록뿐이라
  그것으로 발달 평가를 쓰면 근거 없는 판정이 된다. AI 에게 진단 · 발달 판정을 시키지 않는다는 원칙(일지 3단 게이트 「쓰면 안 되는 것」)과도 부딪친다.
- **[실측]** 영유아 평가로 AI 초안을 real 로 한 번도 재지 않았다(docs/evaluation/06-ai-quality.md). 실물 양식도 한 장 못 봤다(U-3).
- **[실측]** 만든 평가를 화면에서 열 길이 없었다(#496, 11-07 재현). 지금 화면으로는 이 기능이 4-2 를 채운 적이 없다.
- 사용자 결정 2026-11-10 — 「우리가 갖고있는 데이터로는 만들 수 없기도 하고 실측도 없으니 영유아발달평가니깐 빼는 게 맞겠네. 나중에 고도화로 넣거나 하면 될 듯」.

## 대안

- **생성 길은 두고 화면만 감춘다** — API 를 아는 사람은 여전히 근거 없는 평가를 만든다. 문서와 코드가 계속 엇갈린다.
- **생성 요청에 전용 코드(`KIND_NOT_GENERATED`)를 새로 둔다** — `kind` 허용 목록에서 빼면 공통 422 가 이미 `fields: ["kind"]` 로
  어느 칸인지 알려 준다. 새 코드를 화면이 따로 처리할 곳이 없다.
- **DB 제약에서 `assessment` 를 뺀다** — 올린 평가가 들어갈 자리가 없어진다. 4-2 가 늘 0 이 된다.

## 결과

- 4-2 를 채우는 길은 올리기 하나다. 숫자가 비면 「예전 평가 올리기」로 보낸다.
- U-3(영유아 평가 한글 파일 칸 배치)은 정할 이유가 없어졌다 — 만들지 않으니 내보낼 것도 없다. 올린 원문은 원래 파일을 쓴다.
- #496 의 생성 쪽 막다른 길은 없어졌다. **올린 평가를 보관함에서 여는 일**은 남는다(보관함 담당과 따로 정한다).
- 예전에 AI 로 만든 `assessment` 행이 있으면 지우지 않는다. 확정했으면 4-2 에 그대로 세어진다.

## 나중에 고도화 후보

다시 만든다면 아래가 먼저 있어야 한다. 하나라도 없으면 ADR-007 의 판단이 그대로다.

- **공식 양식 hwpx** — 원에서 실제로 쓰는 영유아 평가 양식(표준보육과정 기반 · 연 2회). 칸 배치(U-3)가 여기서 정해진다.
- **발달 영역별 칸** — 영역마다 무엇을 적는지. 관찰 기록의 누리과정 5영역과 같은지 다른지부터.
- **판정 기준 실측** — 사실에 없는 발달 판정 · 진단을 걸러내는 검사를 영유아 평가로 따로 잰다(일지 jev 처럼).
- **평가 세트** — 실제 평가 문서와 그 근거 관찰을 짝지은 묶음. 이것이 있어야 초안 품질을 잴 수 있다.
