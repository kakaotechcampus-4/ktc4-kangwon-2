# 요구사항명세서 — 쌤플 (Ssample)

> 2026-10-13 · 강원대 2팀 · 카카오테크캠퍼스 4기
> **이 문서는 「무엇을 만들어야 하는가」만 적는다.**
> 화면 생김새는 [docs/screen-spec.md](screen-spec.md), 계약은 [docs/api-spec.md](api-spec.md),
> 결정 배경은 [docs/adr/](adr/), 주차 범위는 [docs/PRD.md](PRD.md).

## 읽는 법

**ID 는 바꾸지 않는다.** 기능이 없어져도 번호를 비워 두고 다시 쓰지 않는다 —
PR·이슈·회의록에 이미 적힌 번호를 밀면 추적이 끊긴다.

```
FR-1xx  계정 · 온보딩          FR-5xx  일지 생성
FR-2xx  연간계획안             FR-6xx  검증 · 확정
FR-3xx  월간 · 주간계획안       FR-7xx  보관 · 대조 · 내보내기
FR-4xx  기록 입력              FR-8xx  평가제 · 부가
NFR-01~08  비기능
```

**우선순위**

```
상   없으면 서비스가 성립하지 않는다
중   있어야 쓸 만하다
하   없어도 데모가 된다
```

**진행도** — 2026-10-13 기준. **「서버만」을 「됨」으로 읽지 않는다.**
2026-10 에 세 번 당했다 — curl 로 되는데 화면 버튼은 다른 데로 가고 있었다(CLAUDE.md).

```
완료     서버 + 화면이 이어져 있고 운영 주소에서 눌러 봤다
서버만   API 는 있는데 화면이 부르지 않는다
화면만   화면은 있는데 목업이거나 로컬 상태다
미진행   둘 다 없다
```

## 9. 비기능 요구사항

| 항목 | 구분 | NFR ID | 설명 | 적용 범위 |
|---|---|---|---|---|
| 생성 응답 시간 | 성능 | NFR-01 | 목표 미확정. 연간 12개월·월간 43칸을 운영 서버에서 측정한 뒤 팀이 목표를 정한다. 수 초가 걸리므로 **진행 표시는 지금도 필수** | 모든 LLM 생성 |
| LLM 예산 | 비용 | NFR-02 | 팀 월 ₩120,000. **초과하면 API Key 가 자동 삭제된다.** 사용량은 카테캠 담당자 통보로 보고, 로그에 `llm_usage` 네 숫자를 남겨 날짜별로 합산한다. 자동 차단은 두지 않는다 — 파일럿 중 교사 앞에서 멈춘다 | 모든 LLM 호출 |
| 문서 위조 금지 | 신뢰성 | NFR-03 | **사실기록형 문서(알림장·사고보고서·투약의뢰서)에 생성 기능을 붙이지 않는다.** 없는 사실을 쓰면 문서 조작이다 | 문서 5분류 전체 |
| 근거 추적 | 신뢰성 | NFR-04 | 값마다 Evidence·Generation·Audit 세 축을 따로 기록한다. 교사가 고치면 Evidence 는 두고 Audit 에 남긴다. **출처 표시는 화면에만** — 제출 파일에 마커가 섞이면 안 된다 | 생성된 모든 칸 |
| 아동 실명 | 개인정보 | NFR-05 | LLM 호출 직전 `shared/childCode` 한 곳에서 받침 있는 한글 가명으로 치환하고 응답에서 복원한다. **치환 실패 시 호출하지 않고 에러를 낸다.** 브라우저 저장소에 실명을 두지 않는다(ADR-013) | 아동 이름이 지나는 모든 경로 |
| 원 격리 | 보안 | NFR-06 | 문서·기록 조회가 교사의 원으로 걸린다. 없으면 로그인한 아무 교사나 남의 원 문서를 **아동 실명까지** 받아간다 | 목록 · 단건 · `related` |
| 부가 기능 장애 | 장애 대응 | NFR-07 | 트렌드봇·외부 API 가 죽어도 계획안 생성과 일지 생성은 돌아간다. 필수 의존으로 넣지 않는다. AI 를 못 부르는 상태여도 **교사는 확정할 수 있다** | 본 기능 전체 |
| 접근성 | 사용성 | NFR-08 | 색만으로 상태를 전하지 않는다. 입력칸에 레이블이 있다. 초점이 보이고 순서대로 이동한다. 명도 대비를 지킨다 | 교사가 쓰는 모든 화면 |
