## 0. 한 줄

만 3~5세 유아반 담임교사가 **연간·월간 계획안 초안을 5분 안에 받는다.**

## 1. 사용자

```
주 사용자    어린이집 만 3~5세 유아반 담임교사
부 사용자    원장 — 결재란에 이름이 들어간다. 계정은 P1
```

**한 교사가 여러 반을 맡을 수 있다.** 반마다 연간 주제가 다르다 `[실측]`.

## 2. 범위

```
P0   계획안 계열      연간 · 월간
P1   일지 계열        관찰일지 · 보육일지.  8주차
P2   평가제 대조       11~12주차
스펙아웃  알림장 · 사고보고서 · 투약의뢰서 · 발달평가
```

**알림장 계열을 만들지 않는다.** 식사·배변·수면·투약은 사실이고, 없는 사실을 쓰면 문서 조작이다. (ADR-007)

## 3. 이번 주(6주차) 범위

**연간계획안 1건이 온보딩부터 저장까지 관통한다.**

```
포함   S1~S3 온보딩 · S5 메인 · S6a·S6b · S7 연간 생성 · S8 결과 확인
제외   월간계획안(43칸) · 양식 업로드 화면 · hwp 내보내기 · 트렌드 · 설정(S10)
```

**왜 연간 먼저인가.** 규칙이 강제한다 — "연간이 `CONFIRMED` 가 아니면 월간을 생성하지 않는다".
연간이 훨씬 작다(12개월 vs 43칸). **작은 걸로 전체 경로를 뚫고 월간에 재사용한다.**

### S2 · 반 정보 (반복) + 동의 게이트

| | |
|---|---|
| 목적 | 반 단위 생성의 전제 + 아동 명단 게이트 |
| 입력 | 반 이름 · **연령** · 현재 원아 수(선택) · 담임 이름 |
| 게이트 | ☑ 이 반 모든 아동의 법정대리인 동의를 받았습니다 |
| 반복 | 「+ 반 추가」 · 각 카드에 「삭제」 |
| 완료 조건 | 최소 1개 반. 이름·연령·담임이 채워짐 |

#### ★ 연령은 혼합을 포함한다

```
체크박스 3개                 전송값
  [v]만3 [ ]만4 [ ]만5      age_min 3 · age_max 3
  [ ]만3 [v]만4 [ ]만5      4 · 4
  [ ]만3 [ ]만4 [v]만5      5 · 5
  [v]만3 [v]만4 [ ]만5      3 · 4
  [ ]만3 [v]만4 [v]만5      4 · 5
  [v]만3 [v]만4 [v]만5      3 · 5
  [v]만3 [ ]만4 [v]만5      3 · 5   ← 떨어진 조합은 범위로 채운다
```

`[실측]` 충청북도 연간계획안 18개 중 **7개(39%)가 혼합반**이다 — 마성 만3-4세, 큰빛 만4-5세, 예담 만3,4세+만4-5세, 금잔디 만4-5세 등. 국가 API `cpmsapi030` 에도 `class_cnt_m5`(유아혼합) 필드가 따로 있다.

**DB 가 이미 범위다** — `classes.age_min` / `age_max`, `CHECK (age_min <= age_max)`. 숫자 하나만 보내면 컬럼 하나를 못 채운다.

**교사는 체크박스를 누르고 FE 가 두 값으로 바꿔 보낸다.** `selected_ages` 같은 배열을 보내지 않는다 — DB 가 범위 컬럼이라 「4세만 제외」를 표현할 수 없고, 배열을 보내면 범위 변환 규칙이 FE·BE 두 곳에 생긴다.

**떨어진 조합(만3·만5)은 `3 · 5` 로 채우고 화면에 「만 3~5세반」으로 표시한다.** 만 4세만 빼는 반은 실무에 없다. 「만 3·5세반」으로 쓰면 교사가 본 것과 저장된 것이 달라진다.

#### 동의 게이트

```
☑ 이 반 모든 아동의 법정대리인 동의를 받았습니다.
   동의 확인 전에는 아동 이름을 입력하지 않아요.
```

**체크 없이 입력되면 우리가 위법 상태를 유도한 것이 된다.** 교사 대부분은 동의서 절차를 모른다.
두 번째 줄이 「왜 체크해야 하는지」를 설명한다 — **이 줄을 빼지 않는다.**

**동의서 파일을 업로드받지 않는다** (ADR-004). 원이 개인정보처리자고 우리는 수탁자다(§26). 파일을 보관하면 우리가 처리자가 되고 보관·파기 의무가 따라온다.

**동의 확인 시각을 `classes.consent_confirmed_at` 에 저장한다.** 체크박스는 여전히 UI 게이트이고 **증빙이 아니다** — 위 두 줄이 그 역할이다. 컬럼을 두는 이유는 **복원**이다. 「나중에 입력할래요」로 건너뛰면 아동이 0명이라, 아동 수로 복원하면 교사가 들어올 때마다 다시 체크해야 한다.

| 상태 | 화면 |
|---|---|
| loading | 목록 스켈레톤 |
| empty | 반 0개 — "반을 추가해 주세요" + 추가 버튼 |
| success | 반 카드 목록 |
| error | 해당 카드에만 표시, 나머지 카드 유지 |

### S3 · 아동 명단 (반별)

| | |
|---|---|
| 목적 | P1 일지 계열의 전제. 지금 받아두면 8주차에 다시 안 받는다 |
| 입력 | 반마다 — 아동 이름 입력 후 Enter / 「+ 추가」 |
| 표시 | 번호 · **코드 배지** · 실명 · 「삭제」 |
| 건너뛰기 | **「나중에 입력할래요」** |
| 완료 조건 | 없음. 0명이어도 다음으로 |

#### 받는 것은 이름 하나뿐

**생년월일·성별·건강정보를 받지 않는다.** 발달평가를 스펙아웃해서 생년월일을 쓸 기능이 없다.
이름만이면 「이름+생년월일+원명」 특정 조합이 애초에 안 생긴다.

#### 코드는 등록 시점에 발급한다

```
name  "이승석"   ← 실명. DB 에만
code  "승석"     ← LLM 에 나가는 값. 받침 있는 더미 한글 이름
```

**나중에 발급하면 이미 쌓인 기록을 다시 훑어야 한다.**
영문 토큰이면 조사가 복원 후 틀어진다 — `Child1이` / `Child2가`.

#### 「나중에」 의 나머지 절반 — 메인 배너

**버튼만 두면 교사가 잊는다.** S5 메인에 배너를 띄운다.

```
⚠ 햇살반 · 별빛반 아동 명단이 비어 있어요
  관찰일지를 쓰려면 명단이 필요합니다        [입력하기 →]
```

**문구가 "관찰일지를 쓰려면" 이어야 한다.** 명단이 없어도 **P0(계획안)는 정상 작동한다** — 계획안에 아동 이름이 안 들어간다. 지금 막힌 게 아니라는 뜻이 전달돼야 한다.

| 상태 | 화면 |
|---|---|
| loading | 명단 스켈레톤 |
| empty | 반별로 — "아직 등록된 아동이 없어요. 위에서 이름을 입력해 추가해주세요" |
| success | 번호 + 코드 배지 + 실명 목록. 하단에 "현재 N명의 아동이 등록되어 있어요" |
| error | 추가 실패 — 입력한 이름을 지우지 않는다 |

**개발 DB 에 실제 아동 실명을 넣지 않는다.** 테스트는 가명으로.

### S4 · ~~성품인사~~ — 설정(S10)으로 이동

**온보딩에서 뺐다.** 충청북도 연간 18 + 월간 5 = **23개 중 0개**다.
표본 1개 원의 월간계획안으로 정했던 것이 뒤집혔다. (ADR-011 초안)

```
12칸을 채우게 하는 단계 하나
22/23 원이 쓰지 않는 화면을 전원이 지나간다
온보딩 이탈은 되돌릴 수 없다
```

**기능은 지우지 않는다.** 설정 화면(S10 · 7주차)으로 옮기고 **기본 off**.
`GET·PUT …/greetings` 계약은 그대로다 — 호출 지점만 바뀐다. `enabled` 기본값은 `false`.

**번호는 비워 둔다.** 이미 공유한 S5~S9 를 밀지 않는다.

### S6a · 계획 문서 구성 — 첫 진입 1회

| | |
|---|---|
| 질문 1 | 월간 계획안을 쓰나요 |
| 질문 2 | 주간 계획을 어디에 쓰나요 |
| 선택지 | ○ 주간계획안(별도) ○ 주간보육일지 계획칸 ○ 일일보육일지 계획칸 |

`[출처]` 정부 보육일지 예시 ② — *"주간보육계획을 활용하되 계획과 실행 기록을 통합하여 작성"*. 원마다 다르다.

**「계획안 안 씀」 선택지가 없다.** 안 쓰면 이 버튼을 안 누른다. **선택지 하나가 화면 구조로 대체됐다.**

### S6b · 시작 방식

```
○ 처음부터 만들기
○ 있는 계획안 이어받기   → 연간계획안 파일 업로드
+ 안전교육 연간계획안 업로드   (선택. 없으면 이수 시간 숫자 1개)
+ 원 자체 행사                (선택. 「나중에」)
```

**연간 주제 12칸을 직접 입력받지 않는다** `[실측]` — 반마다 다르다. 반 4개면 48칸이라 아무도 안 쓴다.
업로드가 없으면 **연령별 기본 주제 12개를 제시하고 고치게 한다.** 빈칸 48개를 주지 않는다.

### S7 · 계획안 생성

| | |
|---|---|
| 입력 | 반 · 학년도 |
| 결과 | `DRAFT` 로 저장 |

**생성은 규칙 엔진이 한다. LLM 은 문장화만 한다** (ADR-005). 같은 입력이면 같은 출력이다.

| 상태 | 화면 |
|---|---|
| loading | **진행 표시 필수.** 수 초 걸린다. 빈 화면이면 교사가 다시 누른다 |
| empty | 발생하지 않는다 — 12개월이 항상 찬다 |
| error | `NO_ACTIVITIES` 503 / `GENERATION_FAILED` 500. **부분 결과를 저장하지 않는다** |

### S8 · 결과 확인 · 수정

```
① 생성 결과 표
② 칸 클릭 편집            ← 기본 수정 수단
③ 이 칸만 다시 뽑기        ← ② UI 위에 붙는다
④ 출처 표시
⑤ 상태창
⑥ 확정 버튼   DRAFT → CONFIRMED
⑦ 변경 이력
```
