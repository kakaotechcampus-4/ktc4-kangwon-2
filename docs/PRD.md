# PRD — 쌤플 P0

> **무엇을 만드는 서비스이고, 이번 주에 어디까지 하는가.** 그 둘만 다룬다.
> **지나간 주차를 쌓지 않는다** — 무엇을 왜 정했는지는 `docs/adr/`, 무엇을 바꿨는지는 git,
> 지금 어디까지 됐는지는 `docs/요구사항명세서.md` 의 진행도가 답한다.

| 찾는 것 | 어디 |
|---|---|
| 기능 하나하나의 입력·처리·출력·수락 기준 | [요구사항명세서](요구사항명세서.md) |
| 화면이 어떻게 생겼고 어떻게 도나 | [화면 명세](screen-spec.md) |
| 누가 쓰나 | [페르소나](페르소나.md) |
| 서버와 무슨 약속을 했나 | [api-spec](api-spec.md) · [schema](schema.md) |
| 아직 안 정한 것 | [미확정사항](미확정사항.md) |

**서비스 이름은 「쌤플 · Ssample」이다.** 운영 주소도 `ssample.duckdns.org` 다.
이전 이름 「쓱싹요정」과 시안 파일명의 「새싹플랜」은 쓰지 않는다.

---

## 0. 무엇을 만드나

**만 3~5세 유아반 담임교사가 보육 문서 초안을 받는 웹 서비스.**
교사가 적어 둔 것을 근거로 AI 가 초안을 쓰고, 교사가 읽고 고쳐 확정한다.

어린이집 교사는 계획안 · 보육일지 · 관찰일지 · 평가제 서류를 손으로 쓴다.
빈 칸 앞에서 첫 문장이 안 나오는 것이 제일 큰 벽이고, 작년 문서를 열어 고쳐 쓰다 보면
무엇을 고쳤는지 본인도 모른다. **쌤플은 첫 문장을 대신 써 주고, 그 문장이 어디서
나왔는지를 칸마다 붙여 준다.**

**대신 다 쓴 문서를 주지 않는다. 초안까지다.** 확정 버튼은 교사가 누른다 —
그 문서는 교사 이름으로 원에 제출된다.

## 1. 사용자

```
주 사용자    어린이집 만 3~5세 유아반 담임교사
부 사용자    원장 — 결재란에 이름이 들어간다. 계정은 P1
```

**한 교사가 여러 반을 맡을 수 있다.** 반마다 연간 주제가 다르다 `[실측]`.

이 사람이 **언제 쓰고 무엇을 싫어하는지**는 [페르소나](페르소나.md) 에 있다.
여기서 다시 쓰지 않는다 — 두 군데 적으면 한쪽만 고쳐진다.

## 2. 제품 목표

```
1  교사가 빈 칸 앞에서 멈추지 않는다        초안이 먼저 채워져 있다
2  교사가 「이거 어디서 나왔지」에 답할 수 있다  칸마다 근거가 붙어 있다
3  AI 가 안 본 것을 쓰지 않는다            교사가 적은 사실만 근거가 된다
4  교사가 읽고 고친 뒤에만 문서가 된다       확정은 사람이 누른다
5  AI 가 죽어도 교사가 하던 일을 끝낸다       초안이 안 나와도 쓰고 확정할 수 있다
```

**3번이 나머지를 묶는다.** 보육 문서는 교사가 책임지고 내는 서류라, 없는 사실이 한 줄
들어가면 그건 도움이 아니라 사고다.

## 3. 범위

```
P0   계획안 계열      연간 · 월간 · 주간   (주간은 월간을 거쳐서만 — ADR-030 PM-04)
P1   일지 계열        관찰일지 · 보육일지.  9~11주차
P2   평가제 대조       11~12주차
스펙아웃  알림장 · 사고보고서 · 투약의뢰서 · 발달평가
```

**알림장 계열을 만들지 않는다.** 식사·배변·수면·투약은 사실이고, 없는 사실을 쓰면 문서 조작이다. (ADR-007)

## 4. 핵심 흐름

**계획안** — 한 번 만들어 1년을 쓴다.

| 단계 | 교사가 하는 일 | 화면에서 보는 것 |
|---|---|---|
| 온보딩 | 원 · 반 · 아동 명단을 넣는다 | 반 연령 범위, 아동 명단은 건너뛸 수 있음 |
| 연간 생성 | 반을 고르고 누른다 | 12개월 주제 초안, 법정 교육 검사 결과 |
| 확인 · 수정 | 읽고 고친다 | 칸마다 근거, 고친 자리 표시 |
| 확정 | 확정 버튼 | 더는 못 고침. 월간을 만들 수 있게 됨 |
| 내보내기 | 한글 파일 받기 | 근거 표시가 빠진 제출용 파일 |

**일지** — 매일·매주 쌓는다.

| 단계 | 교사가 하는 일 | 화면에서 보는 것 |
|---|---|---|
| 기록 | 오늘 일과를 한 줄씩, 아이 관찰을 그때그때 적는다 | 어제 일과 불러오기, 영역별 빈 곳 |
| 근거 고르기 | 어떤 기록으로 일지를 쓸지 고른다 | 활동실행이 빈 줄은 못 고름 |
| 초안 | 누른다 | 사실 · 해석 · 지원 세 칸. 사실은 적은 그대로 |
| 확인 · 수정 | 해석과 지원을 고친다. 사실은 못 고친다 | 체크 3개를 켜야 확정됨 |
| 확정 | 확정 버튼 | 근거 기록을 고치면 「다시 검토」로 바뀜 |

**두 흐름이 만나는 곳은 아직 없다.** 계획안과 일지는 지금 따로 돈다 —
「계획한 대로 했나」 대조는 평가제(P2)에서 다룬다.

## 5. 공통 규칙

```
저장 상태      DRAFT → (교사 확정) → CONFIRMED
층 게이트      연간이 CONFIRMED 가 아니면 월간을, 월간이 CONFIRMED 가 아니면 주간을 생성하지 않는다
확정 취소      계획안에는 없다. 일지에만 있다(ADR-030 PM-03)
자동화 금지    자동 제출 · 자동 발송 없음
아동 실명      LLM 호출 직전 코드로 치환. 실패 시 호출하지 않고 에러
로그인         있다(FR-102). 토큰을 받아 모든 요청에 싣는다
```

## 6. 11주차 범위

**이 절은 주차가 끝나면 갈아끼운다.** 지난 주차를 아래에 쌓지 않는다 —
무엇을 왜 정했는지는 `docs/adr/` 에 남고, 무엇을 했는지는 git 이 들고 있다.
지금 어디까지 됐는지는 [요구사항명세서](요구사항명세서.md) 의 진행도가 답한다.

### 일지 한 건을 처음부터 끝까지 만들어 본다

7주차에 계획안으로 한 것을 **일지로 한 번 더** 한다. 화면이 없어서 못 쓰는 API 를 없앤다.

```
포함   S-J1 일과 기록 입력 · S-J2 일일 보육일지 생성 · S-J4 편집·확정 · S-J5 보관함 서버 연결
제외   주간 보육일지(U-2 미정) · 3단 LLM Judge(U-4 미정) · 아이 노트(U-7 범위 없음)
```

### 완료 조건 — 11주차

```
□  교사가 일과 7줄을 적고 저장하면 routines 테이블에 행이 남고, 새로고침해도 그대로다
□  그 상태에서 [오늘 일지 만들기] 를 누르면 일일 보육일지 초안이 나온다   ★ 11주차의 전부
□  초안의 「사실」이 **저장된 근거 문자열과** 글자 단위로 같다
     `RoutineRecord.fact_text()` 가 만드는 `[일과 이름 09:20~10:40] 활동실행` 형태다.
     교사가 친 글자 그대로가 아니라 **거기에 시간·일과 이름 머리말이 붙은 것**이 기준이다 —
     stale 판정도 이 문자열 하나를 비교한다(§11)
□  해석에 사실에 없는 숫자가 있으면 거절된다
□  체크 3개를 다 눌러야 확정되고, 확정본은 PUT·DELETE 가 409 다
□  일과 기록을 고치면 그걸 쓴 확정 일지가 stale 로 바뀌고 교사에게 「N건」이 보인다
□  문서 보관함이 목업이 아니라 서버 목록을 그린다
□  반이 여럿인 원에서 다른 반 기록이 섞이지 않는다                      (FR-405 · 지금 버그)
□  평가요소 19개가 실려 평가제 저장이 빈 목록 말고도 200 이 난다        (FR-802)
```

### 11주차에도 만들지 않는 것

```
주간 보육일지          만들기로 정한 적이 없다 — U-2
3단 LLM Judge         언제 부르는지가 안 정해졌다 — U-4
```

**월간 화면은 이 목록에서 뺐다**(2026-10-19). 1차 구현이 #187 로 develop 에 들어왔다(착수 근거 ADR-030 PM-09). 칸 수는 고정하지 않는다(43칸 아님).
**일지 hwpx 내보내기도 구현됐다**(2026-10-21). 서버 내보내기에 관찰일지·일일 보육일지의 확정본 화면 버튼을 연결했다. 운영 배포 확인은 별도다.

### 담당

```
덕철   S-J1 일과 기록 입력 화면 · 반 격리(FR-405)
수민   S-J2 일일 보육일지 생성 연결 · 만3~5세 일지 양식 수집
수린   S-J4 편집·확정 · S-J5 보관함 서버 연결 · 양식 수집
하민   주간계획안(weekly) · Core Error 목록
성진   hwp 변환 컨테이너 · 배포 자동화 점검
PM     평가요소 19개 · plans 조회 함수 · 월간 화면 · 트렌드봇 · 접근성 3건
```

**양식 수집이 11주차에도 0건이면 U-1 이 12주차까지 간다.** 가진 것은 #124 의 원 2곳 ·
11건뿐이고, **우리가 먼저 만드는 일일 보육일지는 B원 만1~2세 양식 하나**가 전부다
([페르소나](페르소나.md) · [미확정사항](미확정사항.md) U-1).

**관찰일지(U-1a)를 먼저 모은다.** 관찰 영역 목록은 코드에 상수로 박혀 있어서 양식이
다르면 코드를 고쳐야 한다. 보육일지(U-1b)는 교사가 일과를 직접 쳐서 양식 차이를 흡수한다.
