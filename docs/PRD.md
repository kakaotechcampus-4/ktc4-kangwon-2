# PRD — 쌤플 P0

> 이 문서는 **화면과 이번 주 완료 조건**만 다룬다. **지나간 것을 쌓지 않는다** —
> 무엇을 왜 정했는지는 `docs/adr/`, 무엇을 바꿨는지는 git, 지금 어디까지 됐는지는
> `docs/요구사항명세서.md` 의 진행도가 답한다.
>
> 무엇을 만드나 `docs/요구사항명세서.md` · 누가 쓰나 `docs/페르소나.md` ·
> 계약 `docs/api-spec.md` · 스키마 `docs/schema.md` · 일지 화면 `docs/screen-spec.md`

**화면 번호를 다시 매기지 않는다.** S4 는 빈 번호로 남긴다 — 이미 공유한 S5~S9 를 밀면 팀이 혼란스럽다.

**서비스 이름은 「쌤플 · Ssample」이다.** 운영 주소도 `ssample.duckdns.org` 다.
이전 이름 「쓱싹요정」과 시안 파일명의 「새싹플랜」은 쓰지 않는다.

## 0. 한 줄

만 3~5세 유아반 담임교사가 **연간·월간 계획안 초안을 5분 안에 받는다.**

## 1. 사용자

```
주 사용자    어린이집 만 3~5세 유아반 담임교사
부 사용자    원장 — 결재란에 이름이 들어간다. 계정은 P1
```

**한 교사가 여러 반을 맡을 수 있다.** 반마다 연간 주제가 다르다 `[실측]`.

이 사람이 **언제 쓰고 무엇을 싫어하는지**는 [페르소나](페르소나.md) 에 있다.
여기서 다시 쓰지 않는다 — 두 군데 적으면 한쪽만 고쳐진다.

## 2. 범위

```
P0   계획안 계열      연간 · 월간
P1   일지 계열        관찰일지 · 보육일지.  9~11주차
P2   평가제 대조       11~12주차
스펙아웃  알림장 · 사고보고서 · 투약의뢰서 · 발달평가
```

**알림장 계열을 만들지 않는다.** 식사·배변·수면·투약은 사실이고, 없는 사실을 쓰면 문서 조작이다. (ADR-007)

### S2 · 반 정보 (반복) + 동의 게이트

| | |
|---|---|
| 목적 | 반 단위 생성의 전제 + 아동 명단 게이트 |
| 입력 | 반 이름 · **연령** · 현재 원아 수(선택) · 담임 이름 |
| 게이트 | ☑ 이 반 모든 아동의 법정대리인 동의를 받았습니다 |
| 반복 | 「+ 반 추가」 · 각 카드에 「삭제」 |
| 완료 조건 | 최소 1개 반. 이름·연령·담임이 채워짐 |

#### ★ 연령은 혼합을 포함한다

```
체크박스 3개                 전송값
  [v]만3 [ ]만4 [ ]만5      age_min 3 · age_max 3
  [ ]만3 [v]만4 [ ]만5      4 · 4
  [ ]만3 [ ]만4 [v]만5      5 · 5
  [v]만3 [v]만4 [ ]만5      3 · 4
  [ ]만3 [v]만4 [v]만5      4 · 5
  [v]만3 [v]만4 [v]만5      3 · 5
  [v]만3 [ ]만4 [v]만5      3 · 5   ← 떨어진 조합은 범위로 채운다
```

`[실측]` 충청북도 연간계획안 18개 중 **7개(39%)가 혼합반**이다 — 마성 만3-4세, 큰빛 만4-5세, 예담 만3,4세+만4-5세, 금잔디 만4-5세 등. 국가 API `cpmsapi030` 에도 `class_cnt_m5`(유아혼합) 필드가 따로 있다.

**DB 가 이미 범위다** — `classes.age_min` / `age_max`, `CHECK (age_min <= age_max)`. 숫자 하나만 보내면 컬럼 하나를 못 채운다.

**교사는 체크박스를 누르고 FE 가 두 값으로 바꿔 보낸다.** `selected_ages` 같은 배열을 보내지 않는다 — DB 가 범위 컬럼이라 「4세만 제외」를 표현할 수 없고, 배열을 보내면 범위 변환 규칙이 FE·BE 두 곳에 생긴다.

**떨어진 조합(만3·만5)은 `3 · 5` 로 채우고 화면에 「만 3~5세반」으로 표시한다.**
「만 3·5세반」으로 쓰면 교사가 본 것과 저장된 것이 달라진다.

`[실측]` **계획안 369건에서 한 반이 떨어진 연령을 갖는 경우가 0건이다.** 파일명 표기가
반을 나누는 규칙을 그대로 보여준다 — 하이픈은 한 반의 범위, 쉼표는 반 구분자다.

```
만3-5세          86건   한 반 (3~5 혼합)
만3세,만4-5세     65건   두 반 (만3세반 + 만4-5세반)
만3세,만5세        7건   두 반 (만3세반 + 만5세반.  만4세반이 없는 원)
```

**`만3세,만5세` 7건은 전부 부산 하나금융 공동직장어린이집이고 한 반이 아니다.**
PDF 를 열면 1쪽이 「파랑새반 (3세)」, 3쪽이 「기린반 (5세)」로 반 이름과 계획안이 따로다.
`만3,4세+만4-5세`(예담)도 같은 형태다 — 계획안 문서가 원 단위라 여러 반이 한 칸에 적힌다.

**활동은 반대다.** 활동 참고자료에 강강술래·투호놀이가 `supported_ages: [3, 5]` 로 들어 있다.
**반은 범위, 활동은 점의 집합**이고 검사기가 이 둘을 다르게 읽어야 한다.

#### 동의 게이트

```
☑ 이 반 모든 아동의 법정대리인 동의를 받았습니다.
   동의 확인 전에는 아동 이름을 입력하지 않아요.
```

**체크 없이 입력되면 우리가 위법 상태를 유도한 것이 된다.** 교사 대부분은 동의서 절차를 모른다.
두 번째 줄이 「왜 체크해야 하는지」를 설명한다 — **이 줄을 빼지 않는다.**

**동의서 파일을 업로드받지 않는다** (ADR-004). 원이 개인정보처리자고 우리는 수탁자다(§26). 파일을 보관하면 우리가 처리자가 되고 보관·파기 의무가 따라온다.

**동의 확인 시각을 `classes.consent_confirmed_at` 에 저장한다.** 체크박스는 여전히 UI 게이트이고 **증빙이 아니다** — 위 두 줄이 그 역할이다. 컬럼을 두는 이유는 **복원**이다. 「나중에 입력할래요」로 건너뛰면 아동이 0명이라, 아동 수로 복원하면 교사가 들어올 때마다 다시 체크해야 한다.

| 상태 | 화면 |
|---|---|
| loading | 목록 스켈레톤 |
| empty | 반 0개 — "반을 추가해 주세요" + 추가 버튼 |
| success | 반 카드 목록 |
| error | 해당 카드에만 표시, 나머지 카드 유지 |

### S3 · 아동 명단 (반별)

| | |
|---|---|
| 목적 | P1 일지 계열의 전제. 지금 받아두면 8주차에 다시 안 받는다 |
| 입력 | 반마다 — 아동 이름 입력 후 Enter / 「+ 추가」 |
| 표시 | 번호 · **코드 배지** · 실명 · 「삭제」 |
| 건너뛰기 | **「나중에 입력할래요」** |
| 완료 조건 | 없음. 0명이어도 다음으로 |

#### 받는 것은 이름 하나뿐

**생년월일·성별·건강정보를 받지 않는다.** 발달평가를 스펙아웃해서 생년월일을 쓸 기능이 없다.
이름만이면 「이름+생년월일+원명」 특정 조합이 애초에 안 생긴다.

#### 코드는 등록 시점에 발급한다

```
name  "이승석"   ← 실명. DB 에만
code  "승석"     ← LLM 에 나가는 값. 받침 있는 더미 한글 이름
```

**나중에 발급하면 이미 쌓인 기록을 다시 훑어야 한다.**
영문 토큰이면 조사가 복원 후 틀어진다 — `Child1이` / `Child2가`.

#### 「나중에」 의 나머지 절반 — 메인 배너

**버튼만 두면 교사가 잊는다.** S5 메인에 배너를 띄운다.

```
⚠ 햇살반 · 별빛반 아동 명단이 비어 있어요
  관찰일지를 쓰려면 명단이 필요합니다        [입력하기 →]
```

**문구가 "관찰일지를 쓰려면" 이어야 한다.** 명단이 없어도 **P0(계획안)는 정상 작동한다** — 계획안에 아동 이름이 안 들어간다. 지금 막힌 게 아니라는 뜻이 전달돼야 한다.

| 상태 | 화면 |
|---|---|
| loading | 명단 스켈레톤 |
| empty | 반별로 — "아직 등록된 아동이 없어요. 위에서 이름을 입력해 추가해주세요" |
| success | 번호 + 코드 배지 + 실명 목록. 하단에 "현재 N명의 아동이 등록되어 있어요" |
| error | 추가 실패 — 입력한 이름을 지우지 않는다 |

**개발 DB 에 실제 아동 실명을 넣지 않는다.** 테스트는 가명으로.

### S4 · ~~성품인사~~ — 설정(S10)으로 이동

**온보딩에서 뺐다.** 충청북도 연간 18 + 월간 5 = **23개 중 0개**다.
표본 1개 원의 월간계획안으로 정했던 것이 뒤집혔다. (ADR-011 초안)

```
12칸을 채우게 하는 단계 하나
22/23 원이 쓰지 않는 화면을 전원이 지나간다
온보딩 이탈은 되돌릴 수 없다
```

**기능은 지우지 않는다.** 설정 화면(S10 · 7주차)으로 옮기고 **기본 off**.
`GET·PUT …/greetings` 계약은 그대로다 — 호출 지점만 바뀐다. `enabled` 기본값은 `false`.

**번호는 비워 둔다.** 이미 공유한 S5~S9 를 밀지 않는다.

### S6a · 계획 문서 구성 — 첫 진입 1회

| | |
|---|---|
| 질문 1 | 월간 계획안을 쓰나요 |
| 질문 2 | 주간 계획을 어디에 쓰나요 |
| 선택지 | ○ 주간계획안(별도) ○ 주간보육일지 계획칸 ○ 일일보육일지 계획칸 |

`[출처]` 정부 보육일지 예시 ② — *"주간보육계획을 활용하되 계획과 실행 기록을 통합하여 작성"*. 원마다 다르다.

**「계획안 안 씀」 선택지가 없다.** 안 쓰면 이 버튼을 안 누른다. **선택지 하나가 화면 구조로 대체됐다.**

### S6b · 시작 방식

```
○ 처음부터 만들기
○ 있는 계획안 이어받기   → 연간계획안 파일 업로드
+ 안전교육 연간계획안 업로드   (선택. 없으면 이수 시간 숫자 1개)
+ 원 자체 행사                (선택. 「나중에」)
```

**연간 주제 12칸을 직접 입력받지 않는다** `[실측]` — 반마다 다르다. 반 4개면 48칸이라 아무도 안 쓴다.
업로드가 없으면 **연령별 기본 주제 12개를 제시하고 고치게 한다.** 빈칸 48개를 주지 않는다.

### S7 · 계획안 생성

| | |
|---|---|
| 입력 | 반 · 학년도 |
| 결과 | `DRAFT` 로 저장 |

**RAG 로 생성하고 규칙 엔진이 검사한다** (ADR-014). 생성이 먼저고 검사가 나중이다.
**같은 입력이라도 문구가 달라질 수 있다** — 결정론을 약속하지 않는다.

| 상태 | 화면 |
|---|---|
| loading | **진행 표시 필수.** 수 초 걸린다. 빈 화면이면 교사가 다시 누른다 |
| empty | 발생하지 않는다 — 12개월이 항상 찬다 |
| error | `NO_ACTIVITIES` 503 / `GENERATION_FAILED` 500. **부분 결과를 저장하지 않는다** |

### S8 · 결과 확인 · 수정

```
① 생성 결과 표
② 칸 클릭 편집            ← 기본 수정 수단
③ 이 칸만 다시 뽑기        ← ② UI 위에 붙는다
④ 출처 표시
⑤ 상태창
⑥ 확정 버튼   DRAFT → CONFIRMED
⑦ 변경 이력
```

**전체 재생성을 만들지 않습니다** `[사용자]` — 교사가 만족한 항목까지 날아가고, LLM 은 비결정적이라 두 번째가 더 나쁠 수 있고, 되돌릴 수단이 없다.

**출처 표시**

```
근거 있는 칸에 좌상단 점 하나       인라인 각주·칩 안 씀
칸 클릭 시 우측 패널에 출처
source_type = TEMPLATE | TREND | AI | TEACHER
```

**hwp 내보내기에서 점·패널을 전부 제거한다.** 제출 문서에 마커가 나가면 안 된다.
**표시 토글을 만들지 않는다.** 끄면 검증 없이 제출하게 된다.

**상태창** — 빈 칸 수 / 안전교육 미배정 영역 / 연속 3주 동일 활동

| 상태 | 화면 |
|---|---|
| error | 칸 수정 실패 — **그 칸만** 롤백. 나머지 수정분 유지 |

---

### S9 · 내보내기

hwp 파일 생성. **출처 마커 전부 제거.** 자동 제출·자동 발송을 만들지 않는다.
연간계획안은 돈다. **일지는 아직 서버에 엔드포인트가 없다**(요구사항명세서 FR-704).

### S10 · 설정

성품인사(기본 off · 12칸) · 원 정보 수정 · 반 관리.

## 6. 11주차 범위

**이 절은 주차가 끝나면 갈아끼운다.** 지난 주차를 아래에 쌓지 않는다 —
무엇을 왜 정했는지는 `docs/adr/` 에 남고, 무엇을 했는지는 git 이 들고 있다.
지금 어디까지 됐는지는 [요구사항명세서](요구사항명세서.md) 의 진행도가 답한다.

### 일지 한 건을 처음부터 끝까지 만들어 본다

7주차에 계획안으로 한 것을 **일지로 한 번 더** 한다. 화면이 없어서 못 쓰는 API 를 없앤다.

```
포함   S-J1 일과 기록 입력 · S-J2 일일 보육일지 생성 · S-J4 편집·확정 · S-J5 보관함 서버 연결
제외   주간 보육일지(U-2 미정) · 3단 LLM Judge(U-4 미정) · 아이 노트(U-7 범위 없음)
```

### 완료 조건 — 11주차

```
□  교사가 일과 7줄을 적고 저장하면 routines 테이블에 행이 남고, 새로고침해도 그대로다
□  그 상태에서 [오늘 일지 만들기] 를 누르면 일일 보육일지 초안이 나온다   ★ 11주차의 전부
□  초안의 「사실」이 **저장된 근거 문자열과** 글자 단위로 같다
     `RoutineRecord.fact_text()` 가 만드는 `[일과 이름 09:20~10:40] 활동실행` 형태다.
     교사가 친 글자 그대로가 아니라 **거기에 시간·일과 이름 머리말이 붙은 것**이 기준이다 —
     stale 판정도 이 문자열 하나를 비교한다(§11)
□  해석에 사실에 없는 숫자가 있으면 거절된다
□  체크 3개를 다 눌러야 확정되고, 확정본은 PUT·DELETE 가 409 다
□  일과 기록을 고치면 그걸 쓴 확정 일지가 stale 로 바뀌고 교사에게 「N건」이 보인다
□  문서 보관함이 목업이 아니라 서버 목록을 그린다
□  반이 여럿인 원에서 다른 반 기록이 섞이지 않는다                      (FR-405 · 지금 버그)
□  평가요소 19개가 실려 평가제 저장이 빈 목록 말고도 200 이 난다        (FR-802)
```
