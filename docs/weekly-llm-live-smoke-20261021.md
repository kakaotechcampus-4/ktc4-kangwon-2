## 1. 무엇을 쟀나

주간계획안 LLM 경로(문서 생성 · 한 칸 재생성)를 **실제 Luna-6** 로 처음 돌려, 다음을 확인했다.

- Luna-6 가 주간 strict 응답 형식(`weekly_plan_proposal` · `weekly_cell_proposal`, 바깥놀이 후보마다 분기)을 받는가 — HTTP 400 여부
- 저장 성공 · 실패와 실패 코드, 수리율, Q2(입력에 없는 날짜 · 이름 차단) 오탐
- 시간 · 토큰 · 비용
- 세 활동 칸(실내놀이 · 대·소집단 · 대체놀이 — W3c 가 처음 실제로 쓰이는 곳)과 토요일 반의 문장

## 2. 방법

- **실행 장소: 로컬 예외(하민 승인, 2026-10-21).** 팀 CLAUDE.md 는 로컬 실제 LLM 호출을 막는다. 이번 한 번은 하민이 승인을 받아 로컬 컨테이너(python:3.12-slim)에서 돌렸다. 키는 환경 변수로만 넘기고 출력하지 않았다. `IS_SERVER=1` 은 그 실행 한 번에만 줬다.
- **주간 호출만 비용.** 부모 연간 · 월간은 mock(결정적 provider)으로 메모리에 만들었다. DB 를 쓰지 않았고, 잰 토큰 · 비용은 주간 몫뿐이다.
- **예산 가드:** 이번 실행은 「지난 호출 최대 비용 × 2」로 다음 요청을 미리 거르는 방식이었다(걸리지 않음, 실제 ₩11.03). 리뷰에서 이 방식이 상한을 보장하지 못한다는 지적을 받아, 스크립트는 **전송마다(수리 포함) 최대 비용을 먼저 예약**하는 방식으로 고쳤다 — 입력은 보낼 본문 바이트 수, 출력은 4,096 토큰으로 예약하고 **그 출력 예약을 요청의 상한(`max_completion_tokens`)으로 붙인다** — 예약이 공급자가 지키는 상한이 된다(이 칸은 bench 전송에만, 운영 요청은 그대로). usage 를 모르면 예약액을 쓴 것으로 치고 멈추며, 공급자가 상한을 무시해 예약을 넘으면 그 뒤로 멈춘다. 다음 실측 첫 호출에서 Luna-6 가 이 칸을 받는지 확인된다(못 받으면 400 으로 멈춤).

## 4. 품질 관찰 (사람 확인 · 요약)

- **연령 · 계절 · 주제에 맞는다.** 학기 초 만 3세는 새 반 적응 · 친구, 9월은 우리나라와 세계, 12월은 겨울, 10월 혼합반은 가을 자연, 2월 학년 끝은 한 해 돌아보기로 썼다. 세 활동 칸이 서로 다른 활동이고 주제와 이어진다.
- **토요일을 켠 두 반:** 요일을 지어내는 문장이 없었다. 토요일은 운영 요일 목록에만 있다.
- **날짜 · 시각 · 이름:** 생성 문장에 없었다 → Q2 차단 · 수리가 한 번도 일어나지 않았다(오탐 0).
- **결정 B:** 교사가 goals 에 날짜를 쓴 뒤 focus 를 다시 만들었고 저장됐다. 다만 모델이 그 날짜를 쓰지 않아, 「교사 날짜를 허용해 통과」 경로 자체는 이번 실측에서 실제로 밟히지 않았다(단위 테스트로만 확인).
- 문장 다듬기 거리: 학년 끝 계획안 한 칸에 「지난해」처럼 시점이 어색한 표현이 하나 있었다. 막을 성격은 아니고 교사가 고칠 범위다.
- 주간 주제는 부모 월간 주제와 같은 표현이 많았다 — 계약상 부모 값 이어받기는 허용(Q1)이다.
