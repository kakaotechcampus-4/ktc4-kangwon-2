# 화면 명세 — 쌤플

화면 하나가 무엇을 하고, 어떻게 들어가고, 무엇이 되면 끝인지 적는다.

**이 문서는 계약(`api-spec.md`)을 다시 쓰지 않는다.** 요청·응답 모양은 거기 있고, 여기는
「어느 버튼이 그 API 를 부르나」만 적는다. 두 군데 적으면 한쪽만 고쳐져 어긋난다.

**「수락 기준」이 이 문서의 핵심이다.** 그게 있어야 만든 사람이 「다 했다」를 혼자 판단한다.

```
S-J1  일과 기록 입력          보육일지의 입구
S-J2  일일 보육일지 만들기     일과를 골라 초안을 받는다
S-J3  관찰일지 만들기         아이 × 기간 × 5영역
S-J4  일지 편집 · 확정        3층을 읽고 고치고 책임진다
S-J5  문서 보관함            찾고 · 상태 보고 · 내려받는다
S-J6  기록 모아보기           한 주를 펼쳐 어디가 비었나

S-P   계획안 라인            연간 · 월간 · 주간        (아직 안 씀)
```

**미확정은 여기서 정하지 않는다.** `docs/미확정사항.md` 에 적고 번호(`U-1` …)로 가리킨다.

# S-J1 · 일과 기록 입력

## 목적

교사가 **오늘 반에서 무엇을 했는지 한 줄씩 적는다.** 이 줄들이 일일 보육일지의 사실 층이 된다
(ADR-025). AI 가 쓰지 않는다 — 있었던 일이라 모델이 채우면 위조다.

## 왜 필요한가

지금 일일 보육일지는 **입구가 없다.** 서버(`POST /api/routines`)는 9주차에 들어왔는데
적을 화면이 없어서, 문서 만들기에서 일일 보육일지를 「준비 중」으로 잠가 두었다.
이 화면이 그 잠금을 푼다.

## 들어오는 길

```
사이드바 「우리 반」 → 홈 하단 「오늘 일과」 카드 → [일과 적기]
사이드바 「기록 모아보기」 → 날짜를 고르고 → [일과 적기]
```

주소는 `/routines?date=2026-10-13&class_id=1` 이다. 날짜를 안 주면 오늘, 반을 안 주면
주 반(`primaryClassFor`)이다.

## 화면 구성

```
┌────────────────────────────────────────────────────────┐
│ 오늘 일과                          10월 13일 (월) · 햇살반 │   ← 날짜·반 바꾸기
│ 반 아이들과 보낸 하루를 시간 순서로 적어 주세요.              │
├────────────────────────────────────────────────────────┤
│  ⠿  09:00 ~ 09:20   등원 및 맞이하기                     │   ⠿ = 끌어서 순서 바꾸기
│     활동계획  (선택)                                      │
│     활동실행  현관에서 한 명씩 이름을 부르며 맞았다.          │   ← 이 칸이 일지의 사실
│                                                [지우기] │
├────────────────────────────────────────────────────────┤
│  ⠿  09:20 ~ 10:40   오전 실내놀이                        │
│     활동계획  자동차 굴리기                                │
│     활동실행  블록 3개로 길을 만들었다.                     │
│                                                [지우기] │
├────────────────────────────────────────────────────────┤
│                   [ + 일과 추가 ]                        │
├────────────────────────────────────────────────────────┤
│ 7줄 중 5줄에 활동실행을 적었어요        [저장]  [오늘 일지 만들기 →] │
└────────────────────────────────────────────────────────┘
```

**칸 다섯 개가 한 줄이다** — 시간(시작·끝) · 일과 이름 · 활동계획 · 활동실행.
`api-spec §10-1` 의 `start` · `end` · `name` · `plan` · `execution` 과 1:1 이다.

### 처음 들어오면 빈 줄 다섯 개를 미리 깔아 준다

[실측 #124] **일일 보육일지 양식은 B원 한 곳뿐이고 만1~2세다.** 그 양식의 일과 행이
**12~13개**였다. (#124 전체는 원 2곳·11건이지만 **일일 보육일지는 B원 것만 있다.**)
빈 화면에 「+ 추가」만 두면 교사가 열두 번을 누른다. 다섯 줄을 미리 깔고 모자라면 추가하게 한다.

**표본이 한 곳이고 우리 대상(만3~5세)이 아니다.** 유아반은 행 수가 다를 수 있다 —
자료가 모이면 기본 줄 수를 다시 본다. 다섯이라는 숫자 자체는 「열두 번 누르게 하지 않는다」는
뜻이지 실측값이 아니다.

**다섯 줄은 비어 있어도 저장하지 않는다.** **통째로 빈 줄만** 안 보낸다.

**한 칸이라도 적힌 줄은 버리지 않는다.** 활동실행만 적고 일과 이름을 비운 줄을
조용히 빼면 교사가 적은 사실이 새로고침 뒤에 사라진다 — 그게 제일 나쁘다.
이름이 빈 줄이 하나라도 있으면 **저장을 멈추고** 그 줄에 「일과 이름을 적어 주세요」를 띄운다.
적은 글자는 화면에 그대로 둔다.

### 어제 일과를 불러온다

```
[어제 일과 불러오기]    어제 줄의 시간 · 일과 이름만 복사한다.  활동계획 · 활동실행은 비운다
```

**[판단]** 매일 열두 줄을 처음부터 적게 하면 아무도 안 쓴다. 시간과 일과 이름은 날마다
거의 같고 활동실행만 다를 것으로 본다.

**실측이 아니다.** #124 의 「하루 일과표는 한 주 공통이고 요일 구분이 없다」는 **주간 보육일지**
(A원) 관찰이다. 주간 일지는 한 주를 한 장에 적으니 일과표가 한 번만 나오는 것이 당연하다 —
일일 일지에서 어제와 오늘 일과가 같은지는 그 자료로 알 수 없다. 수집이 끝나면 확인한다.

**활동실행을 같이 복사하지 않는다.** 어제 한 일이 오늘 한 일로 둔갑하면 그건 위조다.

## 동작

| 무엇 | 어떻게 | API |
|---|---|---|
| 줄 추가 | 맨 아래 빈 줄 하나 | 없음 (저장 때) |
| 줄 지우기 | 화면에서 지우고 **저장 때 반영**한다. 확인창 없음 | 저장 때 `DELETE /api/routines/{id}` · 저장 전에 지운 줄이면 없음 |
| 순서 바꾸기 | 끌어서 옮긴다 | 저장 때 `position` 으로 |
| 저장 | 바뀐 줄만 보낸다 | 새 줄 `POST` · 고친 줄 `PUT` |
| 오늘 일지 만들기 | **저장을 먼저 하고** S-J2 로 간다 | 저장 API · 실패하면 안 넘어간다 |

**저장은 교사가 누를 때만 한다.** 자동 저장을 하지 않는다 — 적다 만 줄이 일지 근거로 섞인다.
**지우기도 마찬가지다.** 저장을 누르기 전에는 `DELETE` 를 보내지 않는다 — 잘못 눌러도
저장하지 않고 나가면 그 줄은 서버에 그대로 있다. 확인창을 두지 않는 이유가 이것이다.

**`PUT` 은 통째로 바꾼다**(§10-1). 한 칸만 고쳐도 그 줄의 모든 값을 같이 보낸다.
시간을 안 보내면 지워진다.

**`class_id` 를 `PUT` 으로 보내지 않는다** — 422 다. 반이 바뀌면 다른 기록이다.

## 4상태

| | |
|---|---|
| loading | 그날 일과를 불러오는 중. 줄 자리를 회색 띠로 보여준다 |
| empty | 그날 기록이 없다 → **빈 줄 다섯 개 + 「어제 일과 불러오기」.** 하얀 화면을 두지 않는다 |
| success | 줄이 그려지고 「N줄 중 M줄에 활동실행을 적었어요」 |
| error | 저장 실패 — **적은 내용을 지우지 않는다.** 그 자리에 다시 시도를 둔다 |

## 거절 처리

| 서버 | 화면 |
|---|---|
| `name` 이 비었다 | 그 줄 이름 칸에 「일과 이름을 적어 주세요」 |
| `start >= end` | 그 줄 시간 칸에 「끝나는 시간이 시작보다 빨라요」 |
| 404 (남의 원·없는 기록) | 「이 기록을 찾을 수 없어요. 새로고침해 주세요」 |

## 고친 줄이 일지에 미치는 것

```
일과 이름 · 시간 · 활동실행 · 날짜를 고치면   →  그 줄을 쓴 일일 보육일지가 stale
활동계획 · 순서만 고치면                    →  그대로
지우면                                    →  「원본 없음」이라 stale
```

**교사에게 알린다.** 저장 뒤에 그 줄을 쓴 확정 일지가 있으면
「이 일과를 쓴 보육일지 N건이 다시 검토 대상이 되었어요」 한 줄을 띄운다.

## ★ 수락 기준

```
1  교사가 빈 화면에 들어와 일과 7줄을 적고 저장하면, 새로고침해도 그대로 있다
2  「어제 일과 불러오기」를 누르면 시간·일과 이름만 채워지고 활동실행은 비어 있다
3  활동실행이 적힌 줄이 **화면에** 하나라도 있으면 [오늘 일지 만들기] 가 눌린다.
   저장했는지는 보지 않는다 — 첫날에는 저장된 줄이 아직 하나도 없다.
   하나도 없으면 안 눌리고, 왜 안 눌리는지 옆에 적혀 있다
3-1 적기만 하고 저장을 안 한 줄이 있으면, [오늘 일지 만들기] 가 먼저 저장하고 넘어간다.
   저장이 실패하면 넘어가지 않는다 — S-J2 는 서버에서 다시 불러오므로
   저장 안 된 줄은 거기 없다
3-2 활동실행만 적고 일과 이름을 비운 줄이 있으면 [오늘 일지 만들기] 가 **그 줄에서 멈추고**
   「일과 이름을 적어 주세요」를 띄운다. 버튼은 눌리는데 저장이 막히는 자리라,
   왜 안 넘어가는지를 그 줄에서 말해 주지 않으면 교사가 영문을 모른다
4  줄을 끌어서 순서를 바꾸고 저장한 뒤 다시 들어오면 그 순서다
5  저장이 실패해도 교사가 적은 글자가 그대로 남아 있다
6  확정된 보육일지가 쓰던 일과를 고치면 「N건이 다시 검토 대상」 안내가 뜬다
```

# S-J2 · 일일 보육일지 만들기

## 목적

그날 적은 **일과 기록을 골라 보육일지 초안을 받는다.** 사실은 교사 원문 그대로 이어 붙이고,
해석·지원만 AI 가 쓴다.

## 들어오는 길

```
S-J1 일과 기록 → [오늘 일지 만들기 →]        날짜·반이 그대로 넘어온다
문서 보관함(S-J5) → [문서 만들기] → 일일 보육일지
```

## 화면 구성

```
┌────────────────────────────────────────────────────────┐
│ 일일 보육일지 만들기                                       │
│ 종류 [일일 보육일지 ▾]   반 [햇살반 ▾]   날짜 [2026-10-13] │
├────────────────────────────────────────────────────────┤
│ 근거로 쓸 일과                            3개 중 2개 선택  │
│                                                        │
│  ☑ 09:00~09:20  등원 및 맞이하기                         │
│       현관에서 한 명씩 이름을 부르며 맞았다.                │
│  ☑ 09:20~10:40  오전 실내놀이                            │
│       블록 3개로 길을 만들었다.                            │
│  ☐ 10:40~11:00  정리 및 손 씻기        활동실행이 비어 있어요 │  ← 못 고름
│                                                        │
│ 일과 기록이 없네요.  [일과 적으러 가기 →]                    │  ← empty 일 때
├────────────────────────────────────────────────────────┤
│                              [초안 만들기]  (30초쯤 걸려요) │
└────────────────────────────────────────────────────────┘
```

- **아이를 고르지 않는다.** 반 단위 문서다. `child_id` 를 보내면 422 (§10-1)
- **날짜는 하루다.** 시작과 끝이 달라도 422
- **활동실행이 빈 줄은 고를 수 없다.** 회색으로 두고 이유를 옆에 적는다 — 숨기면 교사가
  「내가 적은 줄이 왜 없지」 한다

## 동작

| 무엇 | API |
|---|---|
| 그날 일과 불러오기 | `GET /api/routines?class_id=&from=&to=` (같은 날짜) |
| 초안 만들기 | `POST /api/documents` `{kind:"dailyLog", class_id, start, end, source_ids}` |
| 성공 | S-J4 편집 화면으로 간다 |

**고른 순서가 그대로 사실의 순서다.** 서버가 `[일과 이름 시간] 활동실행` 을 빈 줄로 잇는다.

## 4상태

| | |
|---|---|
| loading | 초안 생성 중 — **AI 가 쓰느라 수십 초 걸린다. 진행 표시 필수.** 없으면 교사가 먹통으로 본다 |
| empty | 그날 일과 기록이 없다 → 「일과 적으러 가기 →」 (S-J1 로) |
| success | S-J4 로 이동 |
| error | 아래 표 |

## 거절 처리

| 서버 | 화면 |
|---|---|
| `VALIDATION_FAILED` `sources.{id}` | 그 줄에 「이 일과는 근거로 쓸 수 없어요」. 왜인지 같이 — 다른 날·활동실행 비었음 |
| `GENERATION_FAILED` 500 | 「초안을 만들지 못했어요」 + 다시 시도. **고른 줄을 풀지 않는다** |
| `LLM_BUDGET_EXCEEDED` 503 | 「지금은 AI 를 쓸 수 없어요. 잠시 뒤 다시 시도해 주세요」 |

## ★ 수락 기준

```
1  일과 5줄 중 활동실행이 있는 3줄만 고를 수 있고, 빈 2줄은 회색이고 이유가 보인다
2  3줄을 고르고 만들면 사실 칸에 그 3줄이 고른 순서대로 들어 있다
3  해석·지원이 비어 있지 않고, 사실에 없는 내용이 안 들어 있다
4  생성 중에 진행 표시가 보이고, 버튼을 두 번 눌러도 두 개가 안 만들어진다
5  실패해도 고른 줄이 그대로 남아 있다
6  그날 일과가 하나도 없으면 「일과 적으러 가기」가 보인다
```

`U-6` 자유놀이 영역 쪼개기 — 쪼개지면 근거 고르기 화면도 바뀐다.

# S-J3 · 관찰일지 만들기

## 목적

한 아이의 **기간 동안 관찰 기록을 모아** 관찰일지 초안을 받는다.
**종이 한 장 = 아이 1명 × 기간 × 5영역** (ADR-024).

## 들어오는 길


# S-J4 · 일지 편집 · 확정

## 목적

AI 가 쓴 초안을 **교사가 읽고 고치고 책임지고 확정한다.** 확정한 문서가 제출본이다.

## 들어오는 길

```
S-J2 · S-J3 에서 만든 직후
문서 보관함(S-J5) → 문서를 누름
```

## 화면 구성

```
┌────────────────────────────────────────────────────────┐
│ 아이 A 관찰일지 (10월)                      초안 · 근거 5건 │
│ ⚠ 근거 기록이 변경되어 다시 검토가 필요합니다  [변경된 근거 반영] │  ← stale 일 때만
├────────────────────────────────────────────────────────┤
│ 사실                                          수정 불가  │
│ ┌────────────────────────────────────────────────────┐ │
│ │ (10.07) 미끄럼틀을 혼자 올라갔다                       │ │
│ │ (10.12) 친구에게 블록을 건넸다                        │ │
│ └────────────────────────────────────────────────────┘ │
│ 교사가 적은 원문입니다. 고치려면 관찰 기록에서 고쳐 주세요. →  │
├────────────────────────────────────────────────────────┤
│ 해석                                        AI 초안 · 수정 가능│
│ ┌────────────────────────────────────────────────────┐ │
│ │ …                                                  │ │
│ └────────────────────────────────────────────────────┘ │
│ 지원                                        AI 초안 · 수정 가능│
│ ┌────────────────────────────────────────────────────┐ │
│ │ …                                                  │ │
│ └────────────────────────────────────────────────────┘ │
├────────────────────────────────────────────────────────┤
│ ☐ 사실이 제가 적은 기록과 같은지 확인했어요                  │
│ ☐ 해석이 사실을 넘어서지 않는지 확인했어요                   │
│ ☐ 지원이 우리 반에서 할 수 있는 것인지 확인했어요             │
├────────────────────────────────────────────────────────┤
│ [초안 저장]  [검토 완료 · 문서 확정]                           │
└────────────────────────────────────────────────────────┘
```

- **사실은 못 고친다.** 서버가 `PUT` 으로 사실이 바뀌면 거절한다(§11). 화면도 읽기 전용으로 두고
  **어디서 고치는지**를 같이 적는다
- **교사 확인 3개를 다 켜야 확정이 눌린다.** 서버도 막지만(422) 화면이 먼저 막는다

## 동작

| 무엇 | API |
|---|---|
| 초안 저장 | `PUT /api/documents/{id}` |
| 확정 | **`PUT` 으로 먼저 저장하고** `POST /api/documents/{id}/confirm` (체크 3개 필요) |
| 확정 취소 | `POST /api/documents/{id}/unconfirm` |
| 근거 반영 | `POST /api/documents/{id}/refresh` — **초안 + `stale` 일 때만.** 확정본은 409 라 버튼을 띄우지 않는다 |
| 내려받기 | ~~`GET /api/documents/{id}/export/hwp`~~ **서버에 없다. 11주차 범위 밖**(PRD §6) — 버튼을 띄우지 않는다 |
| 삭제 | `DELETE /api/documents/{id}` (초안만) |

**[확정] 이 저장을 겸한다.** 교사가 해석·지원을 고치고 [초안 저장] 을 안 누른 채 [확정] 을
누르면, `PUT` 없이 `confirm` 만 부를 경우 **화면에 보이는 글이 아니라 직전에 저장된 글이
확정된다.** `PUT` 을 먼저 보내고, 실패하면 확정으로 넘어가지 않는다
(`DocumentEditor` 의 `saveAndConfirm` 이 이미 이 순서다).

**확정 뒤에는 수정·삭제가 안 된다**(409 `ALREADY_CONFIRMED`). 되돌리려면 확정 취소가 먼저다.

**확정 취소는 다른 문서를 건드린다.** 이 문서를 근거로 쓴 문서가 `stale` 이 된다.
취소 뒤에 「이 문서를 근거로 쓴 문서 N건이 다시 검토 대상이 되었어요」를 띄운다.

## 4상태

| | |
|---|---|
| loading | 저장·확정 중. 버튼을 잠근다 |
| empty | 없다 — 이 화면은 문서가 있을 때만 들어온다 |
| success | 저장됨 · 확정됨 안내 |
| error | 아래 |

## 거절 처리

| 서버 | 화면 |
|---|---|
| `VALIDATION_FAILED` `sections.해석` | 해석 칸에 「사실에 없는 숫자가 있어요」 |
| `VALIDATION_FAILED` `sections.지원` (20자 미만) | 그 칸에 「20자 이상 적어 주세요」 |
| `STALE_WRITE` 409 | 「다른 화면에서 먼저 고쳤어요」 + [최신 불러오기]. **적던 글을 지우지 않는다** |
| `ALREADY_CONFIRMED` 409 | 「확정된 문서는 고칠 수 없어요. 확정을 먼저 취소해 주세요」 |
| `GATE_BLOCKED` 409 | 서버 문구를 그대로 띄운다 |

## ★ 수락 기준

```
1  사실 칸이 읽기 전용이고, 어디서 고치는지가 적혀 있다
2  체크 3개를 다 켜야 [확정] 이 눌린다
3  확정하면 수정·삭제 버튼이 사라지고 [확정 취소] 가 나타난다
4  [한글 파일로 내려받기] 가 **아직 없다.** `/api/documents/{id}/export/hwp` 가 서버에
   없어서 띄우면 404 다. 엔드포인트가 생긴 뒤에 「확정본에서만 보인다」로 되살린다
5  **초안이면서** stale 일 때만 [변경된 근거 반영] 이 보이고, 확정이 막힌다.
   **확정본이 stale 이면 그 버튼을 띄우지 않는다** — `refresh` 가 확정본을 409
   `ALREADY_CONFIRMED` 로 거절한다. 「확정을 먼저 취소해 주세요」로 안내한다
6  확정 취소하면 「근거로 쓴 문서 N건이 다시 검토 대상」 안내가 뜬다
7  저장이 실패해도 교사가 적은 글자가 그대로 남아 있다
```

# S-J5 · 문서 보관함

## 목적

만든 문서를 **한곳에서 찾고, 상태를 보고, 내려받는다.**

## 들어오는 길

```
사이드바 「문서 보관함」
```

## 화면 구성

```
┌────────────────────────────────────────────────────────┐
│ 문서 보관함                              [+ 문서 만들기]   │
│ 계획안과 일지를 한곳에서 확인하고 관리하세요.                 │
│                                                        │
│ 전체 12 │ 초안 8 │ 확정 4 │ 다시 검토 1                   │
│ [제목 검색]  [모든 종류 ▾]  [모든 반 ▾]                    │
├────────────────────────────────────────────────────────┤
│ 문서                    종류        작성일      상태        │
│ 10월 13일 보육일지        일일 보육일지  10.13   초안   →    │
│ 아이 A 관찰일지 (10월)    관찰일지     10.12   다시 검토 →   │
│ 2026학년도 연간계획안     연간계획안    10.01   확정   →     │
└────────────────────────────────────────────────────────┘
```

- **계획안과 일지가 같이 보인다.** 교사에게는 둘 다 「내가 만든 문서」다.
  **다만 출처가 다르다** — 일지는 `GET /api/documents`, 계획안은 `GET /api/plans/annual`
  (§5). `documents` 표와 `plans` 표가 아예 다르다. 두 번 불러 화면에서 합친다
- **「다시 검토」(`stale`)를 상태로 보여준다.** 초안·확정과 나란히 — 교사가 제일 먼저 봐야 할 줄이다

## 동작

| 무엇 | API |
|---|---|
| 일지 목록 | `GET /api/documents?kind=&class_id=&child_id=&status=&stale=` |
| 계획안 목록 | `GET /api/plans/annual?class_id=` (§5). 월간이 생기면 하나 더 |
| 일지 열기 | S-J4 로 |
| 계획안 열기 | **계획안 화면으로** (`/plans/annual/{id}`). S-J4 는 일지 전용이다 |
| 문서 만들기 | 종류를 고르면 S-J2 · S-J3 로 |

**정렬은 화면이 한다.** 일지와 계획안은 서로 다른 API 라(§11 · §5) 서버가 둘을 같이 정렬해
줄 수 없다 — 각 응답은 자기 것만 `created_at` 내림차순으로 온다. 화면이 두 목록을 합친 뒤
`created_at` 내림차순으로 다시 정렬한다. 같으면 일지를 먼저 두고, 그 다음 `id` 내림차순.
**두 표의 `id` 는 서로 다른 번호다** — 종류가 다른 둘을 `id` 만으로 비교하지 않는다.

**목록에는 `sections` · `sources` 가 없다**(§11). 미리보기를 그리려면 단건 조회가 필요하다 —
목록에서는 제목·종류·날짜·상태만 그린다.

## 4상태

| | |
|---|---|
| loading | 목록 불러오는 중. 줄 자리를 회색 띠로 |
| empty | 「아직 만든 문서가 없어요」 + [문서 만들기] |
| success | 표 |
| error | 「목록을 불러오지 못했어요」 + 다시 시도 |

## ★ 수락 기준

```
1  초안 · 확정 · 다시 검토가 눈으로 구분된다
2  종류 · 반으로 거를 수 있다
3  문서가 하나도 없을 때 하얀 화면이 아니라 [문서 만들기] 가 보인다
4  「일일 보육일지」가 만들 수 있는 종류로 보인다  ← 지금 「준비 중」으로 잠겨 있다
5  일지와 계획안이 **섞여서 최신순**으로 보인다. 계획안 묶음이 일지 묶음 아래에
   통째로 붙어 있으면 틀린 것이다 — 두 목록을 합친 뒤 `created_at` 으로 다시 정렬한다
```

# S-J6 · 기록 모아보기

## 목적

**한 주를 펼쳐 놓고 어느 날이 비었는지 본다.** 관찰 기록 화면은 아이로 찾을 때 쓰고,
이 화면은 「이번 주 뭐가 비었지」를 볼 때 쓴다.

## 화면 구성

```
┌────────────────────────────────────────────────────────┐
│ 기록 모아보기                            [+ 기록 남기기]   │
│                                                        │
│ 우리 반 기록                       ←  10월 12일 – 18일  →  │
│ ┌────┬────┬────┬────┬────┬────┬────┐                  │
│ │ 월 │ 화 │ 수 │ 목 │ 금 │ 토 │ 일 │                  │
│ │ 12 │ 13 │ 14 │ 15 │ 16 │ 17 │ 18 │                  │
│ │ ●● │ ●  │ ─  │ ─  │ ─  │ ─  │ ─  │   ● 관찰  ● 일과  │
│ │ 4건│ 2건│    │    │    │    │    │                  │
│ └────┴────┴────┴────┴────┴────┴────┘                  │
│                                                        │
│ [전체] [관찰 기록] [일과 기록]            10월 13일  2건    │
│ ┌──────────────┐ ┌──────────────┐                     │
│ │ 아이 A        │ │ 햇살반        │                     │
│ │ 자연탐구  10:34│ │ 오전 실내놀이 09:20│                 │
│ │ 도토리를 …     │ │ 블록 3개로 …   │                     │
│ │ [관찰 기록]    │ │ [일과 기록]    │                     │
│ └──────────────┘ └──────────────┘                     │

```

- **관찰 기록과 일과 기록을 같이 보여준다.** 둘 다 일지의 근거라 교사는 섞어서 본다
- 점 색으로 종류를 구분한다. 건수만 보여주면 「관찰만 있고 일과가 없는 날」을 못 본다

## 동작

| 무엇 | API |
|---|---|
| 주간 집계 | `GET /api/observations?class_id=&from=&to=` + `GET /api/routines?class_id=&from=&to=` |
| 날짜 고르기 | 그날 카드만 그린다. 서버를 다시 부르지 않는다 |

**시각은 자르지 않는다.** `created_at` 은 UTC 다 — `localTime()` 을 쓴다 (CLAUDE.md 날짜·시각).

## 4상태

| | |
|---|---|
| loading | 주간 띠 자리를 회색으로 |
| empty | 그 주에 기록이 없다 → 「이번 주는 아직 기록이 없어요」 + [기록 남기기] |
| success | 띠 + 카드 |
| error | 「기록을 불러오지 못했어요」 |

## ★ 수락 기준

```
1  월~일 7칸이 보이고 기록이 있는 날에 점과 건수가 보인다
2  관찰과 일과가 점 색으로 구분된다
3  날짜를 누르면 그날 카드만 보인다
4  ← → 로 주를 넘기면 그 주 집계가 보인다
5  시각이 한국 시간으로 보인다
   밤 10시에 적은 기록이 **오후 1시로 보이지 않는다** (UTC 를 그대로 자른 값이다)
   자정 넘겨 적은 기록이 **전날 칸에 들어가지 않는다** (UTC 로는 아직 전날이다)
6  반이 여럿인 원에서 **고른 반의 기록만** 보인다.
   두 조회 모두 `class_id` 를 보내야 한다 — 안 보내면 원 전체가 섞인다
```

## 지금과 다른 것

지금 이 화면은 **관찰 기록만** 보여준다. 일과 기록이 빠져 있다 — `GET /api/routines` 를
같이 불러 섞어야 한다.

그리고 **`class_id` 를 안 보내고 있다.** `lib/api/records.ts` 의 `listRecords()` 가
`getObservations()` 를 빈 조건으로 부른다 — 반이 여럿인 원에서 다른 반 기록이 섞인다.
같이 고친다.
