# 화면 명세 — 쌤플

화면 하나가 무엇을 하고, 어떻게 들어가고, 무엇이 되면 끝인지 적는다.

**이 문서는 계약(`api-spec.md`)을 다시 쓰지 않는다.** 요청·응답 모양은 거기 있고, 여기는
「어느 버튼이 그 API 를 부르나」만 적는다. 두 군데 적으면 한쪽만 고쳐져 어긋난다.

**「수락 기준」이 이 문서의 핵심이다.** 그게 있어야 만든 사람이 「다 했다」를 혼자 판단한다.

```
S-J1  일과 기록 입력          보육일지의 입구
S-J2  보육일지 만들기         근거를 골라 초안을 받는다 (일일 · 주간)
S-J3  관찰일지 만들기         아이 × 기간 × 5영역
S-J4  일지 편집 · 확정        사실 · 해석 · 지원을 읽고 고치고 책임진다
S-J5  문서 보관함            찾고 · 상태 보고 · 내려받는다
S-J6  기록 모아보기           한 주를 펼쳐 어디가 비었나
S-J7  관찰 기록 자세히 적기    한 번에 한 가지씩 물어 채운다
S-J8  관찰 기록              오늘 본 것을 적고 쌓인 기록을 본다 (/records)
소개  소개 화면               로그인 전에 보는 쌤플 소개 (/welcome)

S1~S11 계획안 라인          온보딩 · 연간계획안 · 내보내기 · 설정 · 월간계획안   맨 아래
```

**미확정은 여기서 정하지 않는다.** `docs/미확정사항.md` 에 적고 번호(`U-1` …)로 가리킨다.

# S-J1 · 일과 기록 입력

## 목적

교사가 **오늘 반에서 무엇을 했는지 한 줄씩 적는다.** 일일 보육일지의 「사실」 칸이
이 줄들로 채워진다(ADR-025). AI 가 쓰지 않는다 — 있었던 일이라 모델이 채우면 위조다.

## 왜 필요한가

일일 보육일지의 **입구다.** 서버(`POST /api/routines`)는 9주차에 들어왔고, 이 화면이
11주차에 붙어 잠금을 풀었다(`/routines`). 여기에 줄이 없으면 일일 보육일지를 만들 수 없다.

## 들어오는 길

```
사이드바 「보육일지」 → 「일일 보육일지」 탭 (/routines)
홈 「오늘 일과」 카드 → [일과 작성하기]
문서 보관함 「보육일지에서 일과 적기 →」 · 평가제 화면의 보육일지 링크
```

주소는 `/routines?date=2026-10-13&class_id=1` 이다. 날짜를 안 주면 오늘, 반을 안 주면
교사가 고른 반이다. 고른 반이 없거나 주소의 반을 못 찾으면 첫 반을 대신 열지 않고 「반을 골라주세요」다(FR-405).

## 화면 구성

```
┌──────────────┬─────────────────────────────────────────────────┐
│  11월 달력     │ 보육일지                  저장됨  [오늘 일지 만들기 →] │  ← 저장 단추 없음
│  (적은 날 점)   │ [일일 보육일지 | 주간 보육일지]                       │
│  날짜 [    ]  │ 10일 화 ◯                                  ☂ 날씨    │
├──────────────┤ ┌ 반 기본 일과표로 깔았어요 ───────────────────────┐ │
│ 10일 보육일지  │ │ [어제 지원] 반영한 줄의 「반영」을 누르세요.          │ │
│ 포스티 · 상태   │ │ (반영) 오전 실내놀이     오전 09:20 ~ 10:40 🕘  × │ │
│ [이어서 쓰기]   │ │   실제로 한 것  블록 3개로 길을 만들었다.            │ │
│              │ │   계획에서 [블록 길 만들기]  · 그 시간 관찰 [넣기]    │ │
│              │ │   계획한 것 적기 ▾                     ⟲ 되돌리기  │ │
│              │ │ …                                            │ │
│              │ │ [+ 줄 추가]  [기본 일과표로]                      │ │
│              │ └──────────────────────────────────────────────┘ │
│              │ (펴 놓은 그날 보육일지 편집기)                          │
└──────────────┴─────────────────────────────────────────────────┘
```

**한 줄은 계약의 다섯 칸이다** — 시작 · 종료 · 일과 이름 · 활동계획(「계획한 것」) · 활동실행(「실제로 한 것」).
`api-spec §10-1` 의 `start` · `end` · `name` · `plan` · `execution` 과 1:1 이다.
줄에는 표시 칸 둘이 더 붙는다 — 「반영」 도장(`reflected`)과 계획에서 맞다고 고른 활동(`activities`). 둘 다 사실 칸이 아니다(ADR-086).

- **시간은 한 칸이다.** 「오전 09:20 ~ 10:40」로 적히고, 누르면 시계판이 열려 구간 양 끝을 끌어 고친다(5분 단위).
  같은 칸 안의 시작 · 종료 `<input type="time">` 으로도 고친다 — 키보드 · 화면 읽기 프로그램의 길이다.
  시계판은 12시간이라 끈 자리만으로는 오전 · 오후를 모른다. 시작 · 종료 칸마다 납작한 「오전 | 오후」 두 칸으로 반나절을 바꾼다(#538).
- **순서는 시간이 정한다.** 끌기 · ↑ ↓ 는 없다. 시계를 닫으면 그 자리에서 시간순으로 다시 선다.
  다른 줄과 시간이 겹치면 세우지 않고 「「간식」과 시간이 겹쳐요. (09:00 ~ 09:20)」를 띄운다.
- **「계획한 것」은 접어 둔다** — 쓰는 원이 있고 안 쓰는 원이 있다. 접힌 칸은 「계획한 것 적기 ▾」,
  글이 있으면 펴진 채 「계획한 것 ▾」다. 교사가 편 칸은 글을 다 지워도 접히지 않는다(적다가 비우는 순간 커서를 잃지 않게).
- **달력.** 왼쪽 달 달력에서 날을 고른다. 그날 일과를 적은 날에 점이 찍히고, 앞날은 누르지 못한다.
  폰 너비에서는 달 달력 대신 고른 날이 든 한 주를 한 줄로 보이는 주 띠 달력이다.
  폰 달력 머리줄 오른쪽 끝 「한 달 ▾ / 한 주 ▴」로 달 한 장을 폈다 접는다(#538).
- **일과 쪽지 접기**(#538). 이름이 있는 쪽지는 이름 · 시간 한 줄로 접어 두고, 누르면 그 쪽지만 편다(데스크톱도 같다).
  이름이 없는 새 줄과 고칠 곳이 있는 줄은 늘 펴 둔다. 접기는 보이는 것만 바꾸고 적은 글은 그대로다.
- **날씨**는 날짜 옆 아이콘이다. 누르면 여섯 하늘 + 「자동으로」가 펼쳐진다(ADR-089, api-spec §10-1 「그날 날씨」).

### 새 날에 깔아 두는 줄 (ADR-085)

그날 적은 것이 없으면 서버가 정한 줄(하루치 조회의 `preset`)을 깐다. 순서는
① 반 기본 일과표(고정 줄 + 그 요일 줄) ② 지난주 같은 요일 ③ 가장 최근 기록일이고, 셋 다 없으면
국가 공식 양식의 유아 10행(`docs/references/보육일지-공식양식.md`)을 깐다.
**이름 · 시간만 깐다.** 활동계획 · 활동실행은 비운다 — 다른 날 한 일이 오늘 한 일처럼 적히면 위조다.
칠판 맨 위에 어디서 깔았는지 한 줄을 둔다 — 「반 기본 일과표로 깔았어요」 · 「11월 3일 (월) 일과로 깔았어요」.

**깔아 둔 줄은 교사가 손대기 전까지 근거로 올리지 않는다.** 열어 보기만 한 날이 서버에 쌓이면
일일 보육일지가 빈 일과를 근거로 삼는다.

**「기본 일과표로」** 를 누르면 그 하루의 이름 · 시간 목록이 펼쳐지고, 「기본 일과표로 두기」로 반 기본 일과표가 된다.
「{요일}요일만」을 누른 줄은 그 요일에만 더하는 줄이다. 다른 요일 줄은 그대로 남는다. 일요일에는 요일 줄을 둘 수 없다.
적은 글(활동계획 · 활동실행)은 옮기지 않는다. 이미 적은 날은 표를 바꿔도 그대로다.

### 줄 아래에 붙는 것 — 전부 교사가 눌러야 들어간다 (ADR-086)

- **계획 후보.** 그 주 주간계획안이 있으면 「활동」 · 「특별활동」 줄 아래에 그날 칸의 활동이 회색 칩으로 뜬다.
  누르면 그 이름이 「실제로 한 것」에 덧붙고 맞다고 한 활동으로 남는다. 그 밖의 줄은 「계획 보기」를 펴서 고른다.
- **그 시간 관찰.** 관찰 기록의 상황이 이 일과 이름과 맞으면 그 글이 아이 이름을 「○○」로 뺀 채 뜬다. 「넣기」는 붙여 넣기다.
  못 가린 낱말(외자 이름 꼴)은 노랗게 짚는다 — 넣은 뒤 교사가 고친다.
- **「반영」 도장.** 지난 기록일 일지가 **확정**이고 지원 칸이 있으면 칠판에 「어제 지원」 쪽지가 뜨고, 줄마다 「반영」 도장을 누를 수 있다.
  글자는 종이에서만 원 설정 표기(기본 `(반영)`)로 붙는다.
- **「바깥놀이(대체)」.** 비 · 눈 · 미세먼지 날 「바깥놀이」 줄에 이름을 바꾸는 칩이 뜬다.

## 동작 — 저장 단추가 없다 (ADR-084)

| 무엇 | 어떻게 | API |
|---|---|---|
| 쓰기 | 멈춘 뒤 0.8초에 **하루치 화면 줄 전체**를 임시본으로 보낸다. 머리줄에 「저장됨」 | `PUT /api/routines/draft` (`promote: false`) |
| 줄 추가 · 지우기 | 화면에서 더하고 지운다. 지운 줄은 번호만 남겨 두고 **올릴 때** 서버가 지운다. 확인창 없음 | 임시본에 같이 |
| 되돌리기 | 서버와 다른 줄에만 「⟲ 되돌리기」. 올라간 줄은 마지막으로 읽은 일과 기록으로, 안 올라간 줄은 깔았을 때로 | 임시본에 같이 |
| 떠나기 | 날짜 · 반을 옮기거나, 다른 화면으로 가거나, 창을 닫으면 **그날 일과 기록으로 올린다** | 같은 `PUT` 에 `promote: true` · 창을 닫을 때는 `keepalive` |
| 오늘 일지 만들기 | 먼저 올리고, 성공하면 「실제로 한 것」이 적힌 줄을 근거로 그날 일일 보육일지 초안을 만들어 **이 화면에서** 편다 | `PUT .../draft` `promote: true` → `POST /api/documents` |
| 일지 열기 | 그날 일지가 이미 있으면 머리줄 단추가 「일지 열기」다. 올린 뒤 그 일지를 편다 — 새로 만들지 않는다 | `PUT .../draft` `promote: true` |

- **임시본은 근거가 아니다.** 일지 · `stale` 판정은 임시본을 보지 않는다. 올린 것만 일과 기록이다.
  쓰는 대로 일과 기록에 바로 쓰면 확정 일지가 글자 하나마다 `stale` 이 되고, 열어 보기만 한 날도 쌓인다(ADR-084 맥락).
- **다시 열면 안 올라간 임시본이 먼저다.** 다른 기기에서 쓰다 만 글도 거기 있다. 없으면 그날 일과 기록, 그것도 없으면 깔 줄.
- **올리기는 서버 한 트랜잭션이다.** 새 줄 만들기 · 고치기 · 지우기가 같이 되거나 같이 안 된다 — 줄 몇 개만 올라가는 일이 없다.
- **올릴 수 없는 줄**(이름이 빔 · 끝이 시작보다 빠름)이 있으면 떠날 때는 임시본만 두고 올리지 않는다. 다음에 열면 그대로다.
  「오늘 일지 만들기」는 그 줄을 짚어 멈춘다(아래 거절 처리).
- **판 번호 하나만 맞춰 본다.** 다른 기기 · 옛 탭이 먼저 고쳤으면 409 `STALE_WRITE` 로 덮지 않는다.
- 날짜 · 반을 옮길 때 일과는 묻지 않는다. 펴 놓은 일지 편집기에 저장 안 한 글이 있을 때만 「저장하지 않은 일지 글이 사라져요. 옮길까요?」를 묻는다.

**그날 보육일지 칸.** 달력 밑에 그날 일지 상태를 포스티와 한 줄로 둔다 — 「아직 만들지 않았어요」 · 「초안까지 만들어 두었어요」 ·
「확정까지 끝냈어요」 · 「근거가 바뀌었어요. 다시 볼 것이 있어요.」. 일지가 있으면 「이어서 쓰기」(초안) · 「일지 보기」(확정) · 「접기」.
편집기는 칠판 바로 아래에 펴진다. 일일 보육일지를 만드는 길이 보관함(S-J2)을 거치지 않는다(2026-11-10).

### 그날 보육일지 칠판 — PR 대기 (#539)

#539 전에는 칠판 아래 편집기가 S-J4 편집기(`DocumentEditor`)다. #539 부터는 관찰일지(S-J3)와 같은 모양의
칠판 편집기(`DailyJournalBoard`)다. 저장 · 확정 · 충돌 · 근거 반영은 S-J4 와 같은 API 를 같은 순서로 부른다.

- **만든 초안으로 내려간다.** 「오늘 일지 만들기」로 만들면 화면이 그 편집기로 내려가 한 번 반짝이고,
  요약 칸에 「초안을 만들었어요. 칠판 밑 일지에서 다듬어 주세요.」가 뜬다. 만들어도 위 칠판만 보여 생긴 줄 몰랐다(PM)
- **「오늘 한 일」은 일과마다 분필 쪽지다.** 쪽지 머리에 일과 이름 · 시간, 옆에 「근거 N건」. 사실이라 못 고친다 —
  「칠판에서 고치기 ↑」가 위 일과 칠판으로 올린다
- 해석 · 지원 공책 두 장, 「반 운영 특이사항」 칸과 그 밑 칩
- **AI 검증** — 「AI 검증하기」를 누르면 문장마다 쪽지와 대조한다. 끝나면 「AI 검증 끝」 도장(판정을 못 했으면 「판정 못 함」).
  걸린 문장은 그 공책 아래에 형광펜과 이유로 짚는다. 확정 조건은 아니다
- **확인 한 줄 → 「확정」.** 확인 줄은 관찰일지와 같은 분필 타원이고, 켜야 「확정」 도장 단추가 눌린다.
  「일지 삭제」는 저장 · 확정 줄에서 떨어뜨려 둔다(초안만)
- **제목 옆 도장** — 초안은 점선 「초안」, 확정은 빨간 「확정」 도장. 확정본은 흰 종이 한 장(오늘 한 일 → 해석 → 지원 → 특이사항)이고
  「한글 파일로 내려받기」 · 「다시 수정」(`unconfirm`)만 있다
- **휴대폰(1024px 아래)은 화면을 덮는 한 장으로 편다.** 칠판 밑에 붙이면 세 화면 아래에 열렸다.
  닫을 때 저장 안 한 글이 있으면 먼저 묻는다

## 4상태

| | |
|---|---|
| loading | 「이 날짜의 일과를 불러오는 중이에요…」 |
| empty | 그날 기록이 없어도 **깔아 둔 줄이 있다** — 하얀 화면을 두지 않는다. 날짜가 없거나 반을 못 정했을 때만 「날짜를 선택해주세요」 · 「반을 골라주세요」 |
| success | 줄이 그려지고 머리줄에 저장 상태 한 단어 |
| error | 불러오기 실패 — 「다시 시도」. 임시본 저장 실패 — 머리줄 「저장 못 했어요」 + 다시 보내는 아이콘. **적은 글자를 지우지 않는다.** 그 상태로 창을 닫으려 하면 브라우저가 한 번 묻는다 |

## 거절 처리

| 서버 · 화면 | 화면 |
|---|---|
| `name` 이 비었다 · 50자 넘음 | 포스티 「고칠 곳이 N군데 있어요」 + 줄마다 「n번째 일과 — 일과 이름을 적어 주세요」 · 「가기 →」. 그 줄 이름 칸에도 같은 말 |
| `start >= end` | 같은 판에 「끝나는 시간이 시작보다 빨라요」 |
| 이번에 시간을 바꾼 줄이 다른 줄과 겹친다 | 같은 판에 「「간식」과 시간이 겹쳐요」. 예전부터 겹쳐 있던 줄은 막지 않는다 |
| 409 `STALE_WRITE` | 머리줄 「다른 화면에서 먼저 고쳤어요」 + 다시 불러오는 아이콘 |
| 404 (남의 원 · 없는 기록) | 「이 기록을 찾을 수 없어요. 새로고침해 주세요」 |

## 고친 줄이 일지에 미치는 것

```
일과 이름 · 시간 · 활동실행 · 날짜를 고치면   →  그 줄을 쓴 일일 보육일지가 stale
활동계획을 고치면                         →  확정 일지만 stale (확정 때 종이 한 줄을 박는다, ADR-086 결정 7)
반영 · 맞다고 한 활동을 바꾸면              →  그것을 박은 확정 일지가 stale (ADR-086 결정 6)
순서만 고치면                             →  그대로
지우면                                    →  「원본 없음」이라 stale
```

**올린 순간에 바뀐다** — 임시본에 적는 동안은 아무 일지도 `stale` 이 되지 않는다.
「오늘 일지 만들기」 로 올렸을 때 그 줄을 쓴 확정 일지가 있으면 「이 일과를 쓴 보육일지 N건이 다시 검토 대상이 되었어요」 한 줄을 띄운다.
떠나면서 올린 것은 안내를 띄울 화면이 없다 — 그 일지 칸이 「근거가 바뀌었어요」가 되고 보관함 「다시 검토」에 든다.

# S-J2 · 보육일지 만들기 (일일 · 주간)

## 목적

그날 적은 **일과 기록을 골라 보육일지 초안을 받는다.** 사실은 교사 원문 그대로 이어 붙이고,
해석·지원만 AI 가 쓴다.

## 들어오는 길

```
S-J1 일과 기록 → [오늘 일지 만들기 →]        날짜·반이 그대로 넘어온다
문서 보관함(S-J5) → [문서 만들기] → 일일 보육일지
```

> **2026-11-10** — 일일 보육일지는 S-J1 에서 바로 만든다. 「오늘 일지 만들기」가 그날 일과를 올리고
> 「실제로 한 것」이 적힌 줄 전부를 근거로 초안을 만들어 S-J1 아래 편집기에서 편다(S-J1 「동작」). 이 화면을 거치지 않는다.
> 아래는 보관함 「문서 만들기」 길과 주간 보육일지다.

## 화면 구성

```
┌────────────────────────────────────────────────────────┐
│ 일일 보육일지 만들기                                       │
│ 종류 [일일 보육일지 ▾]   반 [햇살반 ▾]   날짜 [2026-10-13] │
├────────────────────────────────────────────────────────┤
│ 근거로 쓸 일과                            3개 중 2개 선택  │
│                                                        │
│  ☑ 09:00~09:20  등원 및 맞이하기                         │
│       현관에서 한 명씩 이름을 부르며 맞았다.                │
│  ☑ 09:20~10:40  오전 실내놀이                            │
│       블록 3개로 길을 만들었다.                            │
│  ☐ 10:40~11:00  정리 및 손 씻기        활동실행이 비어 있어요 │  ← 못 고름
│                                                        │
│ 일과 기록이 없네요.  [일과 적으러 가기 →]                    │  ← empty 일 때
├────────────────────────────────────────────────────────┤
│                              [초안 만들기]  (30초쯤 걸려요) │
└────────────────────────────────────────────────────────┘
```

- **아이를 고르지 않는다.** 반 단위 문서다. `child_id` 를 보내면 422 (§10-1)
- **날짜는 하루다.** 시작과 끝이 달라도 422
- **활동실행이 빈 줄은 고를 수 없다.** 회색으로 두고 이유를 옆에 적는다 — 숨기면 교사가
  「내가 적은 줄이 왜 없지」 한다
- **고를 수 있는 줄이 하나도 없으면 [일과 적으러 가기] 를 띄운다.** 회색 줄만 늘어놓고
  [초안 만들기] 가 안 눌리면 교사가 여기서 막힌다 — 깔아 둔 하루(이름 · 시간만)만 올라간 날이 딱 이 상태다

## 동작

| 무엇 | API |
|---|---|
| 그날 일과 불러오기 | `GET /api/routines?class_id=&from=&to=` (같은 날짜) |
| 초안 만들기 | `POST /api/documents` `{kind:"dailyLog", class_id, start, end, source_ids}` |
| 성공 | S-J4 편집 화면으로 간다 |

**고른 순서가 그대로 사실의 순서다.** 서버가 `[일과 이름 시간] 활동실행` 을 빈 줄로 잇는다.

## 주간 보육일지 (ADR-044 · 2026-10-28)

같은 화면에서 종류를 **「주간 보육일지」**로 바꾸면 **「근거로 쓸 기록」 칸이 하나 더 나온다.**
원마다 일일을 쓰는 곳과 주간을 쓰는 곳이 갈려서 두 길을 다 둔다.

```
┌────────────────────────────────────────────────────────┐
│ 종류 [주간 보육일지 ▾]   반 [햇살반 ▾]                     │
│ 근거로 쓸 기록 [확정한 일일 보육일지 ▾]                     │  ← 주간일 때만 보인다
│                 확정한 일일 보육일지 / 일과 기록             │
│ 기간 [2026-10-12] ~ [2026-10-16]                        │
└────────────────────────────────────────────────────────┘
```

| 고른 값 | 후보 목록에 뜨는 것 | 안내 문구 |
|---|---|---|
| `dailyLog` (기본) | 그 기간 · 그 반의 **확정된** 일일 보육일지 | 「주간 보육일지는 검토가 완료된 일일 보육일지만 근거로 사용해요.」 |
| `routine` | 그 기간 · 그 반의 **일과 기록**(활동실행이 있는 줄) | 「일일 보육일지를 쓰지 않는 원이면 그 주 일과 기록을 바로 근거로 써요. 날짜별 해석·지원 칸은 비워서 내보내고, 주간 총평 하나만 적어요.」 |

- **반 단위다.** 일일과 같이 `child_id` 를 보내면 422
- **근거를 바꾸면 고른 것이 풀린다.** 섞어서 보내지 않는다
- `POST /api/documents` 에 `source_kind` 를 같이 보낸다. **주간이 아닌 종류에 보내면
  422 `fields: ["source_kind"]`** — 보낸 값이 안 먹는데 받으면 교사는 고른 대로
  만들어진 줄 안다 (§11)
- 한글 파일은 해석을 **「놀이 평가」**, 지원을 **「다음 주 지원계획」**으로 내보낸다

# S-J3 · 관찰일지 만들기

## 목적

한 아이의 **기간 동안 관찰 기록을 모아** 관찰일지 초안을 받는다. 반 전체를 한 번에 받을 수도 있다(ADR-083).
**관찰일지 한 장에는 아이 한 명의 그 기간치 영역 줄이 들어간다** (ADR-024). 영역은 원 설정의 축을 따른다 —
누리과정 5영역이거나 일상생활 · 놀이활동 2영역이다(ADR-088 · api-spec §11).

## 들어오는 길

```
관찰 기록 화면(/records) → [관찰일지 만들기 →]          → /records/journal (아이를 골라 두었으면 ?child=&class=)
관찰 기록 카드 → [이 기록으로 일지 만들기]               → 그 아이 · 그 기록 하루로 연다
문서 보관함(S-J5) → [문서 만들기] → 관찰일지
```

**뒤로 가는 단추는 하나다** — 머리줄 「← 관찰 기록」(`/records`). 일지를 펴 둔 동안은 「← 관찰일지 목록」이고,
고친 글이 있으면 한 번 묻는다.

## 화면 구성

```

│ 누구 관찰일지인가요?          │ 반 전체      [반 전체 초안 만들기] [확정 5명 한 파일로] │  ← 아이를 안 골랐을 때
│ [가람] [솔] [하늘 · 기록 없음] │ ☑ 가람   관찰 6개   초안                          │
│ 기간                       │ ☐ 솔     관찰 1개                                 │  ← 1개뿐이면 꺼 둔다
│ [이번 주][이번 달][지난달]     │ ☑ 하늘   관찰 4개   물어볼 것  새 기록 2개 [그대로 열기][넣어서 다시] │
│ [2026-11-01] ~ [11-10]     │   봄     관찰 70개  못 만듦  기록이 60개를 넘어요. 기간을 줄여 주세요. │
│ 근거로 쓸 기록  5건           │                                                │
│ ☑ 11/3(화) · 사회관계  …     │ 「가람 관찰일지」 목록                               │  ← 아이를 골랐을 때
│ ☑ 11/5(목) · 자연탐구  …     │                                                │
│              [초안 만들기]   │                                                │
└──────────────────────────┴─────────────────────────────────────┘

- **아이를 고르면 그 아이 길, 안 고르면 반 전체 길이다.** 고르는 동안 · 만드는 동안 아이 · 기간은 잠근다
- **근거는 기간 안 그 아이 기록 전부가 기본이다.** 체크를 풀어 뺀다. 줄마다 날짜 · 영역이 붙는다
- **기록이 없는 영역은 막지 않는다.** 빈 줄로 두고, 펴 놓은 일지 칠판에 「이 영역 관찰이 없어요: …」로 알린다 (§11 [판단])
- 아이를 안 고르거나 · 기간이 틀리거나 · 고른 기록이 없으면 「초안 만들기」 옆에 이유를 적고 안 눌린다
- **초안 전 오른쪽은 「{이름}의 이번 주」 칠판이다**(2026-11-11). 고른 기간 이름(「이번 주」 · 날짜)과 「N건 골랐어요」,
  영역 칸(5영역이면 다섯, 2영역이면 둘)을 늘 같은 크기로 세운다. 고른 기록이 있는 영역은 그 영역 색 쪽지에 건수,
  없는 영역은 점선 쪽지에 「아직 없어요」. 빈 영역이 있으면 「빈 영역은 초안에 「이 영역 관찰이 없어요」로 남아요.」를 덧붙인다

### 반 전체 초안 (ADR-083 결정 2)

- 「반 전체 초안 만들기」 한 번에 **체크된 아이를 화면이 차례로 부른다.** 서버 작업(큐)은 없다
- 체크는 기록이 있고 그 기간 AI 문서가 아직 없는 아이만 켤 수 있다. **기록이 1개뿐인 아이는 꺼 둔 채로 보인다** — 한 장면을 기간 일지로 읽게 되기 쉽다
- 아이마다 상태 — 「확정」 · 「초안」 · 「만드는 중」 · 「못 만듦」 · 「물어볼 것」 · 「검토 못 함」 · 「기록 없음」.
  「검토 못 함」은 초안은 있는데 붙여 둔 AI 검토가 mock 이거나 실패한 것이다 — 통과처럼 보이지 않게 한다
- **근거 상한 60개.** 기록이 60개를 넘는 아이는 부르지 않고 「못 만듦 — 기록이 60개를 넘어요. 기간을 줄여 주세요.」다(서버 `MAX_SOURCES` 와 같다)
- 한도 초과(503 `LLM_BUDGET_EXCEEDED`)가 나면 남은 아이를 부르지 않고 같은 이유로 「못 만듦」이다. 외자 이름 확인 같은 422 `VALUE_INVALID` 는 「물어볼 것」
- 도는 동안 화면을 떠나려 하면 브라우저가 한 번 묻는다. 떠나면 남은 아이는 만들지 않는다. 다시 누르면 남은 아이부터다
- **같은 아이 · 같은 기간 초안은 하나다**(결정 1). 이미 있으면 모델을 부르지 않고 그 초안을 준다.
  초안을 만든 뒤 새 기록이 생겼으면 「새 기록 n개」와 **「그대로 열기」 · 「넣어서 다시」** 를 묻는다.
  「넣어서 다시」는 새 기록까지 넣어 새로 만들고, 새 초안을 쓰는 트랜잭션에서 옛 초안을 지운다(`replace_draft: true`). 실패하면 옛 초안이 남는다
- **「확정 n명 한 파일로」** 는 확정본을 zip 하나로 받는다. 안의 파일은 한 장씩 받을 때와 같은 hwpx 다.
  원본이 바뀐(`stale`) 확정본은 빼고 「n명은 원본 기록이 바뀌어 파일에서 빠져요.」를 띄운다

### 펴 놓은 일지 — 붙여 둔 AI 검토 (ADR-083 결정 3 · 4)

- 만들면 이 화면에서 바로 편다. 양식은 **그 문서를 만들 때 찍은 영역 축**대로다 — 5영역이면 다섯 줄 + 「종합해석」,
  2영역(일상생활 · 놀이활동)이면 두 줄 + 「총평」. 원 설정을 나중에 바꿔도 이미 만든 문서의 줄은 그대로다(ADR-088)
- **초안을 만들 때 AI 검토를 같이 돌려 붙여 온다.** 걸린 문장은 그 칸 아래에 노란 형광펜과 이유 한 줄로 짚는다.
  지금 글과 검토한 글이 다르면(고쳤거나 근거를 다시 받았으면) 서버가 검토를 주지 않는다 — 옛 결과가 지금 글의 결과로 보이지 않는다
- 검토가 mock 이면 「AI 검토가 꺼져 있어 판정하지 않았어요. 쪽지와 직접 대조해 주세요.」, 실패면 「AI 검토를 못 했어요. …」 — 빈 목록을 통과로 읽지 않는다
- 걸린 문장마다 「고친 문장」 · 「더 짧게」(지원 칸은 「지원을 구체적으로」도). 1 · 2단을 지난 문장만 보라 점선 제안으로 오고,
  jev 판정은 「확인할 곳」으로만 붙는다. 넣을지는 교사가 고르고, 저장은 「초안 저장」이다
- 머리줄 「다시 검토」 아이콘이 지금 글로 검토를 다시 돌린다(`verify`). 확정은 검토를 요구하지 않는다 — 「쪽지와 대조했어요」 체크가 요구한다
- 반 순서로 다음 아이에게 같은 기간 AI 초안이 있으면 「확정하고 다음 아이」로 확정한 뒤 그 초안을 연다

### 펴 놓은 일지 칠판의 모양 (2026-11-11)

- 근거 쪽지마다 머리에 영역 그림(관찰 기록 영역 단추와 같은 그림 · 색)과 「수정」 단추. 「수정」은 관찰 기록에서 그 기록을 연다 — 사실은 여기서 못 고친다
- 기간에 빨간 손 동그라미를 친다. 확인 줄 「쪽지와 대조했어요. …」는 분필 타원이다
- 초안에만 「삭제」(휴지통 · 경고색). 확정하면 출력 미리보기 위에 빨간 「확정」 도장이 찍히고, 단추는 내보내기와 「다시 수정」(`unconfirm`)이다
- 펴 둔 일지는 주소 `?doc=` 에 적는다. 다른 화면에 갔다가 뒤로 오면 그 일지가 다시 펴진다

- **사실은 못 고친다.** 서버가 `PUT` 으로 사실이 바뀌면 거절한다(§11). 화면도 읽기 전용으로 두고
  **어디서 고치는지**를 같이 적는다
- **교사 확인 하나를 켜야 확정이 눌린다.** API의 checks 세 필드는 그대로 모두 true를 보낸다

## 동작

| 무엇 | API |
|---|---|
| 초안 저장 | `PUT /api/documents/{id}` |
| 확정 | **`PUT` 으로 먼저 저장하고** `POST /api/documents/{id}/confirm` (UI 확인 하나 → API checks 셋) |
| 다시 수정 (확정 풀기) | `POST /api/documents/{id}/unconfirm` |
| 근거 반영 | `POST /api/documents/{id}/refresh` — **초안 + `stale` 일 때만.** 확정본은 409 라 버튼을 띄우지 않는다. 근거가 삭제됐으면 교사가 고른 `resolutions` 를 함께 보낸다 |
| 확정된 일일 일지 재검토 | 비교 화면에서 `POST /api/documents/{id}/reconfirm` 하나로 반영·재확정 |
| 내려받기 | `GET /api/documents/{id}/export/hwp?format=` — **확정본만**(FR-704). 편집기(`DocumentEditor`)는 한글(hwpx) 버튼, 관찰일지 화면(`ObservationJournalEditor`)은 PDF · hwpx · hwp 버튼이다. 2026-11-10 고침 — 전에는 「서버에 없다. 11주차 범위 밖」이었다 |
| 삭제 | `DELETE /api/documents/{id}` (초안만) |

**[확정] 이 저장을 겸한다.** 교사가 해석·지원을 고치고 [초안 저장] 을 안 누른 채 [확정] 을
누르면, `PUT` 없이 `confirm` 만 부를 경우 **화면에 보이는 글이 아니라 직전에 저장된 글이
확정된다.** `PUT` 을 먼저 보내고, 실패하면 확정으로 넘어가지 않는다
(`DocumentEditor` 의 `saveAndConfirm` 이 이미 이 순서다).

**확정 뒤에는 수정·삭제가 안 된다**(409 `ALREADY_CONFIRMED`). 되돌리려면 확정을 먼저 푼다(「다시 수정」).

**확정을 풀면 다른 문서를 건드린다.** 이 문서를 근거로 쓴 문서가 `stale` 이 된다.
푼 뒤에 「이 문서를 근거로 쓴 문서 N건이 다시 검토 대상이 되었어요」를 띄운다.

| | |
|---|---|
| loading | 저장·확정 중. 버튼을 잠근다 |
| empty | 없다 — 이 화면은 문서가 있을 때만 들어온다 |
| success | 저장됨 · 확정됨 안내 |
| error | 아래 |

## 거절 처리

| 서버 | 화면 |
|---|---|
| `VALIDATION_FAILED` `sections.해석` | 해석 칸에 「사실에 없는 숫자가 있어요」 |
| `VALIDATION_FAILED` `sections.지원` (20자 미만) | 그 칸에 「20자 이상 적어 주세요」 |
| `STALE_WRITE` 409 | 「다른 화면에서 먼저 고쳤어요」 + [최신 불러오기]. **적던 글을 지우지 않는다** |
| `ALREADY_CONFIRMED` 409 | 「확정된 문서는 고칠 수 없어요. 「다시 수정」을 먼저 눌러 주세요」 |
| `GATE_BLOCKED` 409 | 서버 문구를 그대로 띄운다 |

## ★ 수락 기준

```
1  사실 칸이 읽기 전용이고, 어디서 고치는지가 적혀 있다
2  단일 교사 확인 체크를 켜야 [확정] 이 눌린다 (API checks 세 필드는 유지)
3  확정하면 수정·삭제 버튼이 사라지고 [다시 수정] 이 나타난다 (#541 전에는 [확정 취소])
4  [한글 파일로 내려받기] 는 **확정본에서만 보인다.** `GET /api/documents/{id}/export/hwp`
   가 서버에 있다(2026-10-21, ADR-039). 기본은 hwpx 이고 `?format=hwp` 면 `.hwp` 다
5  **초안이면서** stale 일 때만 [변경된 근거 반영] 이 보이고, 확정이 막힌다.
   **확정본이 stale 이면 그 버튼을 띄우지 않는다** — `refresh` 가 확정본을 409
   `ALREADY_CONFIRMED` 로 거절한다. 일과 근거 일일 일지는 비교·편집·확인 후
   [변경사항 반영하고 재확정]으로 원자적 reconfirm을 사용한다. 다른 종류는 기존 경로를 유지한다
6  확정을 풀면 「근거로 쓴 문서 N건이 다시 검토 대상」 안내가 뜬다
7  저장이 실패해도 교사가 적은 글자가 그대로 남아 있다
```

# S-J5 · 문서 보관함

## 목적

만든 문서를 **한곳에서 찾고, 상태를 보고, 내려받는다.**

## 들어오는 길

```
사이드바 「문서 보관함」
```

## 화면 구성

왼쪽에서 고르고 오른쪽에서 미리 본다(스플릿뷰, 2026-11-10).

```
┌────────────┬────────────────────────────────────────────────────┐
│ 반 목록      │ 문서 보관함                                          │
│ 남의 반 ·    │ 계획안과 작성한 문서들이 차곡차곡 모여 있어요.            │
│ 받은 열람 요청 │ ⚠ 문서 목록을 불러오지 못했어요  [다시 시도]   ← 알림 띠 │
│            │ (전체)(초안)(확정)  (원본 바뀜)  ( 제목으로 찾기  ✕ )     │  ← 거르개
│            │ [연간 계획안][월간][주간][보육일지][관찰일지]   ← 종류 다섯 칸 │
│            │ ← 11월 10일 ~ 16일 →    [일일 | 주간]   최신순          │
│            │ 월 ✓ │ 화 ◐ │ 수 △ │ 목 ◌ │ …                ← 날짜 칸   │
│            │ ┌ 문서 카드 ┐  ┌ 문서 미리보기 ───────────────┐       │
│            │ │ 11월 10일 │  │ 사실 시간 줄 · 해석 · 지원       │       │
│            │ └──────────┘  │            [편집하기 · 문서 열기] │       │
│            │               └──────────────────────────────┘       │
└────────────┴────────────────────────────────────────────────────┘
```

- **반 → 종류 → 기간으로 좁힌다.** 관찰일지는 아이를 이름으로 찾아 고른 뒤 그 아이 문서를 본다. 보육일지는 「일일 · 주간」을 고른다
- **보육일지 · 관찰일지는 한 주 날짜 칸**이다. 한 날짜에 여러 장이면 가장 손이 갈 상태(검토 중 → 다시 확인 → 확정)를 칸에 찍는다.
  지금은 체크 표시와 상태 글자다. PR 대기 (#540) 부터 상태 그림 넷 — 확정 ✓ 동그라미 · 검토 중 반쯤 찬 동그라미 ·
  다시 확인 느낌표 세모 · 미작성 점선 빈 동그라미. 색을 못 가려도 모양으로 갈리고, 말은 범례가 맡는다
- **만들기는 종류 화면 안의 「… 작성」 단추다**(「이 날짜 보육일지 작성」 · 「새 주간 보육일지 작성」 · 「새 연간 계획안 작성」 …).
  위에 [+ 문서 만들기] 는 없다 — 보관함은 찾아보는 곳이다. 누르면 기존 만들기 화면(S-J2)으로 간다
- **거르개** — 상태(전체 · 초안 · 확정) · 「원본 바뀜」(`stale`) · 제목 찾기. 서버가 거른 목록을 따로 받는다(FR-701).
  지금은 상태가 드롭다운이고, PR 대기 (#540) 부터 칩 · 둥근 찾기 칸(✕ 로 지우기)이다
- **알림 띠** — PR 대기 (#540). 반 정보 · 문서 목록 · 계획안 목록이 따로 실패해도 띠는 한 줄이고 「다시 시도」 하나가 실패한 것만 다시 부른다.
  로그인이 끊겼으면 「다시 로그인」만 띄운다. 서버 문구 대신 「… 불러오지 못했어요」만 보인다
- **미리보기의 사실** — PR 대기 (#540). 보육일지는 `[일과 이름 시간] 실행` 을 일과마다 한 줄(일과 이름 딱지 + 시간)로 나눈 시간 줄이다.
  주간 보육일지는 제목 옆 기간에 빨간 손 동그라미를 치고, 사실을 날짜별로 묶는다(날짜를 못 찾은 줄은 「날짜 없음」). S-J4 편집기도 같은 그림을 쓴다(#541)
- **휴대폰(760px 아래)** — PR 대기 (#540). 목록에서 문서를 고르면 목록을 걷고 문서 한 장만 본다. 「← 문서 목록으로 돌아가기」로 온다.
  빈 「문서를 선택해 주세요」 칸을 두지 않는다

- **계획안과 일지가 같이 보인다.** 교사에게는 둘 다 「내가 만든 문서」다.
  **다만 출처가 다르다** — 일지는 `GET /api/documents`, 계획안은 `GET /api/plans/annual`
  (§5). `documents` 표와 `plans` 표가 아예 다르다. 두 번 불러 화면에서 합친다
- **「다시 검토」(`stale`)를 상태로 보여준다.** 초안·확정과 나란히 — 교사가 제일 먼저 봐야 할 줄이다

## 동작

| 무엇 | API |
|---|---|
| 일지 목록 | `GET /api/documents?kind=&class_id=&child_id=&status=&stale=` |
| 계획안 목록 | 연간 `GET /api/plans/annual?class_id=` (§5) · 월간 · 주간 목록을 따로 부른다. 한쪽이 실패해도 다른 쪽은 그린다 |
| 일지 열기 | 미리보기 → 「편집하기」(초안) · 「문서 열기」(확정)로 S-J4 |
| 계획안 열기 | **계획안 화면으로** (`/plans/annual/{id}`). S-J4 는 일지 전용이다 |
| 문서 만들기 | 종류 화면 안 「… 작성」 단추 → S-J2 |

**섞지 않는다(PM 2026-11-11).** 일지와 계획안은 종류 다섯 칸에 따로 있고, 한 목록에 합쳐 정렬하지 않는다.
일지와 계획안은 서로 다른 API 라(§11 · §5) 따로 부르고 따로 그린다.
**두 표의 `id` 는 서로 다른 번호다** — 종류가 다른 둘을 `id` 만으로 비교하지 않는다.

종류 안의 순서는 화면이 정한다. 계획안 셋과 주간 보육일지는 머리줄 「최신순 · 오래된순」 단추로 뒤집는다(기본 최신순).

| 종류 | 보이는 범위 | 순서 (최신순일 때) |
|---|---|---|
| 연간 계획안 | 고른 학년도 | `id` 내림차순 |
| 월간 계획안 | 고른 달(주제형 · 놀이 중심형) | 서버가 준 순서 |
| 주간 계획안 | 고른 달 | 주(`week_id`) 내림차순 |
| 주간 보육일지 | 고른 달 | 시작일 내림차순 |
| 일일 보육일지 · 관찰일지 | 고른 주의 날짜 칸(월 → 일) 중 고른 하루 | 날짜 칸은 날짜순. 그날 문서는 서버 목록 순서(`created_at` 내림차순). 정렬 단추가 없다 |

**목록에는 `sections` · `sources` 가 없다**(§11). 미리보기를 그리려면 단건 조회가 필요하다 —
목록에서는 제목·종류·날짜·상태만 그린다.

## 4상태

| | |
|---|---|
| loading | 목록 불러오는 중. 줄 자리를 회색 띠로 |
| empty | 그 날짜 · 그 종류 문서가 없으면 가짜 카드 대신 「이 날짜 … 작성」 단추 |
| success | 날짜 칸 + 문서 카드 + 미리보기 |
| error | 「목록을 불러오지 못했어요」 + 다시 시도. PR 대기 (#540) 부터 위 알림 띠 한 줄 |

## ★ 수락 기준

```
1  초안 · 확정 · 다시 검토가 눈으로 구분된다
2  종류 · 반으로 거를 수 있다
3  문서가 하나도 없을 때 하얀 화면이 아니라 그 종류의 「… 작성」 단추가 보인다
4  「일일 보육일지」가 만들 수 있는 종류로 보인다
5  일지와 계획안은 **섞이지 않는다.** 종류 다섯 칸(연간 · 월간 · 주간 계획안 · 보육일지 · 관찰일지)에서
   고른 종류만 보인다. 계획안 셋과 주간 보육일지는 고른 기간 안에서 최신순이 기본이고 「오래된순」으로
   뒤집힌다. 일일 보육일지 · 관찰일지는 한 주 날짜 칸이 날짜순이고, 날짜를 누르면 그날 문서만 보인다
```

# S-J6 · 기록 모아보기

## 목적

**한 주를 펼쳐 놓고 어느 날이 비었는지 본다.** 관찰 기록 화면은 아이로 찾을 때 쓰고,
이 화면은 「이번 주 뭐가 비었지」를 볼 때 쓴다.

## 화면 구성

```
┌────────────────────────────────────────────────────────┐
│ 기록 모아보기                            [+ 기록 남기기]   │
│                                                        │
│ 우리 반 기록                       ←  10월 12일 – 18일  →  │
│ ┌────┬────┬────┬────┬────┬────┬────┐                  │
│ │ 월 │ 화 │ 수 │ 목 │ 금 │ 토 │ 일 │                  │
│ │ 12 │ 13 │ 14 │ 15 │ 16 │ 17 │ 18 │                  │
│ │ ●● │ ●  │ ─  │ ─  │ ─  │ ─  │ ─  │   ● 관찰  ● 일과  │
│ │ 4건│ 2건│    │    │    │    │    │                  │
│ └────┴────┴────┴────┴────┴────┴────┘                  │
│                                                        │
│ [전체] [관찰 기록] [일과 기록]            10월 13일  2건    │
│ ┌──────────────┐ ┌──────────────┐                     │
│ │ 아이 A        │ │ 햇살반        │                     │
│ │ 자연탐구  10:34│ │ 오전 실내놀이 09:20│                 │
│ │ 도토리를 …     │ │ 블록 3개로 …   │                     │

- **관찰 기록과 일과 기록을 같이 보여준다.** 둘 다 일지의 근거라 교사는 섞어서 본다
- 점 색으로 종류를 구분한다. 건수만 보여주면 「관찰만 있고 일과가 없는 날」을 못 본다

## 동작

| 무엇 | API |
|---|---|
| 주간 집계 | `GET /api/observations?class_id=&from=&to=` + `GET /api/routines?class_id=&from=&to=` |
| 날짜 고르기 | 그날 카드만 그린다. 서버를 다시 부르지 않는다 |

**시각은 자르지 않는다.** `created_at` 은 UTC 다 — `localTime()` 을 쓴다 (CLAUDE.md 날짜·시각).

## 4상태

| | |
|---|---|
| loading | 주간 띠 자리를 회색으로 |
| empty | 그 주에 기록이 없다 → 「이번 주는 아직 기록이 없어요」 + [기록 남기기] |
| success | 띠 + 카드 |
| error | 「기록을 불러오지 못했어요」 |

## ★ 수락 기준

```
1  월~일 7칸이 보이고 기록이 있는 날에 점과 건수가 보인다
2  관찰과 일과가 점 색으로 구분된다
3  날짜를 누르면 그날 카드만 보인다
4  ← → 로 주를 넘기면 그 주 집계가 보인다
5  시각이 한국 시간으로 보인다
   밤 10시에 적은 기록이 **오후 1시로 보이지 않는다** (UTC 를 그대로 자른 값이다)
   자정 넘겨 적은 기록이 **전날 칸에 들어가지 않는다** (UTC 로는 아직 전날이다)
6  반이 여럿인 원에서 **고른 반의 기록만** 보인다.
   두 조회 모두 `class_id` 를 보내야 한다 — 안 보내면 내 반과 주인 없는 반 기록이 섞인다(api-spec §2-2)
```

## 지금 화면 (2026-11-11)

**이 화면은 지금 「보육일지」의 「주간 보육일지」 탭(`/weekly-records`)이다.** 위 그림은 처음 계약 때 것이다.

- 왼쪽은 한 주를 수첩처럼 세로로 편다. 날마다 「일과 N」 · 「관찰 N」을 따로 세고, 빈 날은 「비었어요」다.
  오른쪽은 고른 날의 칠판이다 — 일과 기록 쪽지와 관찰 기록 쪽지, 「일과 적기」
- 머리줄 단추는 「주간 일지 만들기」다. 못 만들면 단추를 끄지 않고 눌렀을 때 까닭을 말한다
- 아래 **「이번 주 보육일지」 칸** — 손글씨 제목 밑에 빨간 손 물결(#538). 상태 한 줄(「아직 만들지 않았어요」 · 「초안까지 만들어 두었어요」 ·
  「확정까지 끝냈어요」 · 「근거가 바뀌었어요. 다시 볼 것이 있어요.」)과 「무엇으로 쓸까요」(확정한 일일 보육일지 N건 · 일과 기록 N건).
  이 주 일일 보육일지를 날마다 한 줄로 두고, 근거로 못 쓰는 줄은 까닭(「초안」 · 「근거가 바뀜」 …)을 단다.
  AI 초안은 줄 오른쪽 끝 「여기서 확정」으로 그 자리 편집기에서 확정한다(#538 에서 오른쪽 끝으로 옮김)
- 주간 일지는 「이어서 쓰기」 · 「일지 보기」로 칠판 바로 아래 S-J4 편집기에서 편다

예전 「지금과 다른 것」 두 가지(일과 기록이 빠짐 · `class_id` 를 안 보냄)는 고쳤다(FR-405 · FR-705).
`listRecords()` 는 반을 못 정하면 부르지 않고, 일과 조회도 `class_id` 를 보낸다.

# S-J7 · 관찰 기록 자세히 적기

## 목적

교사가 **한 장면을 작정하고 쓸 때** 쓴다. 빠른 기록이 한 줄로 끝내는 길이라면,
이쪽은 **한 번에 한 가지씩 물어** 빠진 것을 채운다.

## 왜 필요한가

지금 관찰 기록은 사실 한 칸이다. 교사가 「블록 쌓고 놀았음」을 적으면
**AI 가 거기서 해석과 지원을 쓸 근거가 없다.** 관찰일지 품질의 천장이 이 칸에서 정해진다.

**그렇다고 칸을 늘리면 급할 때 안 쓴다.** 그래서 길을 둘로 둔다 — 빠른 기록은 그대로 두고,
자세히 쓸 사람만 이쪽으로 온다.

## 들어오는 길

```
홈 빠른 기록 카드 → [자세히 적기]        ★ 주 경로.  적던 글을 들고 넘어간다
기록 모아보기(S-J6) → [기록 남기기]
관찰 기록 화면(/records) → [자세히 적기]
```

**적던 글을 버리지 않는다.** 빠른 기록에 반쯤 쓰다 누르면 그 글이 **「행동」** 자리에
들어가 있다. 처음부터 다시 쓰게 하면 아무도 두 번은 안 누른다.

## 화면 구성

```
┌────────────────────────────────────────────────────────┐
│ 자세히 적기                                    3 / 10   │
│ ▓▓▓░░░░░░░                                             │
├────────────────────────────────────────────────────────┤
│                                                        │
│   무엇을 어떻게 시작하고 바꿨나요?                        │
│   처음에 한 일 → 다시 해 본 일 → 달라진 일 순서로요        │
│                                                        │
│   ┌──────────────────────────────────────────────┐    │
│   │ 블록 세 개를 쌓다가 무너뜨렸고, 넓은 블록을      │ 🎤 │
│   │ 밑에 놓고 다시 쌓았다.                         │    │
│   └──────────────────────────────────────────────┘    │
│                                                        │
│   [없었어요] [못 봤어요] [기억 안 나요]                   │
│                                                        │
├────────────────────────────────────────────────────────┤
│  [← 이전]                            [건너뛰기]  [다음 →] │
└────────────────────────────────────────────────────────┘
```

**한 번에 하나만 보여준다.** 열 칸을 한 화면에 늘어놓으면 그건 양식이고, 교사가 질린다.

**받아쓰기 버튼을 여기도 둔다.** 퇴근 뒤에 말로 적는 게 빠르다(`use-dictation`).

## 무엇을 묻나

| 묶음 | 묻는 것 | 어디로 |
|---|---|---|
| 상황 | 무엇을 하던 중 · 어디서 · 누구와 | `fact` 앞머리 |
| 행동 | **무엇을 어떻게 시작하고 바꿨나** · 무슨 놀잇감 | `fact` 중심 ★필수 |
| 반응 | 말 · 표정 · 몸짓 / 또래는 어떻게 | `fact` |
| 지원 | 교사가 실제로 한 것 · 그 뒤 달라진 것 | `fact` |
| 마무리 | 전에도 본 적 있나 · 특히 눈에 띈 것 | `fact` 끝 |

**아이 · 날짜 · 영역은 묻지 않는다** — 들어올 때 이미 고른 값을 들고 온다.

## 건너뛸 때 — 네 가지를 가른다

```
[없었어요]      그 상황이 실제로 없었다        → 「또래 반응은 없었다」로 사실에 적는다
[못 봤어요]     있었을 수도 있는데 못 봤다      → 적지 않는다
[기억 안 나요]   기억이 안 난다                → 적지 않는다
[건너뛰기]      해당 없거나 넘어간다           → 적지 않는다
```

**「또래 반응 없음」과 「또래가 있었는지 모름」은 다르다.** 전자는 사실이고 후자는 공백이다.
빈칸으로 두면 AI 가 그 자리를 지어낸다 — §11 의 「미관찰 행동」이 된다.

## 마지막 — 엮은 글을 보여준다

```
┌────────────────────────────────────────────────────────┐
│ 이렇게 적을게요                               10 / 10   │
├────────────────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────────────┐  │
│ │ 오전 자유놀이 시간 쌓기 영역에서 혼자 놀이했다.       │  │
│ │ 블록 세 개를 쌓다가 무너뜨렸고, 넓은 블록을 밑에     │  │
│ │ 놓고 다시 쌓았다. "더 높이 만들래"라고 말했다.       │  │
│ │ 또래 반응은 없었다. 교사는 기다리며 지켜보았다.      │  │
│ └──────────────────────────────────────────────────┘  │
│ 고치고 싶은 곳은 직접 고쳐 주세요.                       │
│                              [뒤로]  [관찰 기록 저장]    │
└────────────────────────────────────────────────────────┘
```

**반드시 보여주고 고치게 한다.** 우리가 엮은 문장이 교사가 본 것과 다를 수 있다.
**사실 층은 교사가 책임지는 칸**이라 교사가 읽지 않은 글을 저장하면 안 된다.

## 동작

| 무엇 | API |
|---|---|
| 저장 | `POST /api/observations` — **기존 그대로** |
| 저장 성공 | 들어온 화면으로 돌아간다 |

**새 엔드포인트를 만들지 않는다. 칸도 안 늘린다.** 화면이 엮어서 `fact` 한 칸에 넣는다 —
스키마가 그대로라 `U-9`(칸 쪼개기)를 안 건드리고도 품질이 올라간다.

```

# S-J8 · 관찰 기록

## 목적

교사가 **오늘 본 것을 한 줄 적고, 쌓인 기록을 본다.** 관찰일지(S-J3)의 근거다(FR-404).
요구사항은 요구사항명세서 FR-404 · FR-406 에 있고, 여기는 화면 모양만 적는다(2026-11-11).

## 들어오는 길

```
사이드바 「관찰 기록」 (/records)
홈 빠른 기록 · 관찰일지 쪽지의 「수정」(그 기록을 연다)
```

## 화면 구성

- **왼쪽 「오늘 본 것 적기」, 오른쪽 쌓인 기록.** 왼쪽 칸은 화면 높이와 상관없이 고정이고(1101px 이상), 길면 칸 안에서만 내려간다
- **「저장됨」 도장.** 저장하면 제목 옆에 초록 도장을 꾹 찍는다. 다시 적기 시작하면 내린다
- **「관찰일지 만들기 →」** 는 적는 칸 바로 위다. 저장한 뒤 한 번, 포스티가 「적은 기록으로 관찰일지를 만들어 보세요」로 이 단추를 가리킨다.
  몇 초 뒤 저절로 사라지고, × 를 누르거나 다시 적으면 내린다
- **영역 단추는 그림 옆에 늘 이름을 둔다**(「신체운동·건강」은 「신체운동」까지). 그림만으로는 무슨 영역인지 몰랐다
- **「그날 일과」 블록 줄.** 상황 칸 위에 그날 일과를 손글씨 시각 + 이름 블록으로 세운다. 누르면 그 일과가 상황 칸에 들어간다
- **같은 날 같은 아이 기록은 한 벌로 겹친다.** 맨 위 한 장만 보이고 뒤 장은 그 영역 색 종이로 비켜 선다.
  「+N」 손글씨 단추 · ← → 키 · 옆으로 밀기로 다음 장을 넘기고, 카드를 누르면 그 장이 펴진다. 몇 번째 장인지 화면 낭독기가 읽는다
- 카드는 영역 색을 띠고, 긴 기록은 네 줄까지만 보이고 접어 둔다. 단추는 「수정」 · 「삭제」(휴지통 · 경고색) · 「이 기록으로 일지 만들기」
- 기록을 고치거나 지우면 「이 기록을 쓴 일지 N건이 다시 검토 대상이 되었어요」(FR-406)

| S10 설정 | `/settings` | 7 |

로그인하면 원·반 여부와 상관없이 S5 메인으로 간다. 원·반이 없어도 `/`(메인)에는 들어간다. 나머지 메뉴(문서 보관함 · 설정 포함)는
화면 대신 「원·반을 먼저 등록해 주세요」 카드를 보이고, 「등록하러 가기」가 `/onboarding` 으로 보낸다.
판단은 서버가 아니라 **브라우저에 저장된** 원 · 반 설정(`roomReady`)이 다 찼는지로 한다.
아동 명단은 0명이어도 통과다. 메인(`/`)은 원·반이 없으면 날짜 아래에 등록 안내 배너(「등록하러 갈게요」 → `/onboarding`)를 보인다.

**S6a·S6b 를 온보딩에 넣지 않는다.** 항목의 수명이 다르다 — 원·반·아동은 모든 기능의 공통 전제,
문서 구성은 계획안 전용이다. 그리고 계획안을 안 쓰는 사람에게 계획안 질문을 하게 된다.

### S2 · 반 정보 (반복) + 동의 게이트

| | |
|---|---|
| 목적 | 반 단위 생성의 전제 + 아동 명단 게이트 |
| 입력 | 반 이름 · **연령** · 현재 원아 수(선택) · 담임 이름 |
| 게이트 | ☑ 이 반 모든 아동의 법정대리인 동의를 받았습니다 |
| 반복 | 「+ 반 추가」 · 각 카드에 「삭제」 |
| 완료 조건 | 최소 1개 반. 이름·연령·담임이 채워짐 |

#### ★ 연령은 혼합을 포함한다

```
체크박스 3개                 전송값
  [v]만3 [ ]만4 [ ]만5      age_min 3 · age_max 3
  [ ]만3 [v]만4 [ ]만5      4 · 4
  [ ]만3 [ ]만4 [v]만5      5 · 5
  [v]만3 [v]만4 [ ]만5      3 · 4
  [ ]만3 [v]만4 [v]만5      4 · 5
  [v]만3 [v]만4 [v]만5      3 · 5
  [v]만3 [ ]만4 [v]만5      3 · 5   ← 떨어진 조합은 범위로 채운다
```

`[실측]` 충청북도 연간계획안 18개 중 **7개(39%)가 혼합반**이다 — inst_049 만3-4세, inst_024 만4-5세, inst_052 만3,4세+만4-5세, inst_074 만4-5세 등. 국가 API `cpmsapi030` 에도 `class_cnt_m5`(유아혼합) 필드가 따로 있다.

**DB 가 이미 범위다** — `classes.age_min` / `age_max`, `CHECK (age_min <= age_max)`. 숫자 하나만 보내면 컬럼 하나를 못 채운다.

**교사는 체크박스를 누르고 FE 가 두 값으로 바꿔 보낸다.** `selected_ages` 같은 배열을 보내지 않는다 — DB 가 범위 컬럼이라 「4세만 제외」를 표현할 수 없고, 배열을 보내면 범위 변환 규칙이 FE·BE 두 곳에 생긴다.

**떨어진 조합(만3·만5)은 P0 에서 지원하지 않는다**(ADR-038). 고르면 `3 · 5` 범위로 저장되고 「만 3~5세반」으로 보인다 —
**만 4세가 포함된다는 사실을 화면에서 알린다.** 「만 3·5세반」으로 쓰면 교사가 본 것과 저장된 것이 달라진다.
안내 방식(경고 문구 · 선택 막기)은 화면 담당이 정한다. 수집 자료에서 떨어진 조합의 반이 확인되면 집합 모델로 다시 정한다.

**연령 이름은 「만 N세」다**(ADR-038) — 화면 · 문서 모두 「만」을 붙인다. 생년월일로 계산한 나이가 아니라 반의 연령이다.

`[실측]` **계획안 369건에서 한 반이 떨어진 연령을 갖는 경우가 0건이다.** 파일명 표기가
반을 나누는 규칙을 그대로 보여준다 — 하이픈은 한 반의 범위, 쉼표는 반 구분자다.

```
만3-5세          86건   한 반 (3~5 혼합)
만3세,만4-5세     65건   두 반 (만3세반 + 만4-5세반)
만3세,만5세        7건   두 반 (만3세반 + 만5세반.  만4세반이 없는 원)
```

**`만3세,만5세` 7건은 전부 inst_025이고 한 반이 아니다.**
PDF 를 열면 1쪽이 「파랑새반 (3세)」, 3쪽이 「기린반 (5세)」로 반 이름과 계획안이 따로다.
`만3,4세+만4-5세`(inst_052)도 같은 형태다 — 계획안 문서가 원 단위라 여러 반이 한 칸에 적힌다.

**활동은 반대다.** 활동 참고자료에 강강술래·투호놀이가 `supported_ages: [3, 5]` 로 들어 있다.
**반은 범위, 활동은 점의 집합**이고 검사기가 이 둘을 다르게 읽어야 한다.

#### 동의 게이트

```
☑ 이 반 모든 아동의 법정대리인 동의를 받았습니다.
   동의 확인 전에는 아동 이름을 입력하지 않아요.
```

**체크 없이 입력되면 우리가 위법 상태를 유도한 것이 된다.** 교사 대부분은 동의서 절차를 모른다.
두 번째 줄이 「왜 체크해야 하는지」를 설명한다 — **이 줄을 빼지 않는다.**

**동의서 파일을 업로드받지 않는다** (ADR-004). 원이 개인정보처리자고 우리는 수탁자다(§26). 파일을 보관하면 우리가 처리자가 되고 보관·파기 의무가 따라온다.

**동의 확인 시각을 `classes.consent_confirmed_at` 에 저장한다.** 체크박스는 여전히 UI 게이트이고 **증빙이 아니다** — 위 두 줄이 그 역할이다. 컬럼을 두는 이유는 **복원**이다. 「나중에 입력할래요」로 건너뛰면 아동이 0명이라, 아동 수로 복원하면 교사가 들어올 때마다 다시 체크해야 한다.

| 상태 | 화면 |
|---|---|
| loading | 목록 스켈레톤 |
| empty | 반 0개 — "반을 추가해 주세요" + 추가 버튼 |
| success | 반 카드 목록 |
| error | 해당 카드에만 표시, 나머지 카드 유지 |

| | |
|---|---|
| 목적 | P1 일지 계열의 전제. 지금 받아두면 8주차에 다시 안 받는다 |
| 입력 | 반마다 — 아동 이름 입력 후 Enter / 「+ 추가」 |
| 표시 | 번호 · 실명 · 「삭제」. 가명 코드는 AI 로 보낼 때만 쓰고 화면에 보이지 않는다 |
| 건너뛰기 | **「나중에 입력할래요」** |

#### 받는 것은 이름 하나뿐

**생년월일·성별·건강정보를 받지 않는다.** 발달평가를 스펙아웃해서 생년월일을 쓸 기능이 없다.
이름만이면 「이름+생년월일+원명」 특정 조합이 애초에 안 생긴다.

#### 코드는 등록 시점에 발급한다

```
name  "이승석"   ← 실명. DB 에만
code  "승석"     ← LLM 에 나가는 값. 받침 있는 더미 한글 이름
```

**나중에 발급하면 이미 쌓인 기록을 다시 훑어야 한다.**
영문 토큰이면 조사가 복원 후 틀어진다 — `Child1이` / `Child2가`.

#### 「나중에」 의 나머지 절반 — 메인 배너

**버튼만 두면 교사가 잊는다.** S5 메인에 배너를 띄운다.

```
⚠ 햇살반 · 별빛반 아동 명단이 비어 있어요
  관찰일지를 쓰려면 명단이 필요합니다        [입력하기 →]
```

**문구가 "관찰일지를 쓰려면" 이어야 한다.** 명단이 없어도 **P0(계획안)는 정상 작동한다** — 계획안에 아동 이름이 안 들어간다. 지금 막힌 게 아니라는 뜻이 전달돼야 한다.

| 상태 | 화면 |
|---|---|
| loading | 명단 스켈레톤 |
| empty | 반별로 — "아직 등록된 아동이 없어요. 위에서 이름을 입력해 추가해주세요" |
| success | 번호 + 실명 목록. 하단에 "현재 N명의 아동이 등록되어 있어요" |
| error | 추가 실패 — 입력한 이름을 지우지 않는다 |

**개발 DB 에 실제 아동 실명을 넣지 않는다.** 테스트는 가명으로.

12칸을 채우게 하는 단계 하나

### S6a · 계획 문서 구성 — 첫 진입 1회

| | |
|---|---|
| 질문 1 | 월간 계획안을 쓰나요 |
| 질문 2 | 주간 계획을 어디에 쓰나요 |
| 선택지 | ○ 주간계획안(별도) ○ 주간보육일지 계획칸 ○ 일일보육일지 계획칸 |

`[출처]` 정부 보육일지 예시 ② — *"주간보육계획을 활용하되 계획과 실행 기록을 통합하여 작성"*. 원마다 다르다.

**「계획안 안 씀」 선택지가 없다.** 안 쓰면 이 버튼을 안 누른다. **선택지 하나가 화면 구조로 대체됐다.**

**질문 1 의 「안 씀」은 P0 에서 고를 수 없다**(ADR-030 PM-04). 주간은 월간을 거쳐서만 만들므로 월간을 안 쓰면 주간도 없다.
선택지는 보이되 비활성으로 둔다. **질문 2 는 P0 에서 「주간계획안(별도)」만 고를 수 있다**(ADR-030 「후속 결정」, 2026-10-20).
보육일지 계획칸 두 선택지는 비활성으로 둔다.

### S6b · 시작 방식

```
○ 처음부터 만들기
○ 있는 계획안 이어받기   → 연간계획안 파일 업로드      월별 주제형만(ADR-056). 놀이 중심형은 후속 — 그때까지 비활성(U-12)
+ 안전교육 연간계획안 업로드   (선택. 없으면 이수 시간 숫자 1개)
+ 원 자체 행사                (선택. 「나중에」)
```

**놀이 중심형의 「있는 계획안 이어받기」는 지원하는 것처럼 보이면 안 된다**(ADR-030 PM-11). 아직 만들지 않은 후속 기능이라(ADR-056 · U-12) 추측으로 읽게 된다.
비활성 표시를 하고 누르지 못하게 한다. 월별 주제형은 원문 일치 검사 + 교사 확인을 거쳐 가져온다(ADR-056). 부분 생성 결과는 저장하지 않는다(S7).

**연간 주제 12칸을 직접 입력받지 않는다** `[실측]` — 반마다 다르다. 반 4개면 48칸이라 아무도 안 쓴다.
업로드가 없으면 **연령별 기본 주제 12개를 제시하고 고치게 한다.** 빈칸 48개를 주지 않는다.

### S7 · 계획안 생성

| | |
|---|---|
| 입력 | 반 · 학년도 · **형식**(필수) |
| 결과 | `DRAFT` 로 저장 |

**형식** — 카드 둘, 「월별 주제형」 · 「놀이 프로젝트형」. 카드마다 결과 문서를 실제로 캡처한 그림(성진이 준 캡처 · 실제 아동 · 기관 이름 없음)과 이름을 보여 준다. 처음에는 선택하지 않으며, 하나를 골라야 만들 수 있다(`format` 필수, api-spec §4).
**놀이 프로젝트형을 고르면** 「사용할 기관 양식」 선택을 비활성으로 두고 요청에서 `form_id` 를 빼며 기관 양식 안내 문구는 보이지 않는다(ADR-043).
**놀이 프로젝트형 생성 중** 「놀이 프로젝트형은 네 구간을 차례로 만들어 몇 분 걸릴 수 있어요.」를 알린다. 월별 주제형은 기존 진행 표시를 쓴다.

**Rule 이 범위를 정하고, LLM 이 그 안에서 정하고, Rule 이 검사한다** (ADR-032 — ADR-014 보충). 연간은 승인된 주제 참고자료에서
그 달 · 반 연령에 맞는 주제를 고르고 LLM 이 문장을 쓴다. 생성이 먼저고 검사가 나중이다.
**같은 입력이라도 문구가 달라질 수 있다** — 결정론을 약속하지 않는다.

**요청 사항**(ADR-060 · api-spec §4 「요청 사항」) — 연간 · 월간 · 놀이 중심 월간 · 주간 생성 화면에 공통으로 둔다.

- 생성 버튼 위 여러 줄 입력 하나, 이름은 「요청 사항 (선택)」. 자리표시 「예: 숲에서 하는 놀이를 넣어 주세요」. 글자 수 n/300 을 보이고 300자에서 더 받지 않는다.
- 비워 두면 지금과 같다. 화면마다 따로 받는다 — 연간에 적은 것이 월간 입력에 미리 채워지지 않는다.
- 결과 화면: 반영한 칸에 「요청 사항」 표시(칸 근거에 `teacher_memo` 가 있는 칸). 머리에 적었던 요청 사항을 읽기 전용으로 보인다.
- 놀이 프로젝트형 연간은 놀이 고르기 · 후보 목록 카드에 글자 배지 대신 작은 ✦ 하나만 단다(`candidates[].memo_applied`, title · 스크린리더 이름 「요청을 반영한 놀이」). 고르기에 영향 없다(Human Decision 2026-11-05(하민)).
- `memo_notices` 가 있으면 결과 위에 「반영하지 못한 요청」 상자 — 줄마다 요약과 까닭(`OUT_OF_RANGE` 「참고자료 밖이에요」 · `RULE_CONFLICT` 「안전교육 · 기준과 맞지 않아요」 · `FIXED_CELL` 「위 계획안에서 가져오는 칸이에요」). 막지 않는다.
- 월간에서 안전교육 횟수 · 주 요청(「재난 안전 세 번」)은 만들 때 안전교육 줄에 이미 놓여 보인다. 더 붙은 후보도 후보 패널에 같은 범주 칩으로 나온다.
- 422 `VALUE_INVALID` `["memo"]` 면 입력 아래에 「아이 이름을 빼고 다시 적어 주세요」. 입력한 글은 지우지 않는다.

### S8 · 결과 확인 · 수정

**놀이 프로젝트형 결과**(ADR-043 §6, 성진 2026-10-25) — ① 「놀이 고르기」 · ② 「배치하고 다듬기」 두 단계이며, 단계 표시를 눌러 이동한다(③ 「전체 초안 보기」는 없앴다 — 확정은 ② 에서 한다). 단계를 바꾸면 화면 맨 위에서 시작한다(① 안의 「다음: … 고르기」는 제외). 구간마다 후보 10개 중 0~5개를 화면에서 고르며, 5개를 채우는 것은 후속 확정 계약의 목표다. 고른 놀이는 문서 배치 순서(고른 순서에서 ↑ ↓ 또는 끌어놓기로 변경)로 보여 준다. 화면 모양은 하민 #252 시안을 앱 토큰으로 옮긴 것이다 — 시안의 색 · 사이드바 · 저장 · 되돌리기는 옮기지 않았다.
①은 후보를 요약 카드(놀이명 · 지원 방향 앞부분 · 지원매체)로 보인다 — 열 수는 폭을 따라 두 열이고, 좁은 화면이나 오른쪽 패널과 나란히 놓아 폭이 모자랄 때(1024~1279px)는 한 열이다. 카드마다 「+ 선택하기」 ↔ 「✓ 선택됨」 토글(`aria-pressed`)과 「자세히 살펴보기」(읽기 전용 대화 상자: 지원매체 · 지원 방향 · 배움, 안에서도 선택 · 해제)를 둔다. 오른쪽 「고른 놀이」 패널은 1~5번 자리를 빈칸 없이 위에서부터 채우고 남은 자리에 「우리 반의 놀이를 골라 주세요」를 보이며, 줄마다 ×로 해제하고 구간별 n/5와 「배치하고 다듬기로」(막지 않음)를 둔다. 구간 탭 줄 오른쪽에 전체 「n/20개 선택」을 보인다. 5개를 고르면 남은 선택 버튼을 잠그고 「5개를 모두 골랐어요. 바꾸려면 하나를 빼 주세요.」를 알린다. 1024px 아래에서는 패널이 카드 아래로 쌓인다.
①에서 한 구간의 5개를 채우면 떠 있는 「다음: … 고르기」 버튼으로 다음 순서(끝에서는 처음으로)의 5개 미만인 구간으로 이동하고, 네 구간 모두 5개를 채우면 떠 있는 「배치하고 다듬기로」 버튼으로 ②로 이동한다. ②는 열이 시기 · 놀이명 · 지원매체 · 내용 및 지원 방향 예상하기 · 놀이를 통한 배움인 문서 모양 표다. 칸을 누르면 칸 전체가 연두색으로 강조되고 왼쪽 「내용 편집」 입력창에 나타난다(아래 칸 편집 · 배움 칸은 읽기만). 확정은 ② 에서 하고(아래 확정), 한글 내려받기는 확정본에서 한다.
②의 왼쪽은 두 탭이다 — 「내용 편집」(칸 입력창, 문서에서 칸을 누르면 이 탭으로 바뀐다)과 「선택한 놀이 n」(고른 목록 + 「넣을 수 있는 놀이」). 목록에서 ↑ ↓로 현재 구간 안의 순서를 바꾸고 「빼기」로 고르기를 푼다(확인 없음, 다시 고르면 맨 뒤). 1024px 이상에서는 목록의 줄과 문서의 놀이 행을 끌어 같은 구간 안에서 순서를 바꿀 수도 있다(i번째 줄에 놓으면 그 자리로 옮기고 나머지가 밀린다, 다른 구간에 놓으면 무시). 옮긴 뒤 「n번째로 옮겼어요」를 화면 안 안내(`role="status"`)로 알린다.
②의 「고른 놀이」 카드 아래 「넣을 수 있는 놀이」는 현재 구간에서 고르지 않은 후보를 후보 번호 순으로 보여 준다. 「넣기」는 문서 순서 맨 뒤에 고르고 해당 놀이명 버튼으로 초점을 옮기며, 5개를 채우면 모든 「넣기」를 잠그고 같은 안내를 보여 준다.
**고른 놀이 저장**(ADR-048 §1) — 고르기를 바꾸는 모든 곳(선택 · 해제 · ↑ ↓ · 끌어놓기 · 빼기 · 넣기)은 바꾸는 즉시 `PUT /api/plans/annual/{id}/selection` 으로 저장한다(저장 단추 없음, 네 구간 전부 보냄). 한 번에 하나만 보내고 응답 `revision` 을 다음 요청에 넘기며, 기다리는 동안 쌓인 변경은 최신 상태 하나로 합친다. 처음 상태는 서버 `selected` 라 새로고침해도 유지되고, `localStorage` · `sessionStorage` 에는 두지 않는다. 제목 옆 한 줄(`role="status"`)이 「저장 중…」 · 「저장됨」 · 「저장하지 못했어요」+ **[다시 저장]** 을 알린다. 실패해도 자동 재시도는 없고 못 보낸 변경은 화면에 남아 다음 변경이나 [다시 저장] 때 다시 간다. 409(`STALE_WRITE` · `ALREADY_CONFIRMED`)면 쓰던 변경은 버리고 최신 계획안을 다시 불러와 화면을 바꾸며(그동안 저장 표시는 「최신 내용을 다시 불러오는 중…」, [다시 저장] · 떠날 때 경고 없음) 「다른 곳에서 바뀌었어요. 최신 내용을 다시 불러왔어요.」를 보인다. 이 안내는 다음 고르기 변경이나 저장 성공 때 지운다. 보내지 못한 저장이 있을 때만 탭을 닫거나 새로고침하기 전에 브라우저 경고를 띄운다.
**칸 편집**(ADR-048 §2) — ②의 「내용 편집」 탭은 고른 후보의 놀이명 · 지원매체 · 지원 방향을 입력창으로 보인다(배움은 읽기 전용, 「배움은 누리과정 원문이라 고칠 수 없어요.」). 입력을 1초 멈추거나 칸을 떠나면(blur · 다른 필드 탭 · 다른 칸 · 구간 · 단계 이동) `PUT /api/plans/annual/{id}/cells/{item_id}` 로 저장하고, 마지막 저장값과 같으면 보내지 않는다. 입력 중 글은 오른쪽 문서에도 바로 보인다. 글자 수는 앞뒤 공백을 턴 「n/600자」이고, 비면 「비워 둘 수 없어요」, 600자를 넘으면 「612/600자 · 600자를 넘으면 저장되지 않아요」로 알리며(글자 수는 코드포인트) 저장하지 않고 떠날 때 마지막 저장값으로 되돌린다. 칸 저장과 고르기 저장은 같은 revision 이라 한 줄로 차례대로 보내며(고르기는 최신 네 구간 하나, 칸은 item_id 별 최신 값 하나로 합치고, 기다리는 고르기가 칸보다 먼저 나감) 실패 · 409 · 다시 저장은 고르기와 같다. 409 가 아닌 4xx 는 그 저장만 버리고 화면을 서버가 확인한 값으로 되돌린 뒤 「저장하지 못한 칸은 원래대로 되돌렸어요.」를 알린다(큐는 계속 보낸다). 떠날 때 경고는 보내지 못한 저장 또는 입력 중인 글이 있을 때 띄운다. 알려진 한계 — 요청이 나가는 동안 칸을 고친 뒤 그 후보를 빼면, 고르기가 먼저 나가 그 칸 편집은 저장되지 않고 원래대로 되돌아가며 되돌리기 목록도 비워진다. 서버가 거절(422)한 저장만 이렇게 버리고, 401 · 404 · 5xx · 네트워크 오류는 들고 있다가 [다시 저장] 때 다시 보낸다.
**되돌리기 · 다시 하기**(⟲ ⟳, 저장 표시 옆 버튼, 비면 꺼짐) — 고르기와 칸 글을 한 목록에서 최근 30번까지 되돌린다. 칸은 한 번 저장으로 보낸 단위가 한 걸음이다. 되돌리기는 이전 상태를 같은 두 API 로 다시 저장하며(이미 같으면 보내지 않음) 「되돌렸어요」 · 「다시 했어요」를 알린다. 새 변경이 오면 다시 하기 목록을 비운다. 목록은 화면 메모리에만 두고(브라우저 저장소 금지) 409 로 다시 불러오면 비워진다. 단축키는 없다 — 입력창 안 Ctrl+Z 는 브라우저 기본이다.
**확정**(ADR-048 §2 · §4, ② 에서) — 「확정하기」는 네 구간이 모두 5개일 때만 켜지고(아니면 꺼지며 위 부족 안내 한 줄이 이유다), 옆에 늘 「확정하면 고칠 수 없어요」를 둔다. 확인 창은 없다 — 누르면 입력 중인 칸을 떠나게 해 그 글을 저장 큐에 넣고, 남은 저장이 모두 끝나길 기다린 뒤 마지막 응답의 revision 으로 `POST /api/plans/annual/{id}/confirm`(본문 `{expected_revision}`)을 보낸다. 진행 중에는 「확정하는 중…」이고 중복 클릭은 막는다. 저장이 끝나지 않았으면 확정하지 않고 「저장하지 못했어요. 다시 저장한 뒤 확정해 주세요.」를 보인다. 422(`fields` 가 부족 구간 키)면 「9월~11월 · 12월~2월 구간이 5개가 안 돼요. 모두 5개를 골라 주세요.」와 그 구간 탭 강조, 409 `STALE_WRITE` 면 위 다시 불러오기, 그 밖은 서버 문구를 보인다.
확정본(`status` `CONFIRMED`)은 처음 열어도 읽기 전용 문서만 보인다 — 단계 표시 · ① ② · ⟲ ⟳ · 확정 버튼 · [다시 저장] 이 없고, 「확정됨」 배지와 「확정했어요. 확정한 계획안은 고치거나 지울 수 없어요.」 · 「한글 파일로 내려받기」 버튼(월별 주제형과 같은 hwpx · 누르면 「내려받는 중…」으로 꺼지고, 실패하면 서버 문구)을 보인다. 초안에는 버튼 대신 「확정하면 한글 파일로 내려받을 수 있어요.」만 둔다. 확정 취소는 없다.
② 와 확정본은 A4 세로(210×297mm, 여백 좌우 8mm · 위아래 7mm) 쪽을 세로로 쌓는다. 두 구간씩 새 쪽에서 제목과 표를 시작하며, 넘치면 제목 없이 머리글과 시기를 반복한 다음 쪽으로 놀이 행 전체를 옮긴다. 1024px 이상에서는 상단 고정 바 60px와 작은 여유를 뺀 높이의 문서 상자 안에서 스크롤하고, 그 아래에서는 문서가 화면을 따라 흐른다.
쪽 버튼은 해당 쪽으로, 구간 탭은 그 구간 첫 행으로 문서를 이동한다(②의 탭은 선택 칸도 푼다). 1024px 이상에서는 선택한 칸도 보이는 곳으로 이동한다. 1024px 아래에서는 놀이 또는 칸을 선택할 때 화면을 움직이지 않고 탭과 쪽 버튼만 이동한다. 가로 넘침은 문서 영역 안에서만 허용한다.
② 와 확정본은 확대 상태를 공유하며 기본은 「맞춤」이다. 「−」 · 「+」는 현재 배율을 10% 단위로 반올림한 뒤 10%씩 바꾸고 50~150%로 제한한다. 「맞춤」은 영역 너비에 맞춰 150%까지, 폰에서는 50% 아래로도 줄이며 실제 배율을 표시한다. 아래는 월별 주제형 기준이다.

```
① 생성 결과 표
② 칸 클릭 편집            ← 유일한 수정 수단
③ ~~이 칸만 다시 뽑기~~    ← 없앴다. 연간은 다시 뽑지 않는다(ADR-035 §4)
④ 출처 표시
⑤ 상태창
⑥ 확정 버튼   DRAFT → CONFIRMED
⑦ 변경 이력
```

**연간에는 「이 칸만 다시 뽑기」가 없다**(PROV-Y-A 도입 안 함, 2026-10-14 · ADR-030). 12개월 주제가 서로 이어져 한 달만 다시
뽑으면 앞뒤가 깨진다. 교사는 ②로 고친다. 월간의 칸 재생성(S11)과는 다르다. 번호는 비워 둔다 — 이미 공유한 ④~⑦을 밀지 않는다.

**전체 재생성을 만들지 않습니다** `[사용자]` — 교사가 만족한 항목까지 날아가고, LLM 은 비결정적이라 두 번째가 더 나쁠 수 있고, 되돌릴 수단이 없다.

audit        교사가 고쳤나 · 누가 확정했나   TEACHER_EDITED · CONFIRMED (⑦)
```

**출처를 값 하나(`TEMPLATE | TREND | AI | TEACHER`)로 그리지 않는다.** 세 축은 따로다(루트 `CLAUDE.md` · FR-207).
「AI」는 출처가 아니라 만든 방법이고, 「교사가 고쳤다」는 출처가 아니라 이력이다 — `generation` 이 아니라 Audit 을 본다.

**hwp 내보내기에서 점·패널을 전부 제거한다.** 제출 문서에 마커가 나가면 안 된다.
**표시 토글을 만들지 않는다.** 끄면 검증 없이 제출하게 된다.

**상태창** — 빈 칸 수 / 안전교육 미배정 영역 / 연속 3주 동일 활동

**⑦ 변경 이력 — 수락 기준** (api-spec §7-1)

- 이벤트마다 종류(생성 · 교사 수정 · 확정) · 시각 · 달(계획안 단위면 비움)을 보여 준다. 시각은 현지 시각으로 바꿔 보여 준다.
- 사람이 한 일은 `actor`(opaque id)로만 온다. **사람 이름을 지어 붙이지 않는다** — 담임 표시 이름이 확정자를 대신하지 않는다.
- 「무엇이 바뀌었나」(이전 값 → 새 값)는 서버가 `value_change` 를 주기 시작한 뒤에 보여 준다(ADR-030 PM-07 B, 연간 Backend Y3′).
  그 전에는 「고침」만 보이고 값은 보이지 않는다.
- 이력이 비어 있으면 빈 상태를 보여 준다. 이력 조회가 실패해도 결과 표 ①은 그대로 쓸 수 있다.

**⑥ 확정 — 수락 기준**

- 확정하면 상태가 `CONFIRMED` 로 바뀌고 ②가 막힌다. **확정 취소 버튼이 없다** — 확정을 풀려면 문서 보관함 「수정하기」(ADR-055 · 064).
- 두 번 눌러도 오류가 아니다 — 서버가 200 과 처음 확정 시각을 준다(api-spec §7).
- 확정은 제출 · 발송을 하지 않는다. 내보내기(S9)는 따로 누른다.

| 상태 | 화면 |
|---|---|
| error | 칸 수정 실패 — **그 칸만** 롤백. 나머지 수정분 유지 |

### S10 · 설정

성품인사(기본 off · 12칸) · 원 정보 수정 · 반 관리 · **트렌드봇 끄고 켜기**(기본 off · FR-808).

**반 관리 — 등록한 반을 고친다** (FR-108 · api-spec §2 반 수정 · ADR-062)

- 고치는 칸은 반 이름 · 연령 · 담임 이름 · 동의 체크박스다. **저장 버튼을 눌러야 서버로 간다** — 입력만으로는 보내지 않는다.
- 이름이 겹치면 이름 칸 아래 「같은 이름의 반이 이미 있어요」.
- 아이 명단이 있는 반에서 동의를 끄려 하면 Notice 「아이 명단이 있어 동의를 끌 수 없어요」. 체크는 그대로 둔다.
- 연령을 바꿔 저장했고 그 반에 연간 계획안이 있으면 Notice 「연령을 바꿨어요. 이미 만든 계획안의 연령은 바뀌지 않아요」. 막지는 않는다.
- 반 주인(담임 계정)을 바꾸는 칸은 없다. 원아 수는 받지 않는다.
- **설정과 온보딩은 따로 돈다**(2026-11-06). 설정의 원 정보 · 반 · 담당 반 · 아동 명단은 설정 화면 안의 쪽지에서 고치고, 온보딩(S3a 마지막 확인)으로 보내지 않는다.
- 쪽지에서 등록한 반의 네 칸은 **아직 잠겨 있다** — 위 규칙대로 여는 일은 다음 PR 이다. 반 추가 · 담당 반 고르기는 된다.
- **등록한 반에는 「삭제」를 두지 않는다.** 반 삭제 API 가 없어 지워도 서버에 남는다. 새로 추가하고 아직 저장 안 한 반만 지울 수 있다.

트렌드봇을 끄면 트렌드 화면이 「지금은 꺼져 있어요」로 바뀌고, 계획안 생성이 트렌드를
참고로 넣지 않는다. **이미 만든 계획안은 그대로 둔다** — 출처는 그때 그랬다는 기록이다.

**사이드바에는 트렌드 메뉴가 없다.** `/trends` 는 주소로만 들어간다(2026-10-17 확인).
그래서 「메뉴를 숨긴다」가 아니라 화면에서 막는다.

### S11 · 월간계획안 — 생성 · 확인 · 수정 · 확정

**1차 구현이 develop 에 들어왔다**(#187 — `/plans/monthly` · 양식 설정 `/plans/template`. 착수 근거 ADR-030 PM-09). 담당 승석. 기능은 FR-301 ~ FR-303, 계약은 api-spec §9-1 ~ §9-5.
**화면과 Template 사람 승인은 별개다** — 기반 Template v0.2.1 은 2026-10-20 승인됐고, 승인 대기인 v0.1.1 을 기반으로 하면 운영에서 생성이 막힌다(ADR-027).
경로 · 배치는 화면 담당이 정한다. 아래는 계약이 이미 정한 동작이다.

**화면 구성**

```
① 반 · 대상 달 고르기
② 양식 설정 확인          어느 버전을 어디서 가져왔나 (반 override / 원 기본 / 직접 선택)
③ 생성 버튼
④ 결과 — 주 축과 칸       칸 수는 서버가 준 만큼 그린다
⑤ 칸 편집 · 칸 다시 만들기 · 출처
⑥ 확정 버튼
⑦ ~~변경 이력~~           ← 화면에서 뺐다(2026-11-03). 이력은 서버에 남는다(api-spec §9-5)
```

**동작**

- **연간이 확정 전이면 만들지 않는다.** 409 `GATE_BLOCKED` → 「연간계획안을 먼저 확정해주세요」(없으면 「먼저 만들어 확정해주세요」).
  연간계획안으로 가는 길을 준다.
- **양식 설정은 고르는 순서가 정해져 있다** — 반 override → 원 기본 → 「선택 필요」(api-spec §9-2, ADR-034). 생성 요청에는 ②에서 보여 준
  **정확한 버전**을 그대로 담는다. 「선택 필요」면 READY 목록과 「Reference 기반으로 시작」을 보여 주고, 고르지 않으면 생성 버튼이 눌리지 않는다.
- **칸 수를 고정하지 않는다.** 4주 · 5주, 양식에 따라 칸이 달라진다. 43으로 박지 않는다(api-spec §9).
- **요청 사항**은 S7 과 같다(ADR-060). ③ 생성 버튼 위에 둔다.
- **편집 · 다시 만들기 · 확정은 받은 `revision` 을 같이 보낸다.** 409 `STALE_WRITE` 면 「다른 화면에서 바뀌었습니다」와 새로 불러오기를 준다 —
  고친 값을 지우지 않는다.
- **다시 만들 수 있는 칸만 버튼이 있다**(`focus` · `outdoor_play` · `basic_habit` · `goals`). 다른 칸은 422 `["item_id"]` 다.
  교사가 고친 칸을 다시 만들면 고친 값이 바뀐다 — 화면이 먼저 확인을 받는다. 이전 값은 서버 변경 이력(api-spec §9-5)에 남는다.
- **안전교육 칸이 비어 있을 수 있다** — 근거가 없으면 비워 두고 「근거 필요」로 보인다(api-spec §9-1 「안전교육」). 그 상태로도 확정된다.
- **검사 결과(findings)는 확정을 막지 않는다.** 무엇을 검사했는지와 무엇을 찾았는지를 따로 보여 준다(ADR-037).
- 확정 뒤에는 편집 · 다시 만들기가 막힌다(409 `ALREADY_CONFIRMED`). 이 화면에 확정 취소 버튼은 없다(문서 보관함 「수정하기」, ADR-055 · 064). 두 번 눌러도 200 이다.
- **놀이 프로젝트형 연간 반은 `/plans/monthly` 에서 갈라진다.** 고른 반의 연간 요약 `format` 이 `PLAY_PROJECT` 면 위의 만들기 · 편집 대신
  놀이 월간 목록(`GET /api/plans/monthly/play?class_id=`)을 보인다 — 달 · 상태(초안/확정) · 만든 시각(UTC → 현지), 누르면 `/plans/monthly/play/{id}`.
  기존 월간 만들기는 이 반에서 409 라 띄우지 않는다. 연간이 없거나 월별 주제형이거나 연간 목록을 못 읽으면 지금 화면 그대로다.
- **놀이 월간 만들기**는 월간 만들기 화면(`MonthlyNew`)에서 반 · 달과 **이번 달에 집중할 놀이**를 골라
  `POST /api/plans/monthly/play`(`emphasized_row_keys` 에 고른 놀이)로 만든다. 201 이면 그 계획안으로 간다.
  그 달 계획안이 이미 있으면(409) 만들기 대신 그 계획안 링크를 보인다. 진행 중에는 버튼을 막는다.

**4상태**

| 상태 | 화면 |
|---|---|
| loading | 생성은 수 초 ~ 수십 초 걸린다. 진행 표시 필수. 칸 다시 만들기는 그 칸만 흐리게 |
| empty | 그 달 월간이 없다 — 생성 버튼 |
| success | 주 축 · 칸 · 칸별 근거 · 상태 |
| error | `GATE_BLOCKED` → 연간으로 · `VALIDATION_FAILED ["profile_ref"]` → 다른 양식 설정 고르기 · `LLM_BUDGET_EXCEEDED` · `DEPENDENCY_UNAVAILABLE` → 운영 문의(재시도 버튼 없음) · `GENERATION_FAILED` → 재시도. **부분 결과를 저장하지 않는다** |

**수락 기준**

- 연간 미확정 반에서 생성이 막히고 연간으로 가는 길이 보인다.
- ②가 생성에 쓸 정확한 버전과 그 출처를 보여 준다.
- 서버가 준 칸 수만큼 그리고, 4주 · 5주 달이 모두 깨지지 않는다.
- 다른 화면이 먼저 고쳤을 때 고친 값을 잃지 않는다.
- 확정 뒤 수정이 막히고, 확정 취소 버튼이 없다.

### S-PM1 · 놀이 중심 월간 — 읽기 화면 (`/plans/monthly/play/[id]`)

연간이 놀이 프로젝트형인 반의 월간계획안(ADR-046)을 보여 준다. 초안은 칸 편집 · 자동 저장 · 되돌리기 · 확정(아래). 확정본은 읽기 전용이라 칸을 누르는 동작도 단추도 없다.
단건 `GET /api/plans/monthly/play/{id}` 하나로 그리고, 404 · 409(기존 월간 id) · 그 밖 오류는 서버 문구로 안내하며 「다시 불러오기」를 준다.
**문서 용지**(A4 한 장, 연간과 같은 확대 · 50~150% · 맞춤. 쪽 나누기는 계산하지 않는다): ① 머리표(주제 · 예상 기간 · 만 나이 · 반 이름 · 주제 선정 이유 — 반 이름은 앱 반 목록에서 `class_id` 로 읽는다)
② 예상되는 놀이 방향(함께 하는 활동 · 우리의 놀이 · 유아 예상 자유놀이) ③ 주별 표(열은 응답 `weeks`, 행은 기본생활습관 · 안전교육 · 소방대피/재난대비) ④ 건강 · 영양교육
⑤ 교사 입력(특성화 · 특별활동 시간표는 서버대로 글 칸 하나씩, 안내사항 · 생일 · 가정연계). 빈 칸은 빈 칸으로 그린다. 출처는 문서에 섞지 않는다.
**옆 패널**: 연간에서 고른 놀이(`parent.plays`)와 놀이 행마다 누리과정 연결 ID 칩(`content_ids`, 문구 없음). 확정본이면 「확정됨」 배지. 응답 `notices` 는 한 줄로 요약한다(예: 「안전교육 4주 미배치 · 건강 빈 칸」). 확정을 막지 않는다.
브라우저 저장소에는 아무것도 두지 않는다.
**칸 편집(초안만)**: 문서 용지의 칸을 누르면 그 칸이 강조되고 옆 패널 「칸 편집」에 입력창이 뜬다(연간 놀이 프로젝트와 같은 입력창 · 앞뒤 공백 털기 · 600자 · 1초 멈춤 또는 칸을 떠날 때 저장). **빈 값도 저장한다**(연간은 거절). 놀이 행 이름을 누르면 문서에 안 나오는 「설명」이 함께 뜬다. 확정본은 칸을 눌러도 아무 일이 없고 저장 표시 · 되돌리기 단추도 없다.
**자동 저장**: 칸 글 · 안전 배치 · 행 삭제 · 훈련 복사는 모두 **한 revision 줄로 하나씩** 보낸다(`lib/plan-generator/playMonthlyQueue.ts`). 서버가 확인한 값과 같은 칸 글은 보내지 않는다(서버는 같은 값을 422 로 거절한다 · 빈 값 → 빈 값 포함). 제목 옆에 저장 중 · 저장됨 · 저장하지 못했어요(+ 다시 저장). 422 는 그 칸만 서버 값으로 되돌리고 「저장하지 못한 칸은 원래대로 되돌렸어요.」, 409 는 최신 계획안을 다시 불러와 「다른 곳에서 바뀌었어요. 최신 내용을 다시 불러왔어요.」. 남은 저장이 있는 채 떠나면 브라우저 경고.
**되돌리기 ⟲ ⟳**: 칸 글 · 안전 배치 · 행 순서 · 습관 옮기기 · AI 후보 넣기 · 빼기 · 훈련 복사 · 시간표를 30번, 버튼만(단축키 없음). AI 후보 빼기를 되돌리면 원래 자리로 돌아온다. 훈련 복사를 되돌리면 칸 글이 복사 전으로, 다시 하기는 같은 후보를 다시 복사한다(2026-11-06). 옛 계획안의 행 삭제만 되돌리지 못하고, 일어나면 되돌리기 목록을 비운다.
**안전 배치(초안만, 옆 패널)**: 「안전교육 후보」에서 하나를 고르고 「N주차에 두기」로 주마다 둔다(같은 후보를 여러 주에 둘 수 있다 · 끌어 놓기는 아래 ADR-065). 「비우기」는 `null` 로 보낸다. 안전 배치는 되돌리기 ⟲ ⟳ 걸음에 들어간다.
**훈련 복사(초안만)**: 「소방대피 훈련 후보」의 「소방대피/재난대비 칸에 넣기」가 그 칸을 후보 글로 채운다. 칸에 쓴 글이 있으면 덮기 전에 확인 상자(「지금 쓴 글을 이 후보로 바꿀까요?」)를 거친다. 되돌리기 ⟲ 로 복사 전 글로 돌아간다.
**행 빼기(초안만, 「놀이 행의 누리과정 연결」 목록 · 문서 용지 밖)**: 행마다 「행 빼기」 → 확인 상자(「이 행을 빼면 되돌릴 수 없어요. 뺄까요?」) → 예. 되돌리기 목록을 비운다. 구역(함께 하는 활동 · 자유놀이)의 마지막 행이면 「빼면 행이 없어 확정할 수 없어요」 안내를 함께 보인다.
**AI 후보 고르기(ADR-065, `activity_pick` 이 있는 계획안만 · 초안만)**: 함께 하는 활동 · 유아 예상 자유놀이는 AI 후보 8개씩 중 **정확히 5개**를 고른다. 고르기는 놀이 중심형 연간 「놀이 고르기」와 같은 3패널 판(**활동 고르기**: 왼쪽 후보 8 · 가운데 「자세히 보기」와 [이 활동 고르기]/[✓ 골랐어요] · 오른쪽 점선 5칸과 ✕ 빼기, 머리 오른쪽에 목록 탭 `함께 하는 활동 n/5 | 유아 예상 자유놀이 n/5`)이다. 어느 목록이든 5개가 안 된 채로 계획안을 열면(생성 직후 포함) 이 판부터 열리고, [유아 예상 자유놀이 고르러 가기 →] → [문서 만들기 →] 로 문서 편집으로 간다(함께 하는 활동에서는 「지금까지 고른 것으로 문서 만들기」도 있다). 문서의 「+ AI 후보에서 고르기」(「n개 더 고르기」) 칸과 확정 창 빈칸 목록의 고르기 줄도 이 판을 그 목록으로 연다. 문서에 넣은 AI 후보 행을 누르면 옆 패널 「AI 후보」 탭에 그 목록 후보가 생성 순서대로 뜬다(넣은 것은 표시 · [넣기]/[빼기] · `n/5 골랐어요`). 5개가 차면 [넣기]를 흐리고 「다 골랐어요. 바꾸려면 하나를 빼 주세요.」.
넣지 않은 후보는 보기만 하고, 넣은 뒤 문서에서 눌러 고친다. AI 후보로 넣은 행은 「이 활동 빼기」 대신 「AI 후보」의 [빼기]로 후보에 돌려보낸다(고친 글도 함께). 교사가 직접 더한 행은 5개에 들고 예전처럼 뺀다. 넣기 · 빼기는 되돌리기 ⟲ ⟳ 에 든다.
5개가 안 된 목록이 있으면 확정 창이 먼저 「함께 하는 활동 · 자유놀이는 AI 후보에서 5개씩 골라야 확정할 수 있어요」를 말하고, 남은 빈칸 목록 맨 위에 고르기 줄을 둔다. 옛 계획안(`activity_pick` null)은 위 행 빼기 그대로다.
**끌어 옮기기(ADR-065)**: 기본생활습관 칸은 손잡이로 다른 주에 놓으면 두 주의 칸이 맞바뀐다(`PUT .../habits/order` · 되돌리기 ⟲ ⟳ 에 든다). 「AI 후보」의 안전교육 후보 카드는 문서의 안전교육 주 칸이나 「넣은 안전교육」 줄에 끌어 놓으면 그 주에 들어간다. 「넣은 안전교육」의 「N월 n주」 줄은 눌러(키보드 포함) 그 주를 고를 수 있다. 습관과 안전교육 사이로 놓는 것은 무시한다.
**확정**: 초안 위에 「확정하기」. 누르면 열린 입력창을 닫아 저장을 큐에 넣고, 새 변경을 막은 채 **남은 저장이 끝난 뒤** 그 revision 으로 확정한다. 저장이 하나라도 실패했으면 확정하지 않고 「저장하지 못했어요. 다시 저장한 뒤 확정해 주세요.」.
서버 422 는 부족한 곳을 한 줄로 안내한다(예: 「확정하려면 채워야 할 곳이 있어요: 놀이 주제 · 이름 없는 함께 하는 활동 1개 · 누리과정 연결을 1~3개로 맞춰야 하는 행 2개」). 409 는 위 「다시 불러오기」와 같고, 다시 불러오기마저 실패해도 안내를 보이고 변경을 다시 받는다.
성공하면 응답 계획안으로 화면이 바뀐다 — 확정본은 읽기 전용(칸 편집 · 저장 표시 · 되돌리기 없음, 「확정됨」 배지). 이 화면에 확정 취소 버튼은 없다(문서 보관함 「수정하기」, ADR-055 · 064).
변경 이력은 화면에 보여 주지 않는다(2026-11-03, 월별 주제형 월간 S11 ⑦과 같다). 서버는 그대로 남기고 `GET .../audit` 로 읽을 수 있다.
저장이 409 로 멈춰 최신 계획안을 다시 불러오는 동안, 또 확정을 진행하는 동안은 위 단추(안전 배치 · 훈련 복사 · 행 빼기)와 칸 저장을 모두 잠근다. 확정본에는 이 패널 · 단추가 없다.

# TASK 2 후속 화면 계약 (2026-10-19)

S-J1: 핸들로 끌 때 시간·일과 이름·활동계획·활동실행을 담은 카드 전체가 프리뷰가 된다.
원본은 흐리게 표시하고 다른 카드의 상·하단에 삽입선을 보인다. ↑↓ 버튼도 유지한다.
시각은 01~12시, 00~55분(5분 간격), 오른쪽 AM/PM 토글(기본 AM)이다. 시간 지우기는 null로 저장한다.
기존 5분 간격이 아닌 분은 기존 값 임시 항목으로 보이며 자동 반올림하지 않는다.
`시간순 정렬`은 현재 입력을 보존하면서 시작·종료의 안정 정렬을 명시적으로 수행한다.
서버의 수동 순서는 조회 시 유지하고 정렬 결과는 저장을 눌러야 position에 반영한다.

> **2026-11-10 — 위 S-J1 문단은 지난 계약이다.** 끌기 · ↑↓ · 01~12시 + AM/PM 칸 · 저장 단추가 없어졌다.
> 순서는 시간이 정하고, 시간은 시계판 한 칸이며, 쓰는 대로 임시본에 둔다(S-J1 「바뀐 것」 · ADR-084).

S-J2/보관함: 검토 체크박스는 하나이며 API checks 세 필드는 유지한다. 기본 검사 결과는
펼치기/접기 가능하고 본문을 바꾸면 기존 결과를 폐기한다. 확정 문서에 삭제 버튼은 없다.
mock 생성은 본문 밖 테스트 모드 안내로 표시한다. 본문 섹션은 사실 → 해석 → 지원이다.
확정된 stale 일일 보육일지를 선택하면 기존 본문보다 먼저 모든 근거의 수정 전/후,
변경 없음 또는 원본 없음 상태를 표시한다. 해석·지원은 검토 영역에서 직접 편집할 수 있다.
교사가 단일 확인을 체크하고 `변경사항 반영하고 재확정`을 누르면 서버 요청 하나로 처리한다.
대기 중 입력/중복 실행을 막고, 실패 시 기존 확정본과 검토 입력을 보존하며 오류를 보여준다.
근거 다시 비교하기로 새 토큰을 받을 때 체크를 초기화한다. 누락된 원본은 **처리를 고르기
전까지** 재확정을 막는다 — 아래 「삭제된 근거」 영역에서 제외·대체를 고르면 같은 요청으로
함께 보낸다. 응답을 못 받아 같은 요청을 다시 보내도 같은 결과 하나로 끝난다.
재검토 경고는 기존 본문 아래에 표시하며 stale 자체로 DRAFT로 바꾸지 않는다.

**초안이면서 근거가 삭제된 경우에도 같은 검토 영역이 뜬다.** 확정을 취소하면 비교·재확정
경로가 닫혀 교사가 「문서를 지우고 새로 만들어주세요」에 갇히던 자리다. 초안에서는 삭제된
근거의 처리(제외 · 같은 반·같은 날짜의 다른 일과로 대체)만 고르고 `변경사항 반영하기` 를
누른다 — 해석·지원 편집칸과 단일 확인 체크박스는 띄우지 않는다. 반영해도 문서는 DRAFT 로
남고, 교사가 본문에서 평소처럼 검토하고 확정한다. 이 영역이 떠 있는 동안에는 실패할
`[변경된 근거 반영]` 버튼을 띄우지 않는다. 사라진 근거가 없는 초안은 예전 버튼 그대로다.
