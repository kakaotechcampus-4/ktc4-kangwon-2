## 핵심 기능 — 계획안과 일지 둘 다 (2026-10-28 PM 결정)

멘토 지적: 평가 기준이 핵심 기능을 **하나로** 보는 것 같다(단수형 표기).
**둘 다 가져간다.** 쪼개진 기능 두 개가 아니라 **한 해가 도는 한 바퀴**라서다.

```
계획안   연간 → 월간 → 주간        앞으로 할 것.  미래 예정이라 위조가 성립 안 함
  ↓                                확정해야 다음 층을 만든다
교사가 한다  관찰 기록 · 일과 기록   실제로 일어난 것
  ↓
일지     일일·주간 보육일지 · 관찰일지 · 영유아 평가   교사가 준 사실만으로
  ↓
평가제 점검   원이 받는 기관 평가에 빠진 게 없나
```

**계획과 기록이 같은 자료를 쓴다.** 누리과정 · 반 정보 · 주제가 계획안에서 내려오고,
일지가 그 주제 아래 쌓인다. 둘을 떼면 교사가 두 번 입력해야 한다.

한 줄로 말하면 — **「계획부터 일지까지, 교사가 원에 내는 문서 한 해치를 한 곳에서」.**

| 축 | 무엇 | 지금 |
|---|---|---|
| 계획안 | 연간 → 월간 → 주간, 놀이 프로젝트형 포함 | 코드량 가장 큼. PR #223~#253 |
| 일지 | 관찰·일과 기록에서 문서 4종 | 4종 다 있음. 3층 규격 · 3단 게이트가 여기 걸린다 |

**둘을 묶어서 생기는 질문 둘** — 평가 때 나올 것이라 미리 적는다.

1. 「범위가 넓어 둘 다 얕은 것 아닌가」 → 답은 **같은 방어 장치가 둘을 지난다**는 것이다.
   출처 3축 · 3단 게이트 · 아동 코드 치환 · 사실기록형 생성 금지가 계획안과 일지에 모두 붙어 있다 → [05](05-agentic-implementation.md) · [07](07-guardrails.md)
2. 「시연은 무엇으로 하나」 → **한 반 한 주를 끝까지** 돈다. 주간 계획안 확정 → 그 주 일과·관찰 기록 → 주간 보육일지 → 평가제 점검.
   기능 목록을 훑지 않는다.
