## 통과 조건을 먼저 정했다 — 3층 규격

```
① 사실   교사가 입력한 관찰 사실.  AI 가 추가 못 함
② 해석   ①에 있는 사실만 근거로
③ 지원   다음에 어떻게 지원할지
```

- **②가 ①에 없는 사실을 쓰면 반려**
- **③이 비면 반려**
- [CLAUDE.md](../../CLAUDE.md) §3층 규격 · ADR-024 `024-journal-three-layers-merge-on-paper.md`

**왜 이 세 칸인가** — 같은 판매자의 두 자료에서 평가어가 60배 차이 났고, 차이는 「해석과 평가」 칸의 유무뿐이었다
([docs/미확정사항.md](../미확정사항.md) L80). 칸 구조가 교사의 글을 바꾼다는 실측에서 나왔다.

## 어떻게 재는가

| 방법 | 무엇을 잡나 | 어디 |
|---|---|---|
| 스키마 게이트 | 칸 이름·개수 | `backend/app/shared/gates/sections.py` |
| 추출 대조 | 이름·수량·날짜가 원문과 다름 (모델 안 부름) | 같은 곳 |
| LLM Judge | ①②③ 관계 — 근거 없는 해석, 빈 지원 | `test_evaluation_judge.py` |
| 벤치 | 실제 문장으로 돌려본 결과 | `test_bench_monthly_luna_guard.py` · `test_bench_weekly_luna.py` |
| 검증 리포트 | 월간 생성이 무엇을 통과·반려했는지 | ADR-037 `037-monthly-verification-report-contract.md` |

- 서술 기준을 글로 먼저 적었다 — [docs/references/관찰일지-서술-기준.md](../references/관찰일지-서술-기준.md) ·

## 품질에 손대지 않기로 한 것

- **평가제 자체점검은 누락 탐지만.** 통과 판정을 LLM 이 하지 않는다 — ADR-019 · ADR-022
- 규칙 엔진은 **고르는 게 아니라 검사한다** — ADR-014

## 아직 아닌 것

- **실제 AI 모드(`real`)에서 문장 품질을 본 기록이 없다.** 2026-10-21 점검은 전부 `mock` 이었다 —
  [docs/mentor-pilot-guide-2026-10-21.md](../mentor-pilot-guide-2026-10-21.md)
