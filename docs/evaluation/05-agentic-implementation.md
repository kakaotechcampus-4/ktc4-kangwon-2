## Rule 이 범위를 정하고, LLM 이 그 안에서 정하고, Rule 이 검사한다

```
Rule   허용 범위    승인된 후보 · 근거 · 제약 · 칸 구조 · 법정 기준
LLM    범위 안에서  값의 의미 내용을 고르고 구성하고 쓴다
Rule   검사         계약 · 근거 · 연령 · 법정 기준을 어겼는지
```

- ADR-032 `032-rule-sets-range-llm-decides-rule-verifies.md` — 연간 · 월간 · 주간 공통
- **LLM 은 문장만 다듬는 역할이 아니다.** 범위 밖(승인 목록에 없는 id · 근거 없는 사실 · 통과 여부)은 안 정한다
- 법정 시수처럼 틀리면 안 되는 값은 규칙 엔진이 원문과 **문자열로** 대조한다

**결정이 바뀐 기록이 남아 있다** — ADR-005(「LLM 은 문장화만」) → ADR-014 가 대체 → ADR-032 가 보충.
ADR-003 의 「P0a 는 결정론적이라 golden set 이 성립한다」도 같이 깨졌고, 그 사실을 적었다.

## 3단 게이트 — 순서 고정

```
1  스키마 게이트   출력 형식 강제. 칸 이름·개수 불일치면 반려
2  추출 대조      고유명사·수량·날짜를 원문과 문자열 비교.  모델 안 부름
3  LLM Judge      ①사실 ②해석 ③지원 관계 검사
```

- **2단을 안 건너뛴다.** 비용 0 인데 숫자·이름 오류를 가장 많이 잡는다
- **3단을 1단보다 먼저 안 돌린다.** 형식 깨진 출력을 Judge 에 넣으면 비용만 나간다
- 검사는 `backend/app/shared/gates/` 한 곳에서만. 기능별로 안 만든다 — `sections.py`

## 호출 구조

- **문서 단위 배치.** 연간은 12개월, 월간은 한 달, 주간은 한 주를 한 번에.
  칸 단위로 부르면 시스템 프롬프트가 칸 수만큼 반복돼 **15배 이상** 나간다 — [CLAUDE.md](../../CLAUDE.md) §LLM 예산
- 모든 호출이 `backend/app/shared/llm/client.py` 한 곳을 지난다
- 성공한 호출마다 `llm_usage` 한 줄(모델 · 토큰 숫자 넷). **프롬프트·응답 내용은 안 찍는다** — ADR-036 · `test_llm_usage_log.py`
- 모델 고정 · temperature 안 씀 — ADR-023
- 연간(놀이 프로젝트형)은 실제 스트리밍. 구간마다 120초 감시 타이머 — PR #229

## 모델을 안 부르고 검증한다

CI 는 **가짜 LLM** 으로 돈다 — ADR-023.
고정한 응답에 대해 애플리케이션이 무엇을 하는지를 고정하고(`p0-planning/tests/finalization/golden/`),
**모델이 쓴 문장은 기대값으로 굳히지 않는다.** 문장 품질은 사람이 보는 실측 점검이 맡는다 → [06](06-ai-quality.md)
