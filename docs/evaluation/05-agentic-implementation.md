**멘토 심사 기준(기술·개발 중심) ⑤ Agentic AI 설계·구현 — 15점**

> 단계 분기·도구 연동·상태 관리·예외 처리가 실제로 구현되어 워크플로우가 끝까지 안정적으로 돌아가는가

## Rule 이 범위를 정하고, LLM 이 그 안에서 정하고, Rule 이 검사한다

```
Rule   허용 범위    승인된 후보 · 근거 · 제약 · 칸 구조 · 법정 기준
LLM    범위 안에서  값의 의미 내용을 고르고 구성하고 쓴다
Rule   검사         계약 · 근거 · 연령 · 법정 기준을 어겼는지
```

- ADR-032 `032-rule-sets-range-llm-decides-rule-verifies.md` — 연간 · 월간 · 주간 공통
- **LLM 은 문장만 다듬는 역할이 아니다.** 범위 밖(승인 목록에 없는 id · 근거 없는 사실 · 통과 여부)은 안 정한다
- 법정 시수처럼 틀리면 안 되는 값은 규칙 엔진이 원문과 **문자열로** 대조한다

**결정이 바뀐 기록이 남아 있다** — ADR-005(「LLM 은 문장화만」) → ADR-014 가 대체 → ADR-032 가 보충.
ADR-003 의 「P0a 는 결정론적이라 golden set 이 성립한다」도 같이 깨졌고, 그 사실을 적었다.

## 3단 게이트 — 순서 고정

```
1  스키마 게이트   출력 형식 강제. 칸 이름·개수 불일치면 반려
2  추출 대조      고유명사·수량·날짜를 원문과 문자열 비교.  모델 안 부름
3  LLM Judge      ①사실 ②해석 ③지원 관계 검사
```

- **2단을 안 건너뛴다.** 비용 0 인데 숫자·이름 오류를 가장 많이 잡는다
- **3단을 1단보다 먼저 안 돌린다.** 형식 깨진 출력을 Judge 에 넣으면 비용만 나간다
- 검사는 `backend/app/shared/gates/` 한 곳에서만. 기능별로 안 만든다 — `sections.py`

## 호출 구조

- **문서 단위 배치.** 연간은 12개월, 월간은 한 달, 주간은 한 주를 한 번에.
  칸 단위로 부르면 시스템 프롬프트가 칸 수만큼 반복돼 **15배 이상** 나간다 — [CLAUDE.md](../../CLAUDE.md) §LLM 예산
- 모든 호출이 `backend/app/shared/llm/client.py` 한 곳을 지난다
- 성공한 호출마다 `llm_usage` 한 줄(모델 · 토큰 숫자 넷). **프롬프트·응답 내용은 안 찍는다** — ADR-036 · `test_llm_usage_log.py`
- 모델 고정 · temperature 안 씀 — ADR-023
- 연간(놀이 프로젝트형)은 실제 스트리밍. 구간마다 120초 감시 타이머 — PR #229

## 모델을 안 부르고 검증한다

CI 는 **가짜 LLM** 으로 돈다 — ADR-023.
고정한 응답에 대해 애플리케이션이 무엇을 하는지를 고정하고(`p0-planning/tests/finalization/golden/`),
**모델이 쓴 문장은 기대값으로 굳히지 않는다.** 문장 품질은 사람이 보는 실측 점검이 맡는다 → [06](06-ai-quality.md)

## 실패했을 때 — 재시도 · 수리 · 폴백을 한 곳에 (2026-11-04 정리)

**일시 오류만 서버가 한 번 더 부르고, 그래도 실패하면 세 갈래로 나눠 화면에 그대로 올린다** —
`backend/app/shared/llm/errors.py`. 2026-11-04 에는 「같은 요청을 다시 보내지 않는다」였는데 ADR-076(2026-11-09)이 바꿨다 —
엘리스 크레딧이 넉넉하고, 요청 하나의 호출 수에 상한을 둬서 두 번 과금이 커지지 않는다.

```
설정 없음 (real 인데 주소 · 키가 없다)   503 DEPENDENCY_UNAVAILABLE   다시 눌러도 같다 → 「운영 문의」
한도 · 키 삭제 (엘리스 401 · 403 · 429)  503 LLM_BUDGET_EXCEEDED      다시 눌러도 같다 → 「운영 문의」
호출이 깨졌다 · 답이 계약을 어겼다         500 GENERATION_FAILED        → 「다시 시도」
```

셋을 한 코드로 뭉치면 「운영 문의」 자리에 「다시 시도」가 떠서 교사가 같은 실패를 되풀이한다.

| 장치 | 어디 | 내용 |
|---|---|---|
| 시간 제한 | `client.py` `TIMEOUT_SECONDS = 30` | 한 호출 30초. 연간 놀이 프로젝트형 스트리밍은 구간마다 120초 감시(PR #229) |
| 자동 재시도 | `client.py` `post_json` — ADR-076, `test_llm_retry.py` | 연결 실패 · 시간 초과 · 502 · 503 · 504 · 429 를 **한 번만** 더 부른다(1초 뒤, 429 는 `Retry-After` 5초 이하면 그 값). 401 · 403 · 크레딧 소진 표시가 있는 429 · 500 · 스트림은 다시 부르지 않는다. 끝내 실패하면 위 세 갈래 그대로 |
| 호출 상한 | `client.py` `MAX_LLM_CALLS_PER_RUN = 6` — ADR-076 | 생성 요청 하나가 LLM 을 6번 넘게 부르면 7번째는 부르지 않고 500. 월 예산 차단(2026-09-21 무효)이 아니라 요청 하나 안의 폭주를 막는다 |
| 수리 1회 | 계획안(월간 v1 · 놀이 월간 · 주간) — ADR-046 §5, `elice_openai_monthly.py` | 답이 계약(스키마 · 근거)을 어기면 **한 번만** 고쳐 달라고 다시 부른다. 재시도가 아니라 수리다. 수리 뒤에도 어기면 500 |
| 부분 저장 없음 | 일지 초안 `documents/draft.py` | 한 칸이라도 비면 실패로 끝내고 아무것도 저장하지 않는다 — `test_create_document_saves_nothing_when_generation_fails` |
| 부르기 전 멈춤 | `require_config` · `draft.py` | real 인데 설정이 없으면 호출 전에 멈춘다. 아동 이름 치환에 실패해도 호출하지 않는다 |
| 폴백 | `is_mock()` | 기본이 mock — 키 없이 real 이 돌면 매번 401 을 받고 원인을 못 찾는다. 관찰일지 배움 칸이 쓰는 누리과정 전사본을 못 읽으면 그 목록 없이 초안을 만든다(PR #373) |
