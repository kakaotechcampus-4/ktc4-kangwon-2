## 1. 왜 행 이름까지 보나

`source_section` 만으로 고르면 다른 칸의 자료가 섞인다 `[실측]`.

- 실내놀이 섹션 안에 대·소집단 행, 원의 특별활동 · 특성화 프로그램, 행사 · 일정 문구, 연간 생활습관 서술이 들어 있다.
- 대체놀이 섹션에는 「바깥놀이」 「실외놀이」 같은 행 이름이 많다. **원본을 보면 대부분 그 바깥놀이 행 안의 [대체] · [실내대체] 칸**이다(§5).
  행 이름만으로 「대체가 아니다」라고 판단한 첫 판의 제외는 틀렸다.
- 행 이름 자리에 활동 문구가 들어간 행이 많다. 원본을 보면 **추출 오류가 아니라 영역 이름 칸이 없는 표**에서 첫 칸이 행 이름으로 잡힌 것이다.
  그 행이 어느 블록(실내놀이 · 활동)에 있는지로 분류했다.

월간 근거 분류와 같은 방식을 쓴다 — `(source_section, source_label)` **정확 일치**, 목록에 없으면 `EXCLUDED`. 월간 분류 파일은 바꾸지 않는다.

## 2. 상태 구분 · 읽는 법

| 상태 | 뜻 | JSON |
|---|---|---|
| **허용 후보** | 원본 · Evidence 로 그 칸의 근거로 맞다고 본 행. 사람이 승인하면 쓴다 | `entries` 에 있음 |
| **확인 필요** | 미승인 · 확인 부족 · 쟁점으로 **지금은 쓰지 않음**. 검토자가 허용으로 바꿀 수 있다 | 없음 (`EXCLUDED`) |
| **부적합** | 원본 · Evidence 내용을 보니 **그 칸의 근거로 맞지 않음**(행사 · 특별활동 · 장소 목록 · 잘린 문구 등) | 없음 (`EXCLUDED`) |

- **검토용 묶음은 보여 주기 위한 것이다.** 띄어쓰기만 다른 행 이름을 한 묶음으로 보이지만, 실행은 원문 행 이름 하나하나를 정확 일치로 쓴다.
- 「원본의 상위 영역」은 원본 표에서 그 행이 속한 블록이다. 원본을 대조하지 않은 행은 그렇다고 적었다.
- 「건 · 기관」의 괄호는 품질 필터(TEXT_LAYER · VALID)를 통과한 건수다.

## 4. 승인하면 근거가 얼마나 남나

월간 생성 코드와 **같은 품질 필터**로 다시 셌다 `[실측]`.

- 품질: `machine_readability == TEXT_LAYER` 이고 `extraction_quality == VALID` — `general_grounding_eligible`(`p0-planning/src/ssuksak/planning/evidence/models.py:157`), 분류 블록이 이 필터를 쓴다(`retrieval/retriever.py:163-166`).
- 같은 달만(`retriever.py:164`). 연령은 W1 §7-1 의 월간 연령 단계(같은 단일 연령 · 요청 연령에 든 단일 연령 · 연령이 겹치는 혼합 페이지), **연령 모름 제외**.

## 8. 원본 대조 기록

- 방법: Evidence 레코드의 `source_path` · `page` 로 원본 PDF 를 로컬에서 열고(pypdf layout 추출) 그 활동 문구가 있는 줄과 행 머리글 · 블록을 확인했다.
  원본은 저장소에 복사하지 않았고 외부로 보내지 않았다. 기관은 이 문서 안에서만 쓰는 번호(I01 …)로 적었다.
- 대조한 행과 페이지는 §5 · §7 의 「근거」 칸에 record_id 로 적었다. 기관 양식별로 대표 페이지를 1개 이상 봤다.
- **NOT_VERIFIED** — 원본 위치를 찾지 못했거나 대조하지 않은 것:
  - 「기존 허용 유지 — NOT_VERIFIED(원본 미대조)」로 적은 허용 후보 행(§7). 행 이름 · Evidence 분류 기준으로 유지했다.
  - I08 「- [미술] …」 「- [과학] …」 6개, I11 「바깥놀이 (대체) …」 4개, I17 「이야기 나누기 [과학] …」, I31 「좋은 언어」.

## 9. 검토 방법 · 승인 뒤

1. §6 쟁점마다 고른다. 고르지 않으면 지금처럼 제외다.
2. §7 의 허용 후보에 잘못 들어간 행이 없는지, 확인 필요에서 허용으로 바꿀 행이 있는지 본다.
3. 바꿀 것이 있으면 이 문서와 JSON `entries` 를 같이 고친다(승인 전 초안 수정).
4. 승인은 JSON `review` 의 `domain_owner_approval` · `approved_by` · `approved_at` 만 바꾼다 — Template 승인 절차(ADR-027 §5)와 같은 방식. 승인자 id 는 `reviewer_<role>_<sequence>`.
5. 승인 뒤 W3c 가 이 분류를 읽어 세 칸을 생성한다. 그 전까지는 코드 변경 없이 빈 칸이다.

**하지 않은 것.** Evidence Store 수정 · 월간 분류 변경 · 코드 변경 · 승인 상태 변경 · 원본 복사 · 외부 LLM 전송.
