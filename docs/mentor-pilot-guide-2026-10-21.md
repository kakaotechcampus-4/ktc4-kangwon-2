## 멘토님께 전달할 요청문

> 쌤플은 만3~5세반 교사가 입력한 기록을 바탕으로 보육 문서 초안을 만드는 서비스입니다.
> 가상의 반과 아동으로 관찰일지와 보육일지를 각각 한 건 만들어 봐주세요.
> 처음 보는 화면에서 다음에 누를 곳을 찾을 수 있는지, 사실·해석·지원의 구분이 이해되는지,
> 입력에 없는 내용이 추가되는지, 수정하고 확정하는 과정이 자연스러운지 봐주시면 좋겠습니다.
> 계획안과 평가 준비는 시간이 남으면 이어서 부탁드립니다.

핵심 흐름 예상 15~20분, 계획안·평가 준비까지 25~30분으로 잡는다. 시간은 진행 제안이며 실제 교사 사용 시간 측정값이 아니다.

## 1. 가입·첫 설정

| 순서 | 누를 곳·입력 | 확인할 결과 |
|---|---|---|
| 1 | 소개 화면의 `우리 반으로 시작하기` 또는 `시작하기` | 회원가입 화면 |
| 2 | 선생님 이름·테스트 이메일·비밀번호·비밀번호 확인 → `회원가입` | 가입 완료 |
| 3 | `로그인하러 가기` → 이메일·비밀번호 → `로그인` | 원 정보 설정 |
| 4 | 원명 `파일럿어린이집`, 원장 이름 `가상원장`, 시·도와 시·군·구 → `다음` | 반 정보 설정 |
| 5 | 반 이름 `햇살반`, `만 4세`, 담임 이름 입력 | 입력값 유지 |
| 6 | 테스트용 가상 아동 명단으로 동의 확인 흐름 확인 → `다음` | 아동 명단 화면 |
| 7 | 아동 추가에 `가나다` 입력 → `+ 추가` → `설정 완료` | `우리 반` 홈 |

실제 아동 이름이나 민감한 관찰 내용은 이번 파일럿에 사용하지 않는다. 여러 반을 넣었다면 담당 반을 확인한다.

## 2. 관찰 기록 → 관찰일지

| 순서 | 누를 곳·입력 | 확인할 결과 |
|---|---|---|
| 1 | 왼쪽 `관찰 기록` | 관찰 기록 입력 화면 |
| 2 | `담당 반`에서 햇살반, `아동`에서 가나다 선택 | 해당 반 아동만 표시 |
| 3 | 날짜·영역 확인, `실제로 관찰한 사실` 입력 | 아래 테스트 문장 사용 가능 |
| 4 | `관찰 기록 저장` | 저장 완료 안내와 목록의 기록 |
| 5 | 저장한 기록 카드의 `관찰일지 만들기` | 반·아동·기간·근거가 선택된 문서 생성 화면 |
| 6 | `초안 만들기` | 사실·해석·지원 세 부분 |
| 7 | 사실을 원문과 비교하고, 해석·지원 내용을 직접 수정 | 사실은 읽기 전용, 해석·지원은 편집 가능 |
| 8 | 검토 확인 체크 → `검토 완료 · 문서 확정` | 교사 확정 상태 |
| 9 | `한글 파일로 내려받기` | `.hwpx` 파일 다운로드 |
| 10 | `보관함 보기` 또는 문서 보관함에서 문서를 다시 열기 | 저장·확정한 내용 유지 |

테스트용 관찰 사실:

> 블록 세 개를 쌓은 뒤 친구에게 같이 만들자고 말했다.

멘토님께 볼 것을 부탁할 부분:

- 입력하지 않은 행동·발언·감정·반복 경향이 해석에 추가됐는가?
- 지원이 다음에 교사가 할 구체적인 행동인가?
- 사실을 고칠 때 관찰 기록으로 돌아가는 방법이 이해되는가?
- `.hwpx`를 한글에서 열었을 때 제출 문서로 읽을 수 있는가? 다운로드·파일 구조 검사는 했지만 실제 한글 앱의 인쇄 품질은 별도 확인 대상이다.

확정 후 관찰 원문을 고쳤다면 문서를 다시 열고 `확정 취소` → `변경된 근거 반영하기` → 해석·지원 재검토 → 검토 체크 → `검토 완료 · 문서 확정` 순서로 진행한다. 원문 수정이 확정 상태를 자동으로 취소하지는 않는다.

## 3. 일과 입력 → 일일 보육일지

| 순서 | 누를 곳·입력 | 확인할 결과 |
|---|---|---|
| 1 | 왼쪽 `우리 반` → `오늘 일과 적기` | 같은 반·날짜의 일과 기록 |
| 2 | 일과 이름 `오전 실내놀이`, 시작 `09:00`, 종료 `10:00` | AM/PM과 시·분 확인 |
| 3 | 활동계획 `자연물과 블록을 제공한다.` | 계획과 실제 실행이 별도 칸 |
| 4 | 활동실행 `유아들이 블록으로 길을 만들고 자연물을 길 옆에 놓았다.` | 실제로 한 일 입력 |
| 5 | `저장` → 새로고침 | 입력값과 순서 유지 |
| 6 | `오늘 일지 만들기 →` | 같은 반·날짜의 근거 선택 |
| 7 | 사용할 일과를 체크 → `초안 만들기` | 고른 순서대로 사실 구성 |
| 8 | 해석·지원 확인·수정 → 검토 체크 → `검토 완료 · 문서 확정` | 확정된 일일 보육일지 |
| 9 | `한글 파일로 내려받기` | `.hwpx` 파일 다운로드 |

`오늘 일지 만들기`는 저장하지 않은 입력이 있으면 먼저 저장한다. 활동실행이 빈 줄은 일지 근거로 고를 수 없다.

시간이 남으면 원본 일과 하나를 수정·저장한 뒤 문서를 다시 연다. 변경된 근거를 보여주는지, 해석·지원 재검토와 재확정이 가능한지 확인한다. 원본을 바꿨다고 확정 상태가 자동으로 취소되는 것은 아니다.

## 4. 연간 → 월간계획안

| 순서 | 누를 곳·입력 | 확인할 결과 |
|---|---|---|
| 1 | `계획 노트` → `계획안 만들기` | 생성 조건 화면 |
| 2 | 대상 연령 확인 → `연간` 카드 선택 → `계획안 생성하기` | 연간 결과 화면 |
| 3 | `내용 수정` → 3월 활동명과 소주제(활동 내용)를 입력 → `수정 완료` | 새로고침해도 수정 유지 |
| 4 | `연간계획안 확정` | 수정 버튼 비활성화, 확정 상태 |
| 5 | `한글 파일로 내려받기` | 연간 `.hwpx` 다운로드 |
| 6 | `계획 노트` → `월간 양식 설정` | 승인된 기반 양식의 칸 선택 |
| 7 | 원하는 추가 칸 선택 → `N칸으로 양식 만들기` | 원 기본 양식 설정 완료 |
| 8 | `계획 노트` → `월간계획안` → 담당 반·월 확인 | 해당 반·월 초안 또는 생성 버튼 |
| 9 | `N월 계획안 만들기` | 주별 표와 칸별 근거 |
| 10 | 내용을 여러 글자 입력 → `수정 내용 저장` → 새로고침 | 입력 포커스와 저장 내용 유지 |
| 11 | 필요하면 지원되는 칸의 `이 칸만 다시 만들기` | 내용 변경 확인 후 해당 칸 재생성 |
| 12 | `확정하기` | 남은 수정을 먼저 저장하고 확정 |
| 13 | `한글 파일로 내려받기` | 월간 `.hwpx` 다운로드, 수정한 문장 포함 |

- 연간을 먼저 확정해야 월간을 만들 수 있다. 계획안 확정은 취소할 수 없다.
- 연간 자동 생성은 월별 주제까지다. 소주제는 직접 입력하며, 안전교육 배치 입력은 아직 없다. 미입력 칸은 내려받아도 비어 있다. 완성된 연간계획안 자동 생성으로 소개하지 않는다.
- 월간 근거는 칸의 `근거 보기`에서 펼친다. 주차는 머리행에만 나오고 빈 본문 행으로 반복되지 않는다.
- 안전교육에 근거가 없으면 빈 칸일 수 있다. 빈칸이나 검사 안내 자체가 확정을 막지는 않는다.
- 추가 요청사항/메모는 연간 생성 내용에 반영되는 입력으로 보장되지 않는다. 생성 화면 안내대로 결과를 검토·수정한다.
- 월간의 주간계획안 생성과 변경 이력 조회 UI는 이번 파일럿의 완료 경로로 제시하지 않는다.

## 5. 평가 준비·부가 화면

| 경로 | 해볼 일 | 정상 동작 |
|---|---|---|
| `평가 준비` | 자동 집계 4-1·4-2 확인 | 기간·건수·반/아동별 현황 표시 |
| 같은 화면의 `교사 자기 점검` | 평가요소 한 개 체크 → 새로고침 | 7개 지표·19개 요소, 체크 보존 |
| `설정` | 트렌드봇 사용 켜기/끄기 → 새로고침 | 설정 유지 |
| `계획 노트` → `트렌드봇` | 꺼짐·자료 없음·자료 목록 상태 확인 | 꺼짐과 조회 실패를 구분 |
| `계획 노트` → `기관 양식` | 양식 화면 진입 | 파일 입력 화면 접근 가능. 이번 브라우저 검사에서 실제 기관 파일 업로드는 수행하지 않음 |
| `설정` → `초대 코드 만들기` | 코드 생성 확인 | 1회용 코드와 만료일 표시. 초대받은 별도 계정의 참여까지 이번 새 시나리오에서 재검증하지 않음 |

평가 준비는 **통과/불통과 판정이 아니다.** 오늘 작성한 일지는 검토 기간이 어제까지이므로 내일부터 집계된다. 4-1은 관찰일지 수를 세지 않으며, 월간계획안과 일일 보육일지를 센다. 4-2는 영유아 평가를 세고 관찰일지로 대체하지 않는다.

`이 브라우저의 기존 증빙 사전점검`은 이전 기능이다. 여기에 등록한 자료는 위 공식 지표의 자동 집계에 연결되지 않는다. 이번 파일럿은 위쪽 서버 체크리스트를 사용한다.

## 수정한 문제

| 문제 | 수정 |
|---|---|
| 월간 편집 시 첫 글자 뒤 포커스가 사라짐 | 렌더마다 입력 컴포넌트를 새로 만들던 구조 제거 |
| 월간 여러 칸 수정 중 저장 결과가 다른 입력을 지울 수 있음 | 변경된 칸을 최신 revision으로 순서대로 저장, 성공한 칸만 임시값 제거 |
| 저장 직전 확정 클릭이 blur 저장과 충돌할 수 있음 | 명시적 저장 버튼과 확정 전 저장 순서 적용 |
| 월간 표에 일반 2열 폼 스타일 적용 | 표 전용 스타일과 열 정렬 검증 추가 |
| 월간 다운로드 버튼 없음 | 기존 서버 내보내기를 확정 후 한글 다운로드 버튼에 연결 |
| 월간 내보내기에 AXIS 구역까지 본문으로 포함 | CONTENT 구역만 내보내고 주차는 머리행에 유지 |
| 연간 소주제·안전교육 빈 칸이 완성본처럼 보임 | 주제만 자동 생성한다는 안내와 소주제 미입력 표시. 자동 생성 범위 확장은 이번 수정에 포함하지 않음 |
| 월간에 바꿀 수 없는 칸에도 재생성 버튼 표시 | 지원되는 section·생성 모드만 표시, 덮어쓰기 확인 |
| 월간 반 선택·양식 버전·안내 동선 부족 | 반 선택, 양식 출처·버전, 다시 조회·연간·양식 설정 링크 제공 |
| 관찰 기록에서 특정 기록으로 일지 생성 진입 불가 | 기록 ID와 반을 전달하는 카드 링크 제공 |
| 일지 서버 한글 내보내기에 화면 버튼 없음 | 인증된 파일 다운로드 연결, stale 확정본은 차단 |
| 일일 보육일지의 사실 수정 안내가 없음 | 같은 반·날짜의 일과 기록으로 돌아가는 링크 제공 |
| 평가 화면이 서버 체크리스트를 사용하지 않음 | 9개 지표·19개 요소·실제 체크 저장 연결 |
| v2 승인 뒤에도 서버가 v1의 빈 평가요소 사용 | 승인·해시 검사를 유지하며 승인된 v2 활성화 |
| 반 수정이 새 반을 만들어 기존 아동·기록과 단절 | 기존 연결 변경 차단. 수정 미지원 안내 제공 |
| 기관 양식·트렌드봇 화면에 클릭 진입점 없음 | 계획 노트에 링크 추가 |
| 프런트 AI 연결 상태로 연간 생성 모드를 단정 | 연간 서버 생성 여부와 무관한 상태 문구 제거 |

## 남은 제한과 검증 범위

- **기존 원·반 정보 수정은 완료된 기능이 아니다.** 원 수정 API가 없으며 원 수정 시 서버가 거절한다. 반 수정도 새 행으로 대체하지 않도록 막았다. 기존 원·반을 실제로 수정하려면 API 계약과 구현이 필요하다. 담당 반 선택·새 반 추가·아동 명단 관리는 별도 경로다.
- 주간계획안은 도메인·기반 양식이 #191로 병합됐지만, 생성 API·운영 UI의 완료 기능은 아니다.
- 의미의 근거 적합성을 판단하는 3단 LLM Judge는 PRD에서 미정으로 남아 있다. 형식·추출 대조와 교사 검토를 의미 검증 완료로 부르지 않는다.
- 원 양식 업로드 파일의 다양성, 실물 한글 앱에서의 인쇄 품질, 실제 AI 문장의 품질·생성 시간은 별도 현장 확인이 필요하다.
- 모든 서버 기능을 운영에서 재실행했다는 의미가 아니다. 로컬에서 실제 HTTP·DB 경로를 검증하고 운영은 공개 health만 확인했다.
