## 평가에 반영되었으면 하는 지점

1. **자율성을 문제에 맞췄다.** 법정 안전교육 · 연령 · 칸 배치처럼 틀리면 안 되는 것은 Rule이 정한다. LLM은 Rule이 허용한 후보 · 근거 안에서 내용과 문장을 정한다. 확정은 언제나 교사가 한다 — ADR-032 · [agent.md](agent.md)
2. **LLM 출력을 믿지 않는다.** 스키마 → Reference · 근거 대조 → 계약 규칙 → 수리 1회 → 그래도 어기면 저장하지 않는다. 가짜 LLM Golden으로 이 동작을 고정했다 — [validation.md](validation.md)
3. **값마다 근거가 남는다.** 칸마다 근거(Evidence) · 만든 방식(Generation) · 변경 이력(Audit)을 따로 기록한다. 주간은 근거를 뽑을 때 쓴 seed를 서버 로그에 남겨(#469) 「왜 이 근거였나」를 다시 만들 수 있다(계획안 본문에는 저장하지 않는다).
4. **계획 변경과 재개를 단계마다 정했다.** 상위가 확정돼야 하위를 만든다. 칸 하나만 다시 만든다. 확정을 풀면 하위에 「상위가 바뀜」이 뜬다. 놀이 연간은 실패한 구간만 · 겹친 후보만 다시 만든다 — ADR-055 · 064 · 077
5. **품질을 기준선과 비교해 쟀다.** 지금 방식을 기준선으로 먼저 정하고, 바꾼 방식을 같은 조건으로 다시 쟀다. 놀이 연간은 10회 × 400 후보와 사람 판정 100개(2차 판정자 3명 추가), 주간은 실측 115회 · 근거 대조 651개 · 사람 판정 168개(3단계 117 · 최종 51)다. 교사 17명 설문도 받았다 — [evaluation.md](evaluation.md)
6. **측정 도구도 검증했다.** 판정 모델(jev)을 사람 판정 8문항과 방향을 맞춰 보고, 채택은 사람 판정으로 했다. 겹침 검사기는 사람이 라벨한 42짝을 테스트셋으로 고정해 검사기를 바꾸면 바로 보이게 했다.
7. **개선은 다시 재서 고른다.** 놀이 연간은 150초 → 38초가 됐다. 주간 후보는 연령 등급 우선을 넣었다가 사람 판정을 보고 활동 종류 순환으로 정했다. 이어질 고도화는 [improvement.md](improvement.md) §3에 있다.
8. **개인정보를 막았다.** 아동 이름은 가명으로 바꿔 보내고, 치환이 실패하면 호출하지 않는다. 근거 자료의 기관 정보도 가명으로 덮어썼다 — ADR-079(#465)

## 5. 기능 요구사항 — 계획안

| ID | 요구사항 | 근거 |
|---|---|---|
| P1 | **연간 · 월별 주제형.** 활성 Theme Reference 안에서 Rule이 월 · 연령에 맞는 주제를 고르고, LLM은 고른 주제의 문장만 쓴다. 정확히 12개월(3월 → 다음 해 2월) | ADR-041 · `golden/yearly.json` |
| P2 | **연간 · 놀이 프로젝트형(v2).** 4구간 × 놀이 후보 10개를 동시에 만들고, 교사가 구간마다 5개를 고른다 | ADR-043 · 048 · 077 |
| P3 | **월간.** 확정된 연간이 있어야 만든다. 주제형은 안전교육 후보 8개 중 교사가 주마다 고르고, 놀이형은 AI 후보 8개 중 교사가 5개를 고른다 | ADR-052 · 065 |
| P4 | **주간.** 확정된 월간이 있어야 만든다. 대·소집단 · 실내놀이는 Rule이 기관 계획안 근거를 찾고, LLM이 그 안에서 후보를 쓰고, 교사가 고른다 | ADR-053 · 054 |
| P5 | **같은 달 주간끼리 · 다시 만들 때 후보가 반복되지 않는다.** 앞 주가 쓴 근거는 뒤로 미루고, 상위 20건 안에서 활동 종류별로 돌아가며 섞어 뽑는다 | #469 · [improvement.md](improvement.md) §2 |
| P6 | **칸 편집 · 칸 하나 다시 만들기.** 초안(DRAFT)에서만 된다. 고르지 않은 칸의 id · 값 · 근거는 그대로 둔다 | CLAUDE.md §19 · `golden/cell_regeneration.json` |
| P7 | **확정 · 확정 풀기.** 확정에는 교사 계정이 필요하다. 확정본은 읽기 전용이다. 고치려면 문서 보관함에서 확정을 풀어 초안으로 되돌린다 | ADR-055 · 064 |
| P8 | **요청 사항 메모.** 글로 쓴 요청은 LLM이 허용 범위 안에서 반영한다. 개수 · 주차 같은 요청은 Rule이 반영한다. 반영하지 못한 요청은 화면에 표시한다 | ADR-060 |
| P9 | **근거 추적.** 모든 칸에 Evidence · Generation(`RULE_ONLY` · `RULE_LLM` · `IMPORTED` · `MANUAL`, rule_id · rule_version) · Audit을 남긴다 | CLAUDE.md §13 |
| P10 | **기존 연간 가져오기.** LLM은 칸 배정만 한다. 배정한 글자가 원문에 그대로 있는지 결정적으로 검사하고, 교사가 표에서 확인해야 저장한다 | ADR-056 |
| P11 | **선택 자료는 실패해도 된다.** 트렌드봇이 실패하거나 늦어도 계획안은 만들어지고, 그 사실이 기록된다 | ADR-072 · CLAUDE.md §7 |

**비기능 (AI)**

- **검증 실패는 저장하지 않는다.** 수리 1회 뒤에도 계약을 어기면 500이고, 아무것도 저장하지 않는다.
- **응답 시간(실측, Sol):** 놀이 연간 평균 38.3초(실험 서버 10회) · 배포 서버 중앙 42.1초 · 주간 중앙값 26~28초.
- **비용(실측):** 한 장에 주제형 연간 약 46원 · 주제형 월간 약 69원 · 놀이 연간 약 172원 · 주간 약 90원. 놀이 연간은 순차와 병렬이 같다(4호출). 한 반 1년치(연간 1 · 월간 12 · 주간 52)는 약 5,600원이다.
- **실측 규모:** 11-08~11-10에 계획안 279장을 실제 모델로 만들었고, Sol에 약 4.3만~4.4만 원(기록 1.4만 · 어림 2.9만, VAT 별도)을 썼다 — [runs/2026-11-10-inventory §9](../evaluation/runs/2026-11-10-inventory/README.md#9-계획안-종류별-실측-요약-11-08--11-10).
- **로그에는 숫자만 남긴다.** 호출마다 모델 · 토큰 · 시간 · 결과만 남기고, 프롬프트 · 응답 · 키 · 아동 이름은 남기지 않는다 — ADR-036

## A. AI 동작 규격 (요약 — 자세히는 [agent.md](agent.md))

| 무엇 | Rule | LLM | 교사 |
|---|---|---|---|
| 칸 구조 · 칸 역할 | **정한다** | — | 양식 설정 |
| 후보 범위 (주제 · 근거 · 누리과정 내용) | 승인 자료에서 월 · 연령으로 **거른다** | 범위 안에서 **고르고 쓴다** | **고른다** |
| 법정 안전교육 기준 | 공식 근거와 **대조한다** | 정하지 않는다 | — |
| 통과 여부 | **검사한다** | 정하지 않는다 | — |
| 확정 · 제출 | 자동 없음 | — | **교사만** |

- 생성 모델은 Sol이다. jev는 품질 측정에만 쓰고, 저장 게이트와 교사 화면에는 쓰지 않는다.
- 모든 호출은 `backend/app/shared/llm/client.py` 한 곳을 지난다. 문서 단위로 한 번에 부른다(칸 단위면 15배 넘게 든다).
- 모델에 닿지 못한 요청만 한 번 더 보낸다(ADR-076). 계약 위반은 수리 1회, 그래도 어기면 저장하지 않는다.

## 계획 변경 · 재개 (요약 — 자세히는 [agent.md](agent.md) §4 · §5)

```
연간 초안 ─► 연간 확정 ─► 월간 초안 ─► 월간 확정 ─► 주간 초안 ─► 주간 확정
   ▲ 칸 편집 · 칸 하나 다시          ▲ 상위 확정 게이트           ▲ 앞 주 근거는 뒤로
   └───── 문서 보관함에서 확정 풀기 → 초안 · 하위에 「상위가 바뀜」 표시 ─────┘
```

- **놀이 연간:** 4구간을 동시에 부르고, 실패한 구간만 한 번 더 부른다. 겹친 후보만 다시 만든다. 「생성 멈추기」는 저장 전까지 언제든 된다.
- **저장은 마지막에 한 번만 한다.** 반쯤 된 계획안은 남기지 않는다. 교사는 「다시 시도」를 누른다.
- **교사 편집은 칸마다 바로 서버에 저장한다.** revision이 다르면 409로 버리고 최신본을 다시 불러온다. 저장 못 한 글은 화면에 남기고 「다시 저장」을 띄운다. 초안은 서버에 있으므로 문서 보관함에서 다시 열어 이어서 고친다 — [agent.md](agent.md) §5

## 12. 트레이드오프

| 선택 | 대안 | 이유 |
|---|---|---|
| **LLM이 도구 · 단계를 고르게 하지 않는다.** Rule이 근거를 찾고 칸을 정한다 | 도구 호출 에이전트 | 법정 기준 · 연령 · 근거는 틀리면 안 된다. LLM은 판단이 필요한 곳(내용 · 문장)에 둔다 — ADR-032 |
| 문서 단위로 한 번에 부른다 | 칸마다 부르기 | 시스템 프롬프트가 칸 수만큼 반복돼 비용이 15배 넘는다 |
| 실패하면 Rule만으로 채운 초안을 내지 않는다 | 빈 칸이 섞인 초안 | 놀이형은 Rule만으로 채울 놀이가 없다. 반쯤 빈 초안보다 분명한 실패가 낫다 |
| 자동 재시도는 모델에 닿지 못한 요청만 한다 | 시간 초과 · 429도 재시도 | 시간 초과는 모델이 이미 돌았을 수 있어 비용이 두 번 나간다 — ADR-076 |
| 구간별 저장 · 작업 큐로 이어서 하기는 하지 않는다 | 생성 작업 테이블 + 워커 | 동시 생성으로 38초가 됐다. 반쯤 저장된 상태를 다룰 필요가 없다 |
| 계획안 저장 게이트에 jev를 쓰지 않는다 | jev로 품질을 걸러 반려 | 사람과 같은 방향인 문항이 8개 중 1개였다. 검증 안 된 판정을 게이트로 쓰지 않는다 |
| 주간 근거는 상위 20건 전체에서 종류별로 돌아가며 섞는다(#469) | 정확 연령 기록부터 채우기(연령 등급 우선) | 등급 우선은 근거의 연령 표기를 맞출 뿐, 근거 등급을 가린 사람 판정에서 연령 적합이 같고(0.88) 주제 적합이 낮았다(0.32 vs 0.61). 다양성 · 영역 분산을 지키는 쪽을 골랐다 — 하민 11-10 |
| 공식 PDF를 런타임에 LLM이 읽지 않는다 | PDF RAG | 사람이 검증한 machine-readable Reference만 Rule 후보로 쓴다. 판과 근거를 추적할 수 있어야 한다 — CLAUDE.md §8 |
